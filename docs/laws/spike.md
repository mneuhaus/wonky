# Proof spike: what proving real kernel properties in Bend costs

Status: 2026-09-22, Bend 2.0.25, on a shared machine (1-minute load 11 to 14 from
other agents throughout; every timing below has its `uptime` in
[`out/laws/spike-timings.jsonl`](../../out/laws/spike-timings.jsonl)).
Scope: an empirical spike. Nothing here changes production code, the root
`LAWS.bend`/`PROOF.bend`, or `npm test`. Companion documents written in parallel:
[inventory](inventory.md) (which laws are worth stating) and [prior art](prior-art.md).

## 1. Short answer

**Bend can prove real properties of the real kernel code, and cheaply,** as long as
the property does not depend on the value of an `F32`. In one session the spike
proved 17 laws about unmodified production defs in `kernel/topology.bend`,
`kernel/robust-predicates.bend`, Base's U32 adder, and a codec produced by
`scripts/native-bridge/gen-wire.mjs`. They include three results that were not
obviously within reach:

- **Loop reversal preserves loop closure**, for every loop and every edge table
  (`reverse_uses_preserves_closure`, generic induction, about 190 proof lines).
- **The multi-limb adder of the exact predicates is exact**: for base-4096 digit
  lists and a carry ≤ 1, `value(mag_add(a, b, c)) == value(a) + value(b) + c`
  (`mag_add_exact`, about 630 proof lines including a reusable U32 lemma library).
- **Wire codec round trips** for topology ADTs, including a generic proof of the
  generated list decoder (`wire_face_roundtrip`, about 65 lines). F32 fields and
  list lengths enter only as explicit hypotheses.

The checker is fast: the whole spike gate (17 laws, 1 300 proof lines, plus the
imported kernel modules) checks in **0.55 s**. Writing the proofs was the
expensive part. It took about 40 minutes of agent time for everything, with 36
rejected check runs on the way, all of them cheap to diagnose.

What does **not** work, precisely:

1. **F32 is opaque.** Every F32 operation in Base is a `law` without a `def`,
   including `F32.bits`. The checker does not even evaluate `0.0 + 0.0`. The float
   filter of `point_plane`, the conversion `from_word` (F32 → Big) and any claim
   about coordinates are therefore out of reach.
2. **Large computed Nats in types crash the checker.** The checker normalizes types
   fully, so `A.pow2(15n)` (32 768 unary nodes) or even `U32.to_nat(32767)` in any
   type overflows its stack. Literals are exempt: `4294967295n` is fine. Every
   statement that needs "below 2^32" has to be width-generic or phrased as a
   hypothesis.
3. **Evaluation proofs grow about cubically.** "`extrude` of an n-gon is a valid
   solid" is proven by evaluation for fixed n: 0.1 s for n = 3, 2.2 s for n = 32,
   12.7 s for n = 64. A proof for all n needs U32 index arithmetic over appended
   edge tables. With the U32 library built here this is feasible, but it was not
   attempted. The estimate is 600 to 1 200 lines.

**Recommendation.** Laws pay off for the kernel's discrete core: topology
bookkeeping, exact integer arithmetic, codecs, gates and truth tables. They need
three conditions. (a) A human states the spec functions (here `solid_ok`, `value`,
`digits_ok`), because the law is only as strong as they are. (b) Proofs live in
their own gate beside `npm test` and are maintained like code: two of the 13
mutants below broke a proof without falsifying its law. (c) Anything F32 stays
with run-time validation and differential tests. Section 9 lists concrete next
steps and proposed diffs.

What the laws do **not** say:

- `solid_ok` covers the discrete half of `validateSolid`: endpoints in range and
  distinct, every vertex referenced, one loop of ≥ 3 in-range coedges per face,
  every loop closed, every edge used once forward and once backward, and
  V + F = E + 2. It does not check that an edge's two uses lie on different
  faces, shell connectivity, planarity, or orientation relative to the normal.
  Laws 1 and 2 hold for any coordinates, including degenerate ones. They say
  nothing about geometry.
- Laws 1 and 2 cover n = 3 and n = 4 only. Law 3 covers all n, but only the counts.
- The robust-predicate laws cover the exact fallback only. `point_plane` first runs
  a float filter whose decision is unprovable (section 5.1).
- The codec laws assume that F32 bits survive (`bits_id(v) == v`) and that the
  list length survives its U32 count word.

## 4. Attempt (a): topology

**Result: success**, including the generic closure law. Timeline from the check
log: the first four laws took about 5 minutes. The closure law took about
3 minutes of iteration: 7 rejected runs in 51 s, all affinity or
rewrite-direction errors. Designing the proof took longer, perhaps 10 minutes.

The spec was written first. `topology-spec.bend` mirrors the discrete checks of
`src/brep.mjs:validateSolid` over the production `T.Solid`. The one deliberate
design choice: `vertex(edges, c, head)` computes the endpoint selector
`Bool.xor(forward, head)` *before* the edge lookup. A flipped coedge then reduces
to the same stuck lookup term, so the flip lemmas need no reasoning about
`List.get`. The first version selected after the lookup and would have needed
that reasoning.

What made proofs easy or hard:

- **Structural recursion over lists** (`transform_faces`, `ring_edges`,
  `side_faces`) was easy. Each length or preservation lemma is 5 to 8 lines, and
  `{==}` closes the base case.
- **Accumulators** (`reverse_uses(xs, acc)`) need a generalized statement. I split
  the result into `revfirst <> revrest` (`rev_split`) and proved chain, last
  element and first-tail lemmas separately. This is the standard functional-
  programming proof shape, about 60 lines.
- **U32 equality.** Loop closure compares vertex ids with `U32.is_eq`, so the
  symmetry lemma `same(a,b) == same(b,a)` needed `Word.cmp` antisymmetry, proven
  by induction over the 32 Bools for every width (about 40 lines, reused by the
  arithmetic laws). Because Base defines U32 as `U32{Word(32n)}`, this works
  symbolically. It is not a black box.
- **U32 index arithmetic** (`offset + i`, `next(i, n)` wrap) is what blocks
  "`extrude` is well-formed for every n". I proved only the counts for all n
  (law 3). The rest is evaluation for fixed n:

| n | 3 | 4 | 8 | 16 | 24 | 32 | 48 | 64 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| check (s) | 0.11 | 0.14 | 0.23 | 0.54 | 1.13 | 2.18 | 6.22 | 12.71 |

  The scaling runs used `List.replicate(G.Vec3, n, p)`. Laws 1 and 2 use distinct
  symbolic points: every coordinate is an opaque variable, and the checker still
  computes the topology to `True{}`.
- **`+` everywhere.** A value used twice must be `+` (Data). This covers
  parameters, pattern fields (`case +c <> +rest`) and proof-local lets. Missing
  ones produce `x (consumed more than once)`, about a third of all rejected runs.
  Equality proofs are Data too: `+da: {digits_ok(a) == True{} : Bool}` works.

Observation from the mutation check (section 7): the mutant "transform reverses
every loop" broke the proof of law 4 but **not the law**. Reversing every loop
preserves closure (law 6) and swaps use directions (law 5). `solid_ok`, which
does not look at normals, cannot tell the difference. A stronger spec would need
orientation, and orientation is F32.

## 5. Attempt (b): exact arithmetic

**Result: success on the integer layer.** This covers the full `mag_add`
correctness, the U32 adder, the limb split, comparison antisymmetry,
self-difference and normal form. The F32 layer fails as expected. Timeline:
laws 7 to 13 took about 10 minutes, `mag_add_exact` another 12 minutes (11 rejected
runs, 0.05 to 0.28 s each).

### 5.1 What the checker can and cannot reason about

U32 is **not** a primitive in the checker. Base says `type U32: U32{data:
Word(32n)}`, and `U32.add`, `and`, `shr` and `cmp` are ordinary recursive defs over
Bools. A literal unfolds into that model:

```
- expected : {U32{Word.and(32n, w, WCon{False{}, WCon{False{}, … WNil{}}}…})} == 0 : U32}
```

So U32 facts are provable by induction over `Word(n)`. The trusted gap is that
the C and JS runtimes implement U32 natively and are assumed to agree with this
model.

F32 is the opposite. Every operation is a postulate:

```
law F32.bits:
  for a: F32
  U32
```

Nothing computes, not even on closed literals:

```
Error:
- expected : F32.add(0.0, 0.0)
- observed : 0.0
Location: f32_zero_add
```
```
Error:
- expected : ../../../kernel/laws/spike/wire/wire.f32_of_bits(F32.bits(F32{w}))
- observed : F32{w}
Location: f32_roundtrip
```

The full predicate, not just the exact fallback, gets stuck at its very first
step, the validity check `finite(word) = … F32.bits(word) …`:

```
- expected : {…robust-predicates.point_plane_valid(Bool.and(…vec_valid(n), Bool.and(…vec_valid(p), …vec_valid(p))), n, p, p)
             == …Decision{…ExactlyZero{}, …ExactDyadic{}} : …Decision}
```

Interesting detail: F32 *literals* are IEEE bit words inside `F32{Word(32n)}` in
the checker. `{1.0 == F32{<0x3F800000 as 32 Bools>}}` checks by `{==}`. So
`F32.bits` could be an ordinary def (proposal 9.1).

### 5.2 The U32 lemma library

The library is built bottom up. Every lemma is generic in the width n, and
checking takes 0.07 to 0.12 s per module.

- `adc_value` (`arith-lemmas.bend`): Base's ripple-carry `Word.adc` satisfies
  `a + b + c == adc(a,b,c) + 2^n · carry_out(a,b,c)` for every n. It is one
  generic algebraic step lemma (`adder_step`, 13 rewrites) and 8 one-line bit
  cases. This worked **on the first check**.
- `word_cmp_anti` and `word_cmp_refl`: `Word.cmp` is antisymmetric and reflexive.
- `mask_value`, `split_value`, `pad_value`, `shr_drop`, `shrw_same` (`limb-lemmas`):
  and-with-mask is the low k bits, and the k-fold right shift is the high part.
  Together they give `limb_split`:
  `to_nat(s & 4095) + to_nat(s >> 12) · 4096 == to_nat(s)` for **every** U32 s.
  This is 183 lines. The trick: define low and high parts structurally on the
  word, and prove that `U32.shrn`'s outermost-first shifts equal innermost-first
  shifts (`shr_commute`).
- `carry_free` and `u32_add_small`: a U32 sum below 2^13 is exact.
- `word_zero`, `digit_value`: `RP.digit` drops only zero digits.
- `order-lemmas`: ≤ algebra (`le_add`, `le_trans`, `le_drop_l`, `pow2_mono`, …).

`mag_add_value` is then a 4-case induction mirroring `mag_add`. It uses the digit
precondition to bound each limb sum by 8191, gets exact U32 sums, splits the sum
into the new digit and a carry ≤ 1, and applies a 9-rewrite algebra lemma.

### 5.3 The checker's large-Nat limit (the main technical obstacle)

The first attempt stated "U32 addition is exact below 2^32" directly:

```
law u32_add_no_overflow:
  for +a: U32
  for +b: U32
  for lt: {Nat.is_lt(Nat.add(U32.to_nat(a), U32.to_nat(b)), A.pow2(32n)) == True{} : Bool}
```
```
Error: the machine stack overflowed (a deep recursion, or a literal too large to expand)
```

With `?goal` in the body, the JS trace shows why: the checker strongly normalizes
the context types (`term_snf`) and expands `pow2(32n)` into unary Succ nodes:

```
RangeError: Maximum call stack size exceeded.
      at term_wnf (/$bunfs/root/bend:2323:24)
      at term_snf (/$bunfs/root/bend:2496:22)
```

Measured thresholds in a def's type: `pow2(12n)` to `pow2(14n)` check,
`pow2(15n)` overflows, and so do `U32.to_nat(32767)` and `{A.pow2(32n) == A.pow2(32n)}`.
Nat *literals* do not expand: `4294967295n` in a type is fine.

Workarounds that the laws above use:

- State facts for every width n (`word_add_no_overflow`, `carry_free`). Inside
  the proof, n stays symbolic, so `pow2(n)` never unfolds. The caller then only
  instantiates `k ≤ n` facts such as `{A.le(13n, 32n) == True{}}` and bounds such
  as `pow2(13n)` (8 192).
- Phrase "below 2^32" as a hypothesis the caller discharges. The codec law does
  this with `pre: {U32.to_nat(U32.from_nat(length)) == length}`.
- Keep bounds small and exact: digit sums stay ≤ 8191. The proof of `hi_bound`
  lets the checker normalize an 8 191-deep unary comparison. That is fine, but it
  makes `mag-lemmas` the slowest module (0.44 s).

### 5.4 What was not proven, and why

- **Sign antisymmetry** `sign(x - y) == -sign(y - x)` is **false without a
  precondition**. Evaluated with non-canonical digit 4096:
  `x = Big{False, [4096]}`, `y = 0` gives `(Positive, ExactlyZero)`. With digit 4095
  it gives `(Positive, Negative)`. A correct law needs at least `digits_ok` (every
  digit ≤ 4095). Hand evaluation suggests that zero top digits are harmless, but
  that was not proven. The proof then needs the one-sided cases of
  `mag_add` and `mag_sub`. The library covers `mag_add`. `mag_sub` needs a Word
  subtraction lemma (`Word.sub` is `adc` with inverted b: estimate 80 to 120 lines).
- **`mag_scale`/`mag_mul`** need `Word.mul` correctness (shift-and-add loop;
  estimate 150 lines) plus a digit-product bound below 2^24 (stated width-generic,
  see 5.3). Estimate for full `mul` correctness: 300 to 400 more lines.
- **`from_word`/`from_real`** (F32 → Big) and the **float filter**: unprovable while
  F32 is postulated. The filter's correctness argument (the error bound in the
  comment) is a floating-point theorem. It needs a floating-point semantics that
  Bend does not have.

### 5.5 The reformulations the brief asked about

| Reformulation | Verdict | Evidence |
|---|---|---|
| Nat reference + proof that the U32 code matches it on a bit model | **Works, and needs no code change**: Base's U32 already *is* the bit model | `adc_value`, `limb_split`, `mag_add_exact` |
| Exhaustive checking on bounded widths | Works for evidence, poor for proofs | `∀ s < 8192: (s & 4095) + ((s >> 12) << 12) == s` by evaluation: 0.26 s / 0.77 s / 5.81 s for 256 / 1 024 / 8 192 cases, about 0.7 ms per case. The same in Nat semantics: 1.28 s for 1 024. One limb of `mag_add` over all inputs is 4096² × 2 ≈ 33.5 M cases, hours of checking. Using an exhaustive check inside a symbolic proof also needs a reflection lemma plus `from_nat(to_nat(s)) == s`, which is more work than the direct lemma was. |
| Move the arithmetic to an ADT digit representation | Unnecessary here | U32 is already an ADT in the logic. Binary-digit lists would make the kernel slower and the proofs no shorter than `adc_value`. |

## 6. Attempt (c): wire codec round trips

**Result: success for fixed-shape ADTs and for the generic list decoder. F32
fields and list lengths are hypotheses.** Timeline: about 4 minutes, 3 rejected runs.

- `Coedge{edge: U32, forward: Bool}`: a case split on `forward` and `{==}`. The
  decoder's `match x: case 0: … case 1: …` on a U32 literal reduces fine.
- `Edge`: `{==}` after exposing the constructor.
- Trailing words are rejected: `complete(True, [w]) = False`, so the result is `None`.
- `List<Coedge>` (`coedges_go`, `coedges_items`, `coedges_list`): the generated
  decoder reverses an accumulator. The generalized lemma is
  `dec_items_go(len(xt), (x, C(enc(xt))), acc) == (reverse.go(acc, x <> xt), C(rest))`,
  and after one element-lemma rewrite it goes through by `{==}`. This is 25 lines.
  Because the generator emits the same shape for every element type, the lemma
  is a template (proposal 9.2).
- `Face`: three Vec3 fields and one coedge list. There are four rewrites in
  `PROOF.bend`. What blocks an unconditional law:
  - F32: see 5.1. The first idea was a single hypothesis
    `-ax: @x: F32 -> {f32_of_bits(F32.bits(x)) == x}`. It fails because rewrite
    evidence is live and a closure is affine:
    ```
    - expected : -ax
    - observed : ax (consumed more than once)
    ```
    The law therefore takes one equation per vector,
    `ho: {WS.bits_id(o) == o : G.Vec3}`.
  - The length word is `U32.from_nat(length)`. The list survives only if its
    length is below 2^32, and that bound cannot be written in a type (5.3).
    Hence `pre`.
- An open law cannot serve as an axiom. That is good: it keeps the gate sound.
  ```
  - expected : a filled definition (an unfilled law is a dead claim: live code cannot use it)
  - observed : helper.bogus
  ```

## 7. Mutation check: do the laws catch drift?

`scripts/laws/spike-mutants.mjs` copies the imported kernel modules and the spike
into `tmp/laws/mutants/<name>/`, applies one edit and runs the spike gate. The
unmodified control passes (0.52 s). **All 13 mutants are rejected** (0.1 to 0.5 s each).

| Mutant | First failure | Law false? |
|---|---|---|
| `reverse-no-flip`: reverse without flipping | `reverse_use_count` | yes |
| `side-wrong-vertical`: side face uses the wrong vertical edge | `extrude_triangle_well_formed`: `expected False{}, observed True{}` | yes |
| `next-off-by-one`: ring successor wraps late | `extrude_triangle_well_formed` | yes |
| `transform-reverses-loops` | `transform_faces_loops` | **no**: only the proof broke (section 4) |
| `top-face-shares-bottom-ring` | `extrude_triangle_well_formed` | yes |
| `mag-cmp-finish-swapped`: tie-break compares b, a | `finish_flip` | **no**: a reversed order is still antisymmetric. No law pins the order to `value` |
| `sub-drops-negation`: `sub(a, b) = add(a, b)` | `sub_self_zero` | yes |
| `make-keeps-negative-zero` | `make_normal` | yes. Law 9 was added **because this mutant first survived** |
| `mag-add-carry-shift-11` | `mag_add_value` | yes |
| `mag-add-drops-carry-in` | `mag_add_value` | yes |
| `mag-add-mask-4094` (one-sided case) | `mag_add_value` | yes |
| `codec-bool-swapped` (generated decoder) | `coedge_step` | yes |
| `codec-ignores-trailing` (generated decoder) | `wire_coedge_rejects_trailing` | yes |

Two lessons. First, a law is only as strong as its spec function: comparison
order and orientation escaped every law. Second, proofs are code: a harmless
refactor can break a proof while the law still holds, so someone must maintain
the proofs.

## 8. Checker errors hit, and the fix for each

36 of 94 check runs were rejected. Every rejection was cheap (≤ 0.34 s) and
precise. The recurring ones:

| Checker output | Cause | Fix |
|---|---|---|
| `x (consumed more than once)` | affine variable used twice live | `+x` on the parameter, pattern field (`case +h <> +t`) or let |
| `expected : -l0` / `observed : l0` | erased let (`-x = …`) passed to a live argument | use `+x = …` (a match inside the callee makes the argument live) |
| `expected : an annotated term (cannot infer)` | list literal or constructor in a let | `{[…] : List<&2, G.Vec3>}` |
| `a parameter or field scrutinee (a match cannot scrutinize a computed value: give it its own def)` | `match f(x)` | helper def with a parameter, or generalize (`digit_gen(c, …)` for `digit`'s computed condition) |
| `a match on a parameter or field (this name is a def or a consumed binder …)` | `match` after a `%` rewrite or let | match first (nested patterns `WCon{True{}, t}`), or move the case split into a lemma (`bit_word`) |
| `expected : a defined name` / `observed : word_zero` | forward reference | define callees first |
| `expected : Data` / `observed : Type` | `for +b: U32 where {…}` (the pair is not Data) | separate hypothesis `for lt: {…}` |
| expected/observed goal mismatch right after `%e : P` | wrong rewrite direction | `%e : P` replaces the **right** side of `e` (marked `_`) by its left. The spike states lemmas as `{replacement == form-in-goal}`, or uses `Equal.sym` |
| `the machine stack overflowed …` | computed Nat ≥ 2^15 in a type | width-generic statement (5.3) |

There were no termination rejections: every recursion in the spike is structural.
The kernel's own style (first parameter shrinks, `Nil{}` passed unchanged in
`mag_add(Nil{}, bt, …)`) was accepted as is.

## 9. Proposals (diffs, not applied)

### 9.1 Upstream Bend: make `F32.bits` a def

F32 literals are already IEEE words in `F32{Word(32n)}` (5.1). Then the codec's F32
round trip becomes `{==}`, and the `bits_id` hypotheses disappear:

```diff
--- bend2/base.bend
-law F32.bits:
-  for a: F32
-  U32
+def F32.bits(a: F32) -> U32:
+  F32{w} = a
+  U32{w}
```

This is a proposal for HigherOrderCO, since `.tools/bend-*` is vendored. NaN
payloads may still differ between the C and JS runtimes (see prior art §1.4).

### 9.2 `gen-wire.mjs`: emit the round-trip proofs with the codecs

Every generated decoder has one of three shapes, so every proof has one of three
templates. For each ADT `K` with constructors `C_i{f_1..f_m}`, emit into
`wire-proof.bend`:

```diff
+def rt_${K}(v: ${T}, +ok: Bool, +rest: List<&2, U32>) ->
+  {(v, Cursor{ok, rest}) == dec_${K}(Cursor{ok, enc_${K}(v, rest)}) : ${T} & Cursor}:
+  match v:
+    case ${C_i}{x_1, …, x_m}:                  # Bool fields: one case per value
+      %rt_${f_1}(x_1, ok, enc_${f_2..m}(…, rest)) : {… == dec_${K}_s0(_) …}
+      …                                         # one rewrite per non-U32 field
+      {==}
+def rt_items_${E}_go / rt_items_${E} / rt_L_${E}  # copy of coedges_go/_items/_list
+law ${K}_roundtrip:
+  for +v: ${T}
+  {decode_${K}(encode_${K}(v)) == Some{v} : Maybe<&2, ${T}>}
```

Until 9.1 lands, F32 leaves need the `bits_id` hypotheses, and list lengths need
`pre`. The native-binding workflow owns `scripts/native-bridge/**`, so this is
theirs to adopt.

### 9.3 A gate for adopted law areas

The laws should stay out of the root `LAWS.bend` until Marc adopts them (his spec).
Adopted areas would get their own `LAWS.bend`/`PROOF.bend` and gate. The gate
must require the exact verdict: prior art §1.6 shows `@unsafe` fills exit 0 with
`All terms check, but …`.

```diff
--- scripts/check-bend.mjs
-execFileSync(bend, ['PROOF.bend'], {
-  cwd: root, env: { ...process.env, BEND_NO_TELEMETRY: '1' }, stdio: 'inherit',
-});
+for (const dir of ['.', ...readdirSync(join(root, 'kernel/laws')).map(d => `kernel/laws/${d}`)]) {
+  const run = spawnSync(bend, ['PROOF.bend', '--check-only'], { cwd: join(root, dir), encoding: 'utf8',
+    timeout: 120_000, env: { ...process.env, BEND_NO_TELEMETRY: '1' } });
+  const out = `${run.stdout ?? ''}${run.stderr ?? ''}`;
+  if (run.error || run.status !== 0 || out.trim().split('\n').at(-1) !== 'All terms check.')
+    throw new Error(`proof gate failed in ${dir}:\n${out}`);
+}
```

Side effect to know: `scripts/check-solid-classification.mjs` and
`scripts/compare-boolean-ports.mjs` hash every `kernel/**/*.bend` into their
implementation snapshots. Files under `kernel/laws/` change those hashes, as
`kernel/proto/` and `kernel/service/` already do.

### 9.4 Run the proven discrete check at run time

`topology-spec.bend` is a Bend implementation of `validateSolid`'s discrete
half. Moved into `kernel/` (for example `kernel/topology-check.bend`) and called
from `src/kernel.mjs` after every construction, it checks
the invariant on every real output, for every n. The laws in turn guarantee
properties of the check itself (4, 5, 6) and of the fixed-size constructions
(1, 2). For fixed skeletons this is cheaper than a generic-n proof and covers the
same failure class. It is a production change, so it is only proposed (sketch;
`checks` would be loaded like `topology.bend`):

```diff
--- src/kernel.mjs
   const solid = kernel.extrude(shifted, vector(delta));
+  if (!checks.solid_ok(solid)) throw new Error('extrude produced a topologically invalid solid');
```

### 9.5 Optional: make `extrude`'s topology provable for all n

The blocker is U32 index arithmetic inside `ring_edges`, `side_face` and
`vertical_edges`. Two options:

1. Keep the code and prove the index lemmas with the library from section 5.2.
   `to_nat(offset + i) = offset + i` via `carry_free` with a width-generic bound
   `3n < 2^k, k ≤ 32`. Add `List.get` over `append`, and the pairing count over
   all faces. Estimate: 600 to 1 200 lines.
2. Generate indices in Nat and convert once:

```diff
--- kernel/topology.bend
-def ring_edges(left: Nat, +n: U32, +offset: U32, +i: U32) -> List<&2, Edge>:
+def ring_edges(left: Nat, +n: Nat, +offset: Nat, +i: Nat) -> List<&2, Edge>:
   match left:
     case 0n:
       Nil{}
     case 1n+p:
-      Edge{(offset + i : U32), (offset + next(i, n) : U32)} <>
-        ring_edges(p, n, offset, (i + 1 : U32))
+      Edge{U32.from_nat(Nat.add(offset, i)), U32.from_nat(Nat.add(offset, next_nat(i, n)))} <>
+        ring_edges(p, n, offset, 1n+i)
```

   The proof then reasons in Nat and needs one lemma,
   `to_nat(from_nat(k)) == k` below 2^32, stated width-generically. Unary Nat
   indices cost runtime (O(index) per conversion). I would only do this if the
   run-time check of 9.4 is rejected.

## 10. Trust base and honest limits

- The laws are checked against the Bend source. The kernel runs through the JS
  emitter (`src/bend-loader.mjs`) or the native C backend, and both implement
  U32 natively. Agreement between those and Base's `Word(32n)` model is trusted,
  not proven.
- Bend's type theory has `Type : Type` and no positivity check. Consistency rests
  on its live/dead separation (guide, "Under the Hood").
- No law here mentions an F32 value except as an opaque passenger or an explicit
  hypothesis.
- The spike is a separate gate. `npm test` does not run it.
- Agent time is given as wall-clock from the check log, on a machine running other
  agents. It is an order of magnitude, not a benchmark.
