# wonky research knowledge base

Research for [wonky-kernel](../../README.md), Marc's code-to-CAD kernel for
FDM-printed parts: FeatureScript frontend, Bend 2.0.25 kernel (F32/U32 only,
F32x2 double-word reals, multi-limb U32 exact predicates, fork-join and GPU
call trees, no mutation, no FFI). Collected on 2026-09-21 to 2026-09-24.
English, except [synthesis.md](synthesis.md), which is written in German for
Marc.

## What this is

A reading library that answers one question per topic: *what do the best
systems do, what do they really guarantee, where do they break, and what
should wonky take, given its constraints?* It has four layers.

| Layer | What it contains | Where |
|---|---|---|
| Synthesis | Cross-topic summary for Marc: key findings, how the commercial kernels work, state of the art per problem, consequences for the Boolean bake-off, a prioritized backlog, war stories, licence map, open questions | [synthesis.md](synthesis.md) (German) |
| Topic chapters | One chapter per topic, each with the same seven sections: 1 landscape, 2 comparison table, 3 state of the art (technique, real guarantee, where it breaks), 4 war stories and anti-patterns, 5 ranked proposals for wonky, 6 open questions worth a prototype, 7 catalog of the remaining sources | the 13 `*.md` files below |
| Addenda | Gap fillers written after a completeness review, each tied to measured demand in Marc's corpus | [addenda/](addenda/) |
| Source notes | One note per deep-read source (paper, repository, manual, patent, issue tracker): canonical URL, licence, activity, how it works, guarantees, failure modes, Bend fit, verdict | [sources/](sources/) (213 notes) |

Scratch material (shallow clones, PDFs, scripts, raw JSON) lives in
`tmp/research/` and is not part of the knowledge base. Worklogs of the
agents that wrote it are in local development evidence.

## How to read it

- **Start with [synthesis.md](synthesis.md)**, section 1 (Kurzfassung) and
  section 5 (backlog). Every backlog item links to the chapter proposal it
  comes from.
- **For one problem, go to its chapter**, section 3 for the technique and
  section 5 for what wonky should do. Proposals carry a Bend-fit statement, a
  risk and a first acceptance test.
- **For one source, use the index table below.** The note is the evidence;
  chapters cite notes, notes cite primary URLs.
- **Labels.** Every claim is marked **DOCUMENTED** (primary source, linked),
  **MEASURED** (a wonky run or a count over Marc's corpus, linked to the wonky
  document), **INFERRED** (the author's reasoning from evidence) or
  **HEARSAY** (secondhand, forums, catalog entries that were not deep-read).
  The synthesis uses the German labels DOKUMENTIERT, GEMESSEN, ABGELEITET,
  HÖRENSAGEN.
- **Verdicts** in the notes: *adopt* (take as is), *adapt* (take with
  changes, re-derived under wonky's constraints), *learn-from* (ideas, tests
  or failure cases only), *avoid*, *unreachable* (primary text could not be
  obtained; only what was verifiable is recorded).
- **State of wonky referenced here** is the working tree of 2026-09-24. The
  most important fact that several scout briefs still had wrong: the Boolean
  bake-off was decided on 2026-09-23 (corefine + recover, see
  [../hybrid-boolean-plan.md](../hybrid-boolean-plan.md) §1). Chapters say so
  in their "corrections" paragraph.
