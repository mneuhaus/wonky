## What it is

**DOCUMENTED:** a fault-reporting API, not a proof-producing validator. Most Parasolid modeling calls assume input bodies are valid. Checking supports debugging, post-operation validation, import repair, and localization of invalid entities. Local checking covers entities changed by an operation, not pre-existing unrelated damage. Whole-body checking is explicitly more expensive. [Chapter §§8.1, 8.4, 8.5](http://www.q-solid.com/Parasolid_Docs/chapters/fd_chap.09.html#pgfId-273788).

## How it works

**DOCUMENTED:** PK_BODY_check(body, options, n_faults, faults) separates the API error from the array of discovered faults. The default option structure limits the array to 10 faults and enables all listed checks. max_faults=0 means raise PK_ERROR_check_error on the first discovered fault, **not** unlimited collection. A positive maximum bounds diagnostic output; even a very large maximum does not guarantee enumeration of all defects. Each fault contains a state, primary entity, optional secondary entity, and an optional position. The old ABI encodes absent positions as (0,0,0), so position applicability comes from the state, not whether its coordinates are zero. [Options](http://www.q-solid.com/Parasolid_Docs/headers/pk_body_check_o_t.html), [fault record](http://www.q-solid.com/Parasolid_Docs/headers/pk_check_fault_t.html), [§8.2.1](http://www.q-solid.com/Parasolid_Docs/chapters/fd_chap.09.html#pgfId-274037).

**DOCUMENTED check families**, in the documentation's listing order:

| Family | Meaning and useful diagnostic granularity |
|---|---|
| geom | Invalid, degenerate, self-intersecting geometric entities; missing geometry attached to topology. Geometry results can be cached; lazy/full/yes differ in whether old cached checks are respected. |
| bgeom | B-curve/B-surface continuity and restrictions on zero derivatives, cusps/ridges, legal boundary degeneracies, closure. |
| top_geo | Edge/face attachment consistency: vertex on curve/surface, edge on face, edge reversal, touching endpoint tolerances, ordering around edges/vertices, missing vertex at a surface singularity. Attached closed geometry needs periodic parameterization; several G1 checks additionally require bgeom enabled. |
| size_box | Geometric domain/resolution limits, not a shape-equality bounding-box comparison. |
| fa_X | A face inconsistent with itself, including edge/edge self-intersection. |
| loops | Loop orientations and types/counts consistent with the supporting surface. |
| fa_fa | Intersections between distinct faces inconsistent with their topology. |
| sh | Inside-out body, inconsistent region shells, body regions, and general-body shell relations. |
| corrupt | Corrupt internal structure or invalid identifiers. |

Source for this table: [PK_BODY_check](http://www.q-solid.com/Parasolid_Docs/headers/pk_body_check.html). **Qualification:** §8.2 says groups run in a dependency order and later dependent groups are skipped after failure; it does **not** explicitly establish that the option-list order above is the exact internal execution schedule. In particular, do not cite it as proof that corrupt-data checks execute last. [§8.2](http://www.q-solid.com/Parasolid_Docs/chapters/fd_chap.09.html#pgfId-273798).

**DOCUMENTED local-check stages:** (1) check each affected face for internal self-intersection; failure raises an error and the chapter strongly advises rollback; (2) compare **each altered face against every other face**, not merely against other changed faces; (3) shell/orientation check, potentially negating an inverted body. A face-face inconsistency can return a zero API error with local_check_failed, because an invalid intermediate result can be intentional. Hence checking only the API status loses real failures. Shell negation may still occur when local checking is off, without reporting local_check_negated. [§§8.4–8.5](http://www.q-solid.com/Parasolid_Docs/chapters/fd_chap.09.html#pgfId-274118).

**DOCUMENTED V35 detail:** PK_FACE_check offers additional nominal-geometry, attached-attribute, and return-version controls. An internal checker failure means theoretical correctness or incorrectness could not be demonstrated, while warning that later modeling may also struggle. That is a distinct outcome from a demonstrated face fault. [V35 reference](http://www.q-solid.com/Parasolid_Docs_V35/headers/pk_face_check.html).

## Robustness and guarantees

**DOCUMENTED:** later checks may be omitted after prerequisite failures; switching off prerequisites can produce misleading diagnoses or checker failures. Internal numerical failures must not be interpreted as proof of an invalid body. Neither n_faults=0 with disabled checks nor successful local checking proves global validity. The chapter also documents self-intersection/session switches, so the selected checking policy is part of the result's meaning. [Body checker](http://www.q-solid.com/Parasolid_Docs/headers/pk_body_check.html), [§§8.3, 8.4, 8.6.2](http://www.q-solid.com/Parasolid_Docs/chapters/fd_chap.09.html#pgfId-274040).

**DOCUMENTED:** incidence checks and several fault explanations refer to edge/vertex/nominal tolerances. Overlarge tolerances can consume features and turn an edge into a ring edge with incompatible open geometry. These pages do not specify one universal numerical tolerance, an exact-arithmetic algorithm, or a completeness theorem. It would be incorrect to infer exact predicates from the API. [§8.3, ring-edge and tolerance faults](http://www.q-solid.com/Parasolid_Docs/chapters/fd_chap.09.html#pgfId-282748).

## Parallelism and performance

**DOCUMENTED qualitative evidence only:** face-face checking is described as by far the most time-consuming check except for simple bodies, and applications are advised to expose levels with and without it. Local checking is faster when only a small fraction of entities changes. No timings, thread model, asymptotic proof, or GPU implementation are supplied. [§8.5.4](http://www.q-solid.com/Parasolid_Docs/chapters/fd_chap.09.html#pgfId-274578).

**INFERRED:** local pair validation has approximately k·n candidate pairs for k changed faces among n, versus n(n−1)/2 globally, before conservative spatial pruning. That is a wonky scheduling model, not a Parasolid benchmark. It follows from the documented changed-face-vs-all rule above.

## Known failures, limitations, war stories

**DOCUMENTED vendor examples, not public issue reports:** failing to roll back after a Boolean error can leave a corrupt structure; interpenetrating regions may still permit some modeling operations but give misleading mass properties; excessive tolerances can collapse intended features; spinning a wire with an internal on-axis vertex through 2π can create an impermissible non-manifold sheet. [§8.3](http://www.q-solid.com/Parasolid_Docs/chapters/fd_chap.09.html#pgfId-274040), [§8.5.1](http://www.q-solid.com/Parasolid_Docs/chapters/fd_chap.09.html#pgfId-274563). No public Parasolid issue tracker or reproducible timings were established in this review.

## Relevance for wonky

**INFERRED implementation plan**, adapting the cited API architecture rather than cloning its numerics:

1. Return a structured result with status checked / invalid / indeterminate, stage coverage, skipped reasons, checker version, tolerance policy, and faults containing stable entity IDs, optional witness point, residual/error bound, and originating feature IDs. An unsupported surface pair is indeterminate, never valid. Separate kernel-operation status from checker status.
2. Run cheap exact U32 topology checks first: index range, ownership, next/previous/twin relationships, loop closure, duplicate identifiers, and expected edge incidence for the declared body kind. Do not reject valid seam edges merely because the same face uses both sides. Then geometry-domain checks and incidence/trim checks; only then global self-intersection and shell nesting. This is an independent dependency DAG, not a claim about Parasolid's exact order.
3. For supported analytic curves/surfaces, exact multi-limb predicates can certify signs for **the represented inputs**. F32x2 is appropriate for residual estimates and bounded construction, but is not mathematically exact and does not certify arbitrary irrational SSI construction. A tolerance-aware result needs an explicit bound; unresolved/algebraic cases need interval isolation, a certified predicate, or an explicit unsupported outcome.
4. Use wonky provenance to form a dirty dependency closure: changed supporting geometry, trims, vertices, adjacent incidences, and bounding boxes. Compare changed faces against all potentially intersecting unchanged faces. Reuse a previous global-validity certificate only when the unchanged subgraph and checker/tolerance version are unchanged.
5. Immutable arrays and balanced fork-join suit per-entity checks and fixed-size candidate batches. Bucket face pairs by analytic type; use conservative broad-phase bounds, then uniform-depth GPU batches with unresolved work carried to another pass or the CPU. Do not let a finite sampling pass masquerade as proof. Keep cached outcomes in a new certificate map instead of mutating geometry.
6. Expose fast and thorough checking, but require the supported thorough checks before final STEP/FDM publication. A nice mass-property result alone cannot rule out intersecting shells, as the vendor's own warning shows.

This plugs directly into Boolean bake-off acceptance, fillet/offset postconditions, per-feature diffs and LLM-readable faults; it is not a replacement Boolean algorithm. The numerical/scheduling suggestions are independent engineering inferences from [the checking contract](http://www.q-solid.com/Parasolid_Docs/chapters/fd_chap.09.html).
