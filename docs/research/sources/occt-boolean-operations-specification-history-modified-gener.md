## What it is

DOCUMENTED: a result-relative relation between an operation's input and output subshapes. It answers which input entities survive, have replacements, produce different entities, or cease to exist. It is **not** a persistent identifier or cross-edit correspondence algorithm. Boolean history covers vertices, edges, faces **and solids**, not arbitrary wires/shells/compounds ([Boolean specification](https://dev.opencascade.org/doc/overview/html/specification__boolean_operations.html#specification__boolean_history), [supported types](https://github.com/Open-Cascade-SAS/OCCT/blob/3d097a0328e71b826377d4814ab05ec3c3d23871/src/ModelingData/TKBRep/BRepTools/BRepTools_History.hxx)).

## How it works

DOCUMENTED contract, with `I` the input set and `O` the final result subshape set ([general history](https://dev.opencascade.org/doc/overview/html/occt_user_guides__modeling_algos.html#occt_modalg_hist)):

- `Modified(s)` contains retained replacements/splits of `s`, normally of the **same dimension**. Empty does not imply deletion: `s` may be unchanged. It is not a list of every intermediate fragment.
- Boolean `Generated(s)` is narrower than generic modeling ancestry: vertices from pure edge/edge, edge/face or face intersection events; edges from face/face intersection. Only **edges and faces as sources** have generated children; merely overlapping/coincident pieces are not new intersection geometry. An extrusion generating a face from an edge belongs to the broader modeling contract, not the Boolean-specific rule ([Boolean generated rule](https://dev.opencascade.org/doc/overview/html/specification__boolean_operations.html#specification__boolean_history)).
- `IsDeleted(s)` means `s` was an input, is absent from `O`, and has **no modified replacements in O**. It can still have generated children. A filleted-away edge can generate a fillet face while being deleted. Thus deletion is not `outDegree(all provenance)==0`. The container calls this `IsRemoved`, while the maker API calls it `IsDeleted` ([History header](https://github.com/Open-Cascade-SAS/OCCT/blob/3d097a0328e71b826377d4814ab05ec3c3d23871/src/ModelingData/TKBRep/BRepTools/BRepTools_History.hxx)).
- For each individual input, `G(s)` and `M(s)` are disjoint. Deleted and modified cannot coexist, but deleted and generated can. One result may have different relation types from **different** sources. Output completeness is described as unchanged input, modified input, or generated input (possibly an implicit null source for new primitives) ([header invariants](https://github.com/Open-Cascade-SAS/OCCT/blob/3d097a0328e71b826377d4814ab05ec3c3d23871/src/ModelingData/TKBRep/BRepTools/BRepTools_History.hxx)).

DOCUMENTED producer details from [`BOPAlgo_Builder_4.cxx`](https://github.com/Open-Cascade-SAS/OCCT/blob/3d097a0328e71b826377d4814ab05ec3c3d23871/src/ModelingAlgorithms/TKBO/BOPAlgo/BOPAlgo_Builder_4.cxx):

1. `PrepareHistory` first maps **the actual final result** into `myMapShape`. Iterate supported source shapes.
2. `LocModified(s)` looks in `myImages`. Keep only images present in the final result. Normalize orientations: vertex/solid orientation follows source; edges/faces can reverse via `IsSplitToReverse`. Topological entity identity and oriented uses must not be conflated.
3. `LocGenerated(s)` rejects unknown/untouched/non-edge/non-face inputs. Scan EE/EF interferences for new vertices, canonicalize same-domain vertex indices, deduplicate them with a fence. For a face also read `FaceInfo.PaveBlocksSc()` and `VerticesSc()`, collecting retained section edges/vertices.
4. Only after that, mark a source deleted when it itself is absent and no modified image was retained. Generated images do not prevent this marker.

DOCUMENTED storage: two source→list maps plus a removed-shape set. Constructor adapts any maker exposing `Modified`, `Generated`, `IsDeleted`; mutators reject duplicate additions and repair/assert contradictory relations. The container is combinatorial; no floating-point arithmetic is necessary for storing or composing history ([header](https://github.com/Open-Cascade-SAS/OCCT/blob/3d097a0328e71b826377d4814ab05ec3c3d23871/src/ModelingData/TKBRep/BRepTools/BRepTools_History.hxx), [implementation](https://github.com/Open-Cascade-SAS/OCCT/blob/3d097a0328e71b826377d4814ab05ec3c3d23871/src/ModelingData/TKBRep/BRepTools/BRepTools_History.cxx)).

DOCUMENTED sequential composition `H12` then `H23`: `M→M` becomes M; `M→G`, `G→M`, `G→G` become G. Retained unchanged intermediates must carry through; relations belonging to sources untouched in the first operation must also be included. The implementation traverses relation lists, propagates additions and removals, and removes empty bindings. This is **composition**, not unioning logs from unrelated operations. Boolean `SimplifyResult` merges ShapeUpgrade_UnifySameDomain history into main history, so references reach the final unified shape rather than dead pre-refine fragments ([header algebra](https://github.com/Open-Cascade-SAS/OCCT/blob/3d097a0328e71b826377d4814ab05ec3c3d23871/src/ModelingData/TKBRep/BRepTools/BRepTools_History.hxx), [simplification](https://dev.opencascade.org/doc/overview/html/specification__boolean_operations.html#specification__boolean_simplify)).

## Robustness and guarantees

DOCUMENTED result-closure guarantee: no Modified/Generated return value may lie outside the result. Empty result means all inputs deleted and all returned lists empty. The edge-fuse/cut and face-fuse/common examples in the specification demonstrate why intermediate intersections must not leak into history ([examples](https://dev.opencascade.org/doc/overview/html/specification__boolean_operations.html#specification__boolean_history_ex)).

INFERRED: this is a well-specified information contract, not proof of robust Boolean geometry or stable order of returned successors. Geometry underneath uses tolerance-bearing OCCT shapes and floating-point calculations; a Bend history port requires no F64, but a port of the Boolean that produces it certainly cannot ignore precision. No promise of stable branch ordinals across changed operands is made ([specification](https://dev.opencascade.org/doc/overview/html/specification__boolean_operations.html)).

DOCUMENTED subtle disabled-history behavior: `BOPAlgo_BuilderShape` can set `SetToFillHistory(false)`; methods then return empty lists/false and `History()` returns null, even if partial history exists for internal purposes. Wonky must distinguish `history unsupported/not collected` from a complete history in which nothing changed ([BuilderShape API implementation](https://github.com/Open-Cascade-SAS/OCCT/blob/3d097a0328e71b826377d4814ab05ec3c3d23871/src/ModelingAlgorithms/TKBO/BOPAlgo/BOPAlgo_BuilderShape.hxx)).

INFERRED code-review caveat, **not runtime verified**: inspected `Merge` checks `IsRemoved(intermediate)` before propagating that intermediate's generated children. The header explicitly permits removed+generated. Therefore a tiny composition test `M12(a)={b}; removed23(b)=true; G23(b)={c}` is essential before treating implementation behavior as the mathematical specification. Independently implement the documented relation algebra rather than blindly translating mutable control flow ([current Merge](https://github.com/Open-Cascade-SAS/OCCT/blob/3d097a0328e71b826377d4814ab05ec3c3d23871/src/ModelingData/TKBRep/BRepTools/BRepTools_History.cxx#L195)).

## Parallelism and performance

DOCUMENTED: source code contains serial source-shape traversal and mutable maps/lists. No measured history-only time, throughput, memory or parallel speedup is supplied in these sources. `PrepareHistory` progress weighting is not a benchmark ([producer](https://github.com/Open-Cascade-SAS/OCCT/blob/3d097a0328e71b826377d4814ab05ec3c3d23871/src/ModelingAlgorithms/TKBO/BOPAlgo/BOPAlgo_Builder_4.cxx)).

INFERRED: emit history records during intersection/split construction instead of rescanning all EE/EF interferences for every source. Sort/group by input and destination with balanced fork-join; immutable merge-joins compose histories. Working size is output-sensitive and can grow with split fanout. Bucket by entity/relation type and size for GPU uniformity; retaining history is likely better suited to CPU fork-join than irregular per-source GPU walks. No speed claims without benchmarks.

## Known failures, limitations, war stories

- DOCUMENTED issue report [OCCT #1357](https://github.com/Open-Cascade-SAS/OCCT/issues/1357), migrated from [legacy 32756](https://open-cascade-sas.github.io/Mantis-Archive/tickets/32756/index.html): duplicate `AddGenerated` entries assert in debug `buildsweep`/thrusection tests, including `test thrusection specific H1`; report mentions 58 affected tests. Still open at inspection, original report 2021 with last legacy update 2023. No local reproduction and no assertion that every current release fails. History producers need their own validation, not blind trust because the solid looks right.
- DOCUMENTED: FUSE and CUT of the same two crossing edges yield different retained Modified sets; intersecting-face COMMON can have empty result and hence empty Generated despite internal intersection work ([examples](https://dev.opencascade.org/doc/overview/html/specification__boolean_operations.html#specification__boolean_history_ex)).
- INFERRED: tags on mesh triangles are only evidence of parent support, not automatically correct B-rep face history. Coplanar coalescing, coincident inputs, removed interior surfaces, shared intersection edges and orientation changes require many-to-many relations plus final-output filtering ([producer invariants](https://github.com/Open-Cascade-SAS/OCCT/blob/3d097a0328e71b826377d4814ab05ec3c3d23871/src/ModelingAlgorithms/TKBO/BOPAlgo/BOPAlgo_Builder_4.cxx)).

## Relevance for wonky

INFERRED highest-priority interface: a Bend-owned `OperationHistory` with explicit `complete|unsupported`, input/output revision/occurrence IDs, surviving unchanged pairs, Modified pair set, Generated pair set, deleted-input set, and typed geometric-event provenance. Store indices/relation tags as U32; foreign keys include entity kind and occurrence. F32x2 and multi-limb predicates remain in geometry, not this layer. Deduplication and relational composition use immutable sorted arrays and balanced fork-join; no FFI or mutable hash table required.

INFERRED hybrid Boolean wiring: tagged mesh fragments establish candidate face parents; analytic recovery assigns surviving B-rep faces; certified SSI events supply generated edge/vertex parents. A face/face intersection edge gets both source faces and a meaningful event identity. A branch ordinal is only revision-local unless separately proved stable. Run final-result filtering **after** sew/unify/analytic recovery and compose their histories. Preserve original creators/roles separately from the latest modifier for FeatureScript queries. Source-derived basis: [LocGenerated/PrepareHistory](https://github.com/Open-Cascade-SAS/OCCT/blob/3d097a0328e71b826377d4814ab05ec3c3d23871/src/ModelingAlgorithms/TKBO/BOPAlgo/BOPAlgo_Builder_4.cxx).

Local integration points inspected 2026-09-24: `<repo>/kernel/identity.bend::boolean_result` currently emits revision-local identities; `<repo>/src/identity.mjs::matchTopologyReference` declines cross-revision matches. Keep that conservative fallback whenever history is incomplete. Add first-class split/merge successors rather than relaxing `unsupported` into a guessed match. Useful for Boolean, fillet/offset lineage, model diffs and source-linked error messages; not a replacement for geometric validity checks.

INFERRED minimal future tests (not run here): unchanged input with empty lists; full removal; partial split; many inputs→one unified face; generated edge from two faces; removed edge still generating fillet face; M→M and all G compositions; deletion after prior generation; orientation reversal; empty Boolean result; disabled history distinguished from empty complete history; no returned intermediate outside final output.

## Verdict: adopt

Adopt this semantic contract and its validation invariants as the native Bend operation-history API. Independently implement immutable relations and composition, with explicit unsupported/partial states. Do not embed OCCT, copy LGPL implementation without license planning, identify deletion with lack of all descendants, or equate history with persistent cross-edit naming. No production changes, builds or test runs.
