## What it is

DOCUMENTED: fit a watertight mesh with a sequential CadQuery program over extrude, revolve, fillet, chamfer, union and cut. Geometry drives proposals and execution/IoU determines acceptance; a learned sketch classifier filters proposals rather than generating program tokens. This is **not an LLM code generator, new Boolean engine, or new fillet construction algorithm**: it relies on CadQuery/OCCT to create the analytic geometry and on native mesh operations for comparisons/residuals. Optional image input first goes through Hunyuan3D plus mesh repair/smoothing/decimation. [Paper §§3–4](https://arxiv.org/pdf/2605.01171v3), [README](https://github.com/ghadinehme/CADFit/blob/fb31f63b79805fff4c5a5c6fa5f8b2f00fe86536/README.md).

## How it works

### Reconstruction state and proposals

DOCUMENTED paper representation: program Pi=(o1,…,oT), operation ot=(type, parameters, references). Parameters include sketch plane/profile, extrusion distance, revolution axis/angle, radius or chamfer length; references select sketch loops, edges or solids. Seek argmax over executable valid programs of IoU(Solid(Pi), target M). Multiple histories can explain one mesh; this is reconstruction of **a** compact program, not proof of original history recovery. [Paper §3](https://arxiv.org/pdf/2605.01171v3).

1. DOCUMENTED: detect planar triangle clusters by normal similarity/area; obtain sketch planes at their centroids, slice at small positive/negative normal offsets and project back. Add five axis-aligned slices per axis. Extract ordered closed loops, remove degenerate ones, group outer boundaries with contained holes via planar containment. Code JSON entries carry origin, normal, xdir and loops_3d. [Paper App. I Algorithms 2–5](https://arxiv.org/pdf/2605.01171v3), [extract_planar_contours.py](https://github.com/ghadinehme/CADFit/blob/fb31f63b79805fff4c5a5c6fa5f8b2f00fe86536/extract_planar_contours.py), [extract_sketches.py](https://github.com/ghadinehme/CADFit/blob/fb31f63b79805fff4c5a5c6fa5f8b2f00fe86536/extract_sketches.py), [split_loops.py](https://github.com/ghadinehme/CADFit/blob/fb31f63b79805fff4c5a5c6fa5f8b2f00fe86536/split_loops.py).
2. DOCUMENTED primitive fit: project into 2D plane basis; PCA least-squares lines, algebraic Kasa circles with radial RMS; grow segments greedily until fit error exceeds a scale-relative threshold, merge collinear lines, close gaps, use spline segments as fallback. Default line/circle RMS tolerances 1e-4 times loop scale, duplicate-point tolerance 1e-6; several code branches round to three decimals. This is heuristic fitting, not certified Hausdorff deviation or analyticity preservation. [fit_primitives.py: fit_line_2d, fit_circle_2d, segment_greedy_fit, close_primitives_loop, build_action_instances_from_entry](https://github.com/ghadinehme/CADFit/blob/fb31f63b79805fff4c5a5c6fa5f8b2f00fe86536/fit_primitives.py).
3. DOCUMENTED extrusion search: slide loop points along plane normal, compare to a sampled target surface using nearest-neighbor distances. Released CLI defaults: 100k surface samples, signed translations -2…2 by .01 in normalized coordinates. Detect intervals with finite-difference slope magnitude <.2 and mean CD <.01, expand interval by one grid step, merge overlaps; translate origin by t_min*n and extrude height t_max-t_min. Paper specifies smallest zero-containing and largest stable intervals; released create_extrusion_from_translation can retain up to **five** widest merged intervals. [analyze_loop_translation.py](https://github.com/ghadinehme/CADFit/blob/fb31f63b79805fff4c5a5c6fa5f8b2f00fe86536/analyze_loop_translation.py), [greedy_search.py#L91-L157](https://github.com/ghadinehme/CADFit/blob/fb31f63b79805fff4c5a5c6fa5f8b2f00fe86536/greedy_search.py#L91-L157), [paper App. K](https://arxiv.org/pdf/2605.01171v3).
4. DOCUMENTED revolve search: symmetric profile candidates, finite principal/rotated-axis hypotheses, full 360-degree revolutions. Paper does not cover general partial revolutions. The released runner passes additional angle hypotheses 0/90 by a 90-degree step to analyze_revolve_axis, unlike the appendix's four additional 45-degree axes; pin configuration instead of assuming paper pseudocode is the executable spec. [App. K.3](https://arxiv.org/pdf/2605.01171v3), [runner](https://github.com/ghadinehme/CADFit/blob/fb31f63b79805fff4c5a5c6fa5f8b2f00fe86536/run_pipeline.py#L718-L730), [axis analysis](https://github.com/ghadinehme/CADFit/blob/fb31f63b79805fff4c5a5c6fa5f8b2f00fe86536/analyze_revolve_axis.py).
5. DOCUMENTED learned prior: DINOv2 views of mesh/loop plus 17 geometric features (area, perimeter, point count, bounding box, plane frame, alignment) feed a 3-layer MLP with GELU/dropout. Paper training pool: 16,719 STLs and about 100k labeled sketches; positives are loops used by previous optimizer outputs. Code uses a thresholded keep mask with at least one top-scoring loop retained, not the paper main text's Bernoulli sampling. Default checkpoint threshold fallback .425; filter is optional and off by default. [App. M](https://arxiv.org/pdf/2605.01171v3), [filter_loops.py](https://github.com/ghadinehme/CADFit/blob/fb31f63b79805fff4c5a5c6fa5f8b2f00fe86536/filter_loops.py), [runner filter path](https://github.com/ghadinehme/CADFit/blob/fb31f63b79805fff4c5a5c6fa5f8b2f00fe86536/run_pipeline.py#L684-L702).

### Program assembly and residual correction

DOCUMENTED paper algorithm: greedily choose maximal positive delta-IoU union candidate; backward remove operations whenever deletion preserves/improves IoU. Residuals are Rplus=M\S (missing volume) and Rminus=S\M (excess). Reconstruct each residual with the same pipeline, union missing geometry and subtract excess. Stop on residual volume tolerance or iteration budget. [Paper §3, Algorithms 1,7](https://arxiv.org/pdf/2605.01171v3).

DOCUMENTED released-code differences matter for a port:

- Actual selection sorts candidates by individual_IoU/volume and makes a sequential pass accepting nondecreasing scores; it is not re-evaluating argmax marginal gain over all remaining candidates at every step. A single candidate over .99 exits early; standalone candidates below .0005 IoU or volume 1e-4 are filtered. [cadquery_ops.py#L1940-L2016](https://github.com/ghadinehme/CADFit/blob/fb31f63b79805fff4c5a5c6fa5f8b2f00fe86536/cadquery_ops.py#L1940-L2016), [greedy_search.py](https://github.com/ghadinehme/CADFit/blob/fb31f63b79805fff4c5a5c6fa5f8b2f00fe86536/greedy_search.py).
- Default single-removal pruning allows a score loss **less than .005 per removal**, despite comments saying improvement. This is an explicit quality/compactness tradeoff, not exact monotonic pruning. [cadquery_ops.py#L2098-L2138](https://github.com/ghadinehme/CADFit/blob/fb31f63b79805fff4c5a5c6fa5f8b2f00fe86536/cadquery_ops.py#L2098-L2138).
- Outer residual updates are accepted after script execution and file creation without an IoU rollback gate. Loop condition tests under_volume only; pure remaining excess can terminate refinement. The CLI defaults to one iteration and both residual thresholds .02, whereas direct function defaults are five iterations and under=.01. Thresholds are absolute normalized volume, not the printed relative ratios. [run_pipeline.py#L812-L1030](https://github.com/ghadinehme/CADFit/blob/fb31f63b79805fff4c5a5c6fa5f8b2f00fe86536/run_pipeline.py#L812-L1030), [CLI](https://github.com/ghadinehme/CADFit/blob/fb31f63b79805fff4c5a5c6fa5f8b2f00fe86536/run_pipeline.py#L1183-L1189).
- Emitted composition sometimes uses CadQuery .add(), a non-fusing Compound, while mesh scoring attempts unions and may concatenate on failure then alpha-wrap. Therefore a high scored mesh does not establish that replayed source produces one nonoverlapping analytic solid. [source emission](https://github.com/ghadinehme/CADFit/blob/fb31f63b79805fff4c5a5c6fa5f8b2f00fe86536/cadquery_ops.py#L2260-L2275), [run_instruction_groups](https://github.com/ghadinehme/CADFit/blob/fb31f63b79805fff4c5a5c6fa5f8b2f00fe86536/cadquery_ops.py#L1706-L1808).

### Fillet/chamfer fitting, not a fillet kernel

DOCUMENTED refine_edges.py: enumerate linear/circular edges shared by nominally nontangent faces; discard short edges <.05, sort by length. Test fillet and equal-distance chamfer at .02 independently on the original base solid. If one improves IoU, sweep sizes .16,.14,…,.02, retain best. Then batch apply selected fillets by descending radius, followed by chamfers; recompute final IoU and rollback whole refinement if no improvement. Log EdgeOp(edge_index, op_kind, size), referencing the original sorted edge list for replay. Fillets/chamfers are off unless --fillet-chamfer is given. [refine_edges.py](https://github.com/ghadinehme/CADFit/blob/fb31f63b79805fff4c5a5c6fa5f8b2f00fe86536/refine_edges.py#L226-L364), [README flags](https://github.com/ghadinehme/CADFit/blob/fb31f63b79805fff4c5a5c6fa5f8b2f00fe86536/README.md).

INFERRED limitation: individually beneficial edge edits need not compose; stale edge references after previous groups can fail, and length-sorted ordinal IDs are fragile under parameter changes. The source skips failing groups and validates aggregate score, but does not supply topological naming or interacting-blend construction. Wonky provenance IDs and transactional edge re-querying are better than copying this selector scheme. [Underlying replay/log code](https://github.com/ghadinehme/CADFit/blob/fb31f63b79805fff4c5a5c6fa5f8b2f00fe86536/refine_edges.py).

## Robustness and guarantees

DOCUMENTED validity is delegated to execution in a native CAD kernel, with failed candidates discarded. Reported zero invalidity is empirical on the paper's selected benchmarks; current code can explicitly produce no-valid-operation output or return without reconstruction. It is not universal success or exact reconstruction. [Paper Table 1](https://arxiv.org/pdf/2605.01171v3), [empty candidate handling](https://github.com/ghadinehme/CADFit/blob/fb31f63b79805fff4c5a5c6fa5f8b2f00fe86536/greedy_search.py#L679-L740).

DOCUMENTED score implementation: iou.py uses CPU manifold3d (float32 vertices, uint32 indices), not a GPU ray sampler. Try direct conversion, accept if volume ratio to Trimesh integral lies .9–1.1; otherwise alpha-wrap. Multiple bodies also trigger wrapping. PyMeshLab input is float64; alpha radius 1% bbox diagonal, offset .1%, optional decimation to 50k faces. Failures return zero, indistinguishable from disjoint solids. INFERRED: repaired volume scoring can erase small holes or inflate thin regions and is not a raw B-rep validity certificate; exact predicate robustness inside Manifold does not undo approximation before scoring. [iou.py](https://github.com/ghadinehme/CADFit/blob/fb31f63b79805fff4c5a5c6fa5f8b2f00fe86536/iou.py).

DOCUMENTED metric conventions differ internally: paper search objective Eq.9 is one-sided **squared** distance, but analyze_loop_translation uses mean unsquared nearest distance for translated loop points. Final paper CD is half the sum of mean **unsquared** bidirectional distances, after Powell similarity alignment; not CAD-Recode's squared ×1000 convention. Pin units/formula rather than comparing raw CD tables. [Paper App. B/K](https://arxiv.org/pdf/2605.01171v3), [translation objective](https://github.com/ghadinehme/CADFit/blob/fb31f63b79805fff4c5a5c6fa5f8b2f00fe86536/analyze_loop_translation.py#L36-L119).

### Theory audit

DOCUMENTED App. G defines a=Vol(M\S)/Vol(M), b=Vol(S\M)/Vol(M), E=a+b, IoU=(1-a)/(1+b), and assumes representability, useful residual sketches, an available contracting candidate and IoU-monotone acceptance. It then claims geometric convergence to an error floor and pruning minimality. Those assumptions already exclude the unsupported/no-candidate cases. [Paper App. G](https://arxiv.org/pdf/2605.01171v3).

INFERRED mathematical issue: IoU-monotonicity does **not** imply the E-contraction used in Theorem G.1's proof. Concrete counterexample with target volume 1: current missing volume .2, excess 0 (E=.2, IoU=.8). One union candidate leaves missing .1/excess 0 (E=.1, IoU=.9), meeting rho=.5, epsilon=0. Another fills all missing material but adds .11 excess (E=.11, IoU=1/1.11≈.90090). Maximizing IoU picks the second yet violates E≤.1. Thus the stated assumptions/acceptance do not establish that recurrence. The valid inequality 1-IoU≤E alone is insufficient. Likewise single-operation irredundancy is not in general a proof of globally shortest/multi-deletion-minimal programs. Treat the algorithm as heuristic search with checked acceptance, not a proved convergence/compactness guarantee; this critique is analytic reasoning, not an upstream-reported bug. [Equations 2–8 and Lemmas G.2–G.3](https://arxiv.org/pdf/2605.01171v3).

## Parallelism and performance

DOCUMENTED code parallelizes independent sketch/axis/candidate fits with process pools and exposes CADFIT_INNER_WORKERS; search/residual updates remain sequential. Nested pools and BLAS thread budgets motivated open PR #2. Uniform batch fitting is the transferable part, not Python process coordination or OCCT mutation. [runner worker sizing](https://github.com/ghadinehme/CADFit/blob/fb31f63b79805fff4c5a5c6fa5f8b2f00fe86536/run_pipeline.py#L704-L725), [PR #2](https://github.com/ghadinehme/CADFit/pull/2).

DOCUMENTED paper timings, not measured locally: Table 7 mean seconds/shape 242.3 DeepCAD complex, 235.0 Fusion360, 303.0 ABC easy, 396.1 medium, 903.7 hard. Prior ablation Table 4 reduces hard 903.7→311.8s (2.90×), with IoU +.2285 under the compared proposal budget; easy loses .0033 IoU while speeding 1.42×. Table 5 smoothing/decimation changes a noisy image-mesh experiment from IoU .876/1255s to .914/456s. The paper text does not give a clear hardware specification for these timings; do not transplant them to Bend/Metal estimates. [Tables 4,5,7](https://arxiv.org/pdf/2605.01171v3).

DOCUMENTED paper quality: mean IoU .964 DeepCAD, .921 Fusion360, .908/.851/.662 ABC easy/medium/hard, with IR=0 on those subsets. ABC hard has 151–1500 STEP faces, 300 cases; this is not all ABC. Median hard IoU .709 appears in Table 6, different from mean .662. On DeepCAD complex, 69.8% win both IoU and program length against the compared baselines. [Tables 1,3,6](https://arxiv.org/pdf/2605.01171v3).

## Known failures, limitations, war stories

- DOCUMENTED paper Figure 10: loft/sweep-dominated forms, helices and smooth high-curvature surfaces can become coarse constructions; stable planar sketches may not exist. No arbitrary spline-surface reconstruction, original design-intent recovery or exact analytic tagged-mesh round trip. [§5, App. F](https://arxiv.org/pdf/2605.01171v3).
- DOCUMENTED issue #4 asks for exact evaluation sample IDs; author replies they still need compilation and recommends CADBench meanwhile. Issue closure is not evidence the requested manifest was supplied. [#4 author reply](https://github.com/ghadinehme/CADFit/issues/4#issuecomment-5801178815).
- DOCUMENTED code comments record former ~50% under-volume alpha-wrap results on slabs with holes and overlapping-compound volume problems. Current fallback/volume-consistency heuristic addresses them but is not a proof of trustworthy volume. [iou.py#L140-L172](https://github.com/ghadinehme/CADFit/blob/fb31f63b79805fff4c5a5c6fa5f8b2f00fe86536/iou.py#L140-L172).
- DOCUMENTED parameter sensitivity: doubling axis slices 5→10 lowers mean IoU .826→.510 in the reported ablation. More proposals need not monotonically help a bounded greedy heuristic. [Table 9](https://arxiv.org/pdf/2605.01171v3).

## Relevance for wonky

INFERRED strong conceptual match: geometry-informed proposal → execute → validate → compare → accept, with explicit residuals and compactness objective. This is a useful **authoring/reconstruction search layer above a kernel**, not a way around missing general curved Booleans or fillet construction. The residual loop itself needs reliable differences/unions; the edge loop needs a working fillet/chamfer. Wonky's tagged-mesh hybrid can use provenance to avoid blind sketch discovery and retain exact surfaces instead of recreating them approximately. Do not replace exact analytic recovery with a high-IoU approximation without an explicit tolerance contract. [Motivation: pipeline and limitations](https://arxiv.org/pdf/2605.01171v3).

INFERRED Bend prototype plan, subject to license/patent review: immutable Candidate records with parent solid version, analytic support IDs, parameter interval, construction/validation status and separate metric status. Generate bounded axis/height hypotheses in balanced fork-join; sequential transaction selects a valid candidate against the unchanged current solid; rollback if raw-solid acceptance criteria fail. Add dimensional/provenance/certified-deviation gates before volume improvement, and distinguish UNMEASURABLE from IoU=0. Prefer Pareto (geometric fidelity, editability, count) rather than quietly allowing .005 score losses. [Observed choices motivating proposal](https://github.com/ghadinehme/CADFit/blob/fb31f63b79805fff4c5a5c6fa5f8b2f00fe86536/cadquery_ops.py), [iou failures](https://github.com/ghadinehme/CADFit/blob/fb31f63b79805fff4c5a5c6fa5f8b2f00fe86536/iou.py).

INFERRED numeric/parallel fit: normalized local-plane fitting can use F32x2 for normal equations, circle fits and cancellation-sensitive moments; U32 indices/counts and explicit sign representations; exact containment/intersection via multi-limb U32 where necessary. Float64 NumPy/Shapely/OCCT behavior cannot be copied by replacing types blindly, especially near tangencies and tiny loops. GPU-friendly tasks are fixed-size candidate distance tiles and reductions; variable-length loop extraction, fitting and recursive kernel failures require CPU fork-join or work buckets. No OCCT/Manifold/PyMeshLab FFI is allowed as wonky's backend. Learning prior may stay in optional frontend authoring, never a correctness gate. [Source fitting, filtering and native numeric stack](https://github.com/ghadinehme/CADFit/tree/fb31f63b79805fff4c5a5c6fa5f8b2f00fe86536).

## Verdict: learn-from

Do not port directly: actual NC license plus claimed provisional patent, important paper/code mismatches, approximating score preprocessing, fragile edge naming, and an insufficient convergence argument. Open: exact benchmark manifest, legal/patent scope, replay-versus-scored-solid equivalence and independently checked numerical behavior.
