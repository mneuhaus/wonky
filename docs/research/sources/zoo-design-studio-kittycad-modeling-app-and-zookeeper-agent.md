## What it is

DOCUMENTED: text/code/GUI hybrid CAD where project artifacts are KCL source, and point-and-click editing transforms that source. React/CodeMirror/XState UI, Rust/WASM interpreter and language tooling, WebSocket modeling requests to a hosted engine, and a video-stream 3D viewport. “GPU-first” README language specifically describes rendering/streaming benefits; it does not publish Boolean/SSI kernels or prove every geometry operation runs on a GPU. [README](https://github.com/KittyCAD/modeling-app/blob/d2f7712388efe52ec89594a4142f52493d8d6cf2/README.md), [transport interface](https://github.com/KittyCAD/modeling-app/blob/d2f7712388efe52ec89594a4142f52493d8d6cf2/rust/kcl-lib/src/engine/engine_manager/engine_transport.rs).

DOCUMENTED author account: Zookeeper loops through plan/act/observe/update, searches documentation, writes/runs/debugs KCL, measures center of mass/mass/area/volume and takes snapshots. Product page calls these “engine-level tools that let the agent inspect, snapshot, and debug geometry.” This is a stated workflow, not independently validated correctness. [Research article](https://zoo.dev/research/introducing-text-to-cad), [product](https://zoo.dev/zookeeper).

## How it works

### 1. Geometry-to-source artifact graph

DOCUMENTED: graph connects plane→path→segment→sweep and generated walls/caps/edges. An engine selection ID maps to an artifact and source/AST location; a generated wall can traverse to both its originating segment and extrusion code. This supports code highlighting, AST edits and semantic agent context rather than screenshot-only targeting. Current Rust `ArtifactCommand` stores command UUID, source range, modeling command and clone identity information; it separates artifact identity, engine entity identity and source-topology identity for patterned/cloned solids. Query-only commands can be omitted from the semantic graph. [Graph explanation](https://github.com/KittyCAD/modeling-app/blob/d2f7712388efe52ec89594a4142f52493d8d6cf2/src/lang/std/artifactGraph-README.md), [Rust graph construction](https://github.com/KittyCAD/modeling-app/blob/d2f7712388efe52ec89594a4142f52493d8d6cf2/rust/kcl-lib/src/execution/artifact.rs#L55-L101).

DOCUMENTED: `constructZookeeperUserPromptRequest()` collects project files, active file and language version, and creates source-range prompts from selected graph artifacts. A selected cap explains START/END face selection and supplies sweep source context; a selected wall explains segment tags and supplies both wall/segment and sweep context. Source ranges are bounds-checked and converted to line/column form; unresolved required file/range references error rather than silently targeting arbitrary text. [Prompt construction](https://github.com/KittyCAD/modeling-app/blob/d2f7712388efe52ec89594a4142f52493d8d6cf2/src/lib/zookeeper/zookeeperPromptRequest.ts#L73-L219), [request assembly](https://github.com/KittyCAD/modeling-app/blob/d2f7712388efe52ec89594a4142f52493d8d6cf2/src/lib/zookeeper/zookeeperPromptRequest.ts#L483-L599).

### 2. Source edits, session fencing and undo

DOCUMENTED: agent file changes are typed created/modified/deleted records with contents, unified diff or previous contents, plus stable `run_id`. Streamed modified diffs are cumulative relative to original contents; latest replaces earlier rather than applying twice. Created→deleted cancels; deleted→created can become a replacement diff; patch application uses `fuzzFactor:0`. `ZookeeperEditPatchHistory` tracks before/after file snapshots and active editor state per exchange with outstanding-write counts. It waits for completion and invalidates incomplete snapshot captures rather than constructing fictitious undo history. These are source-edit snapshots, not B-rep-certified geometry diffs. [Patch merging](https://github.com/KittyCAD/modeling-app/blob/d2f7712388efe52ec89594a4142f52493d8d6cf2/src/lib/zookeeper/zookeeperEditPatch.ts), [history](https://github.com/KittyCAD/modeling-app/blob/d2f7712388efe52ec89594a4142f52493d8d6cf2/src/lib/zookeeper/registry/ZookeeperEditPatchHistory.ts).

DOCUMENTED: `ZookeeperFileRequestProcessor` serializes writes through a Promise queue; reset increments a generation and aborts prior work; pending requests check project path, active session and generation before applying/finishing changes. Controller exposes cancel, reconnect, queue/steer and interrupted-turn resume. INFERRED: these boundaries are essential when humans navigate files or change projects while an agent works. They are not a complete filesystem authorization audit or a proof that every file mutation is transactional. [processor](https://github.com/KittyCAD/modeling-app/blob/d2f7712388efe52ec89594a4142f52493d8d6cf2/src/lib/zookeeper/registry/ZookeeperFileRequestProcessor.ts#L30-L205), [controller](https://github.com/KittyCAD/modeling-app/blob/d2f7712388efe52ec89594a4142f52493d8d6cf2/src/lib/zookeeper/registry/controller.ts).

### 3. Current public agent wire contract, distinct from historical Text-to-CAD

DOCUMENTED from live public schema fetched 2026-09-24: `/ws/ml/copilot` authenticates and uses ping/pong about every 5 s, supports conversation replay and IDs. **The endpoint documentation explicitly says ONLY KCL is returned**, not direct STEP/STL; execute the KCL project through engine `exec_kcl_project` or CLI, then export. Historical `/user/text-to-cad` listing still promises stored STEP contents plus requested format, and `TextToCadResponse` has code, output format, base64 output files, model/version, timestamps and queued/uploaded/in_progress/completed/failed status; that is not the conversational agent's direct return contract. The advertised generation REST page is currently 404 and no corresponding generation POST was present in the fetched paths. [OpenAPI paths and schemas](https://api.zoo.dev).

DOCUMENTED public message types: client `user` includes content, source ranges, current files/project snapshot, active file, optional mode/model/reasoning effort, correlation ID and engine call ID. Server emits deltas, completed tool output, errors, access denial, project updates, replay and end-of-stream. Public `MlCopilotTool` enumerates edit_kcl_code, text_to_cad, mechanical_knowledge_base and web_search; this is **not** evidence that these are the entire internal engine-measurement tool set. Transient client-command catalogs require re-advertisement after reconnect; client-command requests are not persisted/replayed. [OpenAPI `MlCopilotClientMessage`, `MlCopilotServerMessage`, `MlCopilotTool`](https://api.zoo.dev).

DOCUMENTED particularly useful revision contract: `MlCopilotProjectSnapshotMetadata` includes stable namespaced project ID, snapshot idempotency key and optional base revision; base revision includes an opaque writer fence. Every accepted write gets a fresh revision even if contents equal an older revision; revision is not a content hash or ancestry inference. Snapshot outcomes are accepted, merged, rejected_stale, conflict. Canonical update/accept/merge messages are documented as emitted only after durable state. INFERRED: adopt optimistic-concurrency and idempotency semantics, independently of whether wonky ever uses a cloud service. Backend implementation/durability was not tested. [OpenAPI `MlCopilotProjectRevision`, `MlCopilotProjectSnapshotMetadata`, `MlCopilotProjectSnapshotStatus`](https://api.zoo.dev).

### 4. Incremental evaluation

DOCUMENTED: cache compares AST identity/digests, significant annotations/settings and imports. No source change can skip execution but still checks changed imported modules. Changed overlapping statements or deletion clear/rebuild scene; a **pure appended suffix** can execute without clearing. It is not a fully general dependency-DAG incremental geometry recomputation engine. Language-version changes also matter to sketch memory reuse. [cache.rs](https://github.com/KittyCAD/modeling-app/blob/d2f7712388efe52ec89594a4142f52493d8d6cf2/rust/kcl-lib/src/execution/cache.rs#L235-L441).

## Robustness and guarantees

DOCUMENTED historical insight: the December 2023 announcement says multiple valid feature trees can represent one CAD model, complicating training/validation; suggests describing feature operations (fillets/chamfers etc.) rather than vague nouns. At that time outputs were STEP B-reps and KCL delivery was future-facing; by the 2026 agent schema KCL is the primary conversational output. No disclosed training corpus, architecture or geometric success distribution makes “production-ready CAD” a tested guarantee. [2023 announcement](https://zoo.dev/blog/introducing-text-to-cad), [2026 agent article](https://zoo.dev/research/introducing-text-to-cad), [schema](https://api.zoo.dev).

DOCUMENTED current KCL known issues include coplanar CSG and inability to edit imported B-reps as Solid, plus KCL-version-sensitive face tags. UI selections/source references help explain edits but are not a proof of topology equivalence or dimensional conformance. The KCL note separately covers f64, weak higher-dimensional unit tracking and solver tolerances. [Known issues](https://zoo.dev/docs/kcl-lang/known-issues), [numeric docs](https://zoo.dev/docs/kcl-lang/numeric).

## Parallelism and performance

DOCUMENTED architecture, not benchmark: remote WebSocket command batching, streamed viewport frames, Rust/WASM code and process-independent cloud analysis. No independently reproducible latency/Boolean throughput/LLM score table in the inspected announcements. Source-only change skipping and suffix replay reduce work, but no measured speedup inferred. Public API async status and heartbeat are transport contracts, not geometry parallelism. No builds, tests, model inference or authenticated API jobs executed. [README](https://github.com/KittyCAD/modeling-app/blob/d2f7712388efe52ec89594a4142f52493d8d6cf2/README.md), [cache](https://github.com/KittyCAD/modeling-app/blob/d2f7712388efe52ec89594a4142f52493d8d6cf2/rust/kcl-lib/src/execution/cache.rs), [schema](https://api.zoo.dev).

## Known failures, limitations, war stories

- DOCUMENTED user report, unreproduced: [#12709](https://github.com/KittyCAD/modeling-app/issues/12709) reports seven unsuccessful attempts to derive noncircular loft sketch constraints before a supplied working literal template succeeded in under eight minutes. Agent over-solving and an unrelated unsupported union are separated by the reporter. Root-cause attribution to hidden system instructions is the reporter's hypothesis, not verified internal evidence. INFERRED: constraint-first authoring should not force a model to derive every closed-form pattern by reasoning; provide reusable parametric templates and in-code computation.
- DOCUMENTED [#14107](https://github.com/KittyCAD/modeling-app/issues/14107), closed at inspection: repeated `accum+accum` grew source-location metadata exponentially although numeric result remained scalar; supervised report 293.6 MiB versus 43.4 MiB for `accum+1`. Do not treat closure as a verified fix in this reading. INFERRED: wonky provenance must be interned/deduplicated or DAG-based, not copied concatenated ancestry lists.
- DOCUMENTED [#14116](https://github.com/KittyCAD/modeling-app/issues/14116), open: byte-identical KCL circle extrusions sometimes showed a polygonal cap inside the circular boundary; body measurements/export did not settle whether the fault was geometry/tessellation/viewport. This source explicitly does not establish root cause. Maintain separate geometry and rendering checks.
- DOCUMENTED [#14128](https://github.com/KittyCAD/modeling-app/issues/14128) reports update downloads degrading the modeling video stream; this is a cloud-stream dependency absent from a truly local renderer. [#7485](https://github.com/KittyCAD/modeling-app/issues/7485) supplies an unsupported union repro for an ordinary printed mount; [#14138](https://github.com/KittyCAD/modeling-app/issues/14138) explains sketch-solver/engine coincidence tolerance mismatch.

## Relevance for wonky

INFERRED: strong strategic comparison for code-as-model + custom language/runtime + agent, without claiming it is the only such stack. The best portable ideas are **source/geometry graph**, selection-scoped agent requests, file-change replay with revision fences, conflict-aware snapshots and explicit versioned execution. Wonky's existing topology identity/provenance and browser diff/review are the direct insertion points. Add a UI operation that passes selected face/edge provenance plus relevant source spans, dimensions and required unchanged regions into the agent, then reviews both source patch and certified geometric delta. [graph](https://github.com/KittyCAD/modeling-app/blob/d2f7712388efe52ec89594a4142f52493d8d6cf2/src/lang/std/artifactGraph-README.md), [selection requests](https://github.com/KittyCAD/modeling-app/blob/d2f7712388efe52ec89594a4142f52493d8d6cf2/src/lib/zookeeper/zookeeperPromptRequest.ts), [revision schema](https://api.zoo.dev).

INFERRED Bend fit: keep UI/editor/network/session coordination in JS where appropriate; compute production geometry and trustworthy measurements in Bend. Replace mutable HashMaps/UUID references with persistent indexed graph tables or U32-limb identifiers, share/intern provenance nodes, use balanced reductions for graph indexing/metrics. Source spans/patches need no f64; geometry interpreter and solver currently use f64 and cannot simply be transplanted. F32x2 + exact U32 predicates require independent kernel implementation and domain/tolerance tests. Remote GPU video and cloud autoscaling do not transfer to native standalone Bend and do not address uniform GPU work for Booleans. No engine SSI/fillet/offset algorithm was available to port. [value type](https://github.com/KittyCAD/modeling-app/blob/d2f7712388efe52ec89594a4142f52493d8d6cf2/rust/kcl-lib/src/execution/kcl_value.rs#L94-L112), [transport](https://github.com/KittyCAD/modeling-app/blob/d2f7712388efe52ec89594a4142f52493d8d6cf2/rust/kcl-lib/src/engine/engine_manager/engine_transport.rs), [metadata failure](https://github.com/KittyCAD/modeling-app/issues/14107).
