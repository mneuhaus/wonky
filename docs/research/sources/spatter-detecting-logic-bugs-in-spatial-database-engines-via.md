## What it is

**DOCUMENTED:** an oracle-free metamorphic-testing method for spatial predicates: compare a query on geometries against the same query on equivalent representations or on a consistently transformed copy. Tested systems were PostGIS, DuckDB Spatial, MySQL, and SQL Server; the paper reports 34 previously unknown unique bugs, 30 confirmed or fixed, 18 fixed. Of those 30, 20 were logic bugs and 10 crashes. Four reports remained unconfirmed; one duplicate made 35 reports total. These are **2024 campaign figures**, not current issue counts. [PDF §§1,5.1, Tables 2–3](https://arxiv.org/pdf/2410.12496).

The valuable contribution is not “apply random transforms” alone: derive related shapes so touching/containment/overlap actually occur, enforce the relation's mathematical preconditions, compare transformed queries, and minimize contradictions. This complements reference-kernel testing because engines sharing GEOS can agree on the same wrong answer. [PDF pp.3,9–14](https://arxiv.org/pdf/2410.12496).

## How it works

**DOCUMENTED mathematical contract:** A(p)=Mp+b with M nonsingular. For geometry pairs transformed by the **same** affine bijection, their DE-9IM relation remains equal. The 3×3 relation matrix records the dimensions of intersections of each geometry's interior, boundary and exterior. Proposition 3.3 proves preservation via bijectivity, preservation of intersection emptiness, and preservation of dimension. Singular matrices are excluded. The formal development treats cell-complex geometry, with line segments/polygons/polyhedra, not a certified curved B-rep implementation. [PDF Eqs.(1)–(4), Definition 3.2, Proposition 3.3, pp.5–8](https://arxiv.org/pdf/2410.12496).

**DOCUMENTED pipeline (Fig.5; Algorithms 1–2):**

1. Seed a database with a random syntax-valid geometry. Repeatedly choose random-shape generation or derive a new geometry from existing ones, e.g. boundary, convex hull, ring extraction, geometry member extraction, polygonization or coordinate editing. Failed derivations produce EMPTY; semantically invalid geometry is screened/skipped rather than assumed valid. Derivation increases useful topological relationships compared with unrelated random points.
2. Produce alternate representations: remove empty collection elements, flatten/homogenize collections, remove duplicates, reorder elements; for coordinate lists remove consecutive duplicates and normalize direction/orientation. These preserve represented sets only under the selected geometry semantics.
3. Transform all corresponding geometries consistently; paper §4.2 chooses integer coordinates and coefficients to reduce transformation-induced floating-point noise.
4. Compare the same randomly instantiated spatial-join query on the original and transformed databases, primarily SELECT COUNT(*). Log both construction traces on disagreement, then automatically and manually reduce them and identify which result contradicts documented semantics. [PDF §§4–5.1](https://arxiv.org/pdf/2410.12496).

**DOCUMENTED actual-code refinement:** the PostGIS artifact does not simply draw arbitrary integer nonsingular matrices. [MatrixGenerator.py](https://github.com/cuteDen-ECNU/Spatter/blob/39667595500fb4de285b279615cf5de24c2df2da/src/postgis/script/Spatter/MatrixGenerator.py) constructs Pythagorean triples from coprime a,b: x=|a²−b²|, y=2ab, z=√(x²+y²)=a²+b². Python Fraction stores x/z,y/z exactly; orthogonal 2D matrices or products of three 3D matrices are formed using NumPy object arrays. Multiplication by z (or the product of three denominators) clears denominators, giving integer coefficients. Some matrices are reflections, not proper rotations.

[TableUpdator.py](https://github.com/cuteDen-ECNU/Spatter/blob/39667595500fb4de285b279615cf5de24c2df2da/src/postgis/script/Spatter/TableUpdator.py) calls this with max=2, applies scale·Q to one copy and the same uniform scale to the comparison copy. Thus the compared copies differ by an orthogonal transform, allowing distance predicates with the same thresholds; it is more restricted than generic affine invariance. It also implements collection wrapping, normalization, repeated-point removal, axis swapping and adding an already-on-surface point. [RandomQueryGenerator.py](https://github.com/cuteDen-ECNU/Spatter/blob/39667595500fb4de285b279615cf5de24c2df2da/src/postgis/script/Spatter/RandomQueryGenerator.py) filters predicates depending on the transformation, e.g. removing ordering equality after orientation/collection rewrites. This compatibility table is an important design pattern.

**DOCUMENTED reducer:** [QueriesReduce.py](https://github.com/cuteDen-ECNU/Spatter/blob/39667595500fb4de285b279615cf5de24c2df2da/src/postgis/script/Spatter/QueriesReduce.py) deletes batches of INSERT statements, reruns both traces, and keeps changes preserving the disagreement plus guard conditions; it can replace COUNT with ordered ID pairs when inspecting causes. Treat this as a prototype algorithm, not a production-ready reusable reducer.

## Robustness and guarantees

**DOCUMENTED:** the relation is mathematically valid for invertible affine transformations over the modeled Euclidean sets. It is not a proof that either observed kernel result is correct. Finite floating arithmetic can spoil input equivalence; the authors deliberately use integers to reduce false alarms and acknowledge precision trouble in §4.2. Not every representation rewrite preserves every predicate, as the code's exclusions show. Geography/spherical objects, nonlinear transformations, buffer operations, and unrelated file I/O are outside the general guarantee. [PDF §§3,4.2,7](https://arxiv.org/pdf/2410.12496).

**INFERRED numeric caution:** “integer coefficients” alone is not an exactness guarantee when the engine converts them to floating point: coordinate products/sums must stay representable. Python arbitrary integers/Fraction are not available as primitive Bend scalars. Exact bounded generation can instead use signed multi-limb U32 values or a deliberately limited dyadic domain. Nonsingularity must be exact, not a determinant compared against an arbitrary epsilon. This follows from the mathematical preconditions and [artifact numeric choices](https://github.com/cuteDen-ECNU/Spatter/blob/39667595500fb4de285b279615cf5de24c2df2da/src/postgis/script/Spatter/MatrixGenerator.py).

**INFERRED oracle weakness:** count-only comparisons can miss two opposite predicate mistakes that cancel, and a systematic same-error on both sides passes. Prefer per-correspondence results/occupancy witnesses in wonky, plus independent algebraic/mass/topology checks. Mutation of representation is not permission to erase provenance or silently collapse tolerance-sized features.

## Parallelism and performance

**DOCUMENTED measurements:** §5.4 varied 1,10,50,100 geometries per group with 100 queries per run and 10 repetitions. For PostGIS/MySQL above 10 geometries, database execution consumed over 90% of total time; DuckDB Spatial exceeded 90% in all tested configurations. For DuckDB/MySQL, 100 versus 10 geometries took about 20× longer. These measure database workload, not Bend or GPU speed. [PDF pp.19–20, Fig.7](https://arxiv.org/pdf/2410.12496).

The one-hour ablation yielded 2,366 candidate-trigger cases with geometry-aware derivation versus 9,913 without, yet the geometry-aware generator found **more distinct bugs** (Fig.8 roughly 7 versus 3). Raw disagreement count is a bad success metric because duplicates dominate. The 24-hour coverage experiment added 206 PostGIS and 178 GEOS lines beyond unit tests; Table 5 reports PostGIS line coverage 79.5% → 79.9%, GEOS 54.8% → 55.2% for unit tests plus Spatter. [PDF pp.20–21](https://arxiv.org/pdf/2410.12496). No geometry-kernel parallelism proof or native/GPU performance data is supplied.

## Known failures, limitations, war stories

- **DOCUMENTED paper example:** Covers on LINESTRING(0 1,2 0) and POINT(0.2 0.9) changes answer under a suitable affine-equivalent representation. The paper attributes it to precision loss when translating/normalizing vertices; arranging a vertex at the origin bypasses that path. [PDF Listings 1–2, §§1,7](https://arxiv.org/pdf/2410.12496), [GEOS report #968](https://github.com/libgeos/geos/issues/968).
- **DOCUMENTED maintainer-confirmed:** [GEOS #1033](https://github.com/libgeos/geos/issues/1033) has a small polygon/collection reproducer where contains and containsPrep disagreed; maintainers located a deep intersection-matrix problem and deferred to RelateNG. A later maintainer comment says both now return true on main. Do not present the 2024 status as current.
- **DOCUMENTED paper:** EMPTY elements and MIXED-dimensional collections are frequent triggers (6 and 13 of 20 logic bugs respectively, overlapping categories). Prepared versus unprepared and indexed versus unindexed computation expose additional metamorphic relations. Fourteen of the 20 logic bugs were missed by all compared alternatives in their manual analysis. [PDF pp.16–19](https://arxiv.org/pdf/2410.12496).
- No claim is made that this is the only published metamorphic geometry work; the paper's novelty claim concerns spatial DBMSs, not every CAD kernel.

## Relevance for wonky

**INFERRED, high-priority independent implementation:** start with an operation-scoped transform whitelist and a replayable seed. For regularized Booleans and a bijection T, test T(A op B) ≃ T(A) op T(B), where equivalence is geometric with declared error bounds, not face-number or serialization equality. First implement signed-axis permutations/90-degree rotations and positive scaling by 2^k; use translations only when input equivalence is verified. F32x2 scaling by powers of two is exact only while both components stay in their safe exponent range (no overflow, underflow, flushing or rounding during normalization). General integer shears can turn circles/cylinders into unsupported elliptic geometry; defer them until representation and operations are closed under the transform.

For T(x)=sRx+t, s>0 and orthogonal R, check V'=s³V, area'=s²area, centroid'=sR·centroid+t; a constant-density centroidal inertia tensor transforms as I'=s⁵RIRᵀ. A general affine map scales volume by |det M| but does **not** have one scalar surface-area or distance scale. Offset/fillet covariance needs radius and all length tolerances scaled; shear is not valid for constant-radius fillets. Distinguish physical rotation from a cylinder's parameter-seam reparameterization; the latter must transform every pcurve/trim consistently while leaving the occupied set unchanged. These equations are wonky adaptations of the paper's invariance principle, not results claimed by its implementation.

Add representation-only variants: topology storage permutation, loop cyclic-start change, equivalent analytic parameterizations, safe face splitting/rejoining, cached versus uncached evaluation, and per-feature rollback/replay. Test naming/provenance under their own contract rather than demanding identical IDs after physically transformed construction.

Use derivation to generate interesting pairs: clone then place coincident/tangent/slightly separated primitives; cut and reuse a resulting face/edge as another operand; generate holes that cross cylinder seams. Keep a relation witness so a reducer cannot turn an exact tangency case into an unrelated approximate one. Shrink the FeatureScript operation DAG, operands, transforms and parameter bit patterns while preserving the same typed failure and supported-case preconditions.

Bend fit is strong: immutable copies and deterministic seeded generators; fork-join across independent cases; U32/multi-limb exact transform guards; F32x2 bounded property reductions. GPU batches should have similar primitive/operation types and fixed work limits; minimization is irregular and better left to CPU/harness scheduling. Nothing requires embedding another kernel or the Python artifact.

## Verdict: adopt

Adopt metamorphic testing and relation-rich generation immediately; adapt the allowed transforms and oracle precision to Bend and analytic B-rep support. No need to port the SQL driver or depend on a reference kernel. The artifact's permissive code is available, but the major value is its testing method and explicit transformation/predicate compatibility.
