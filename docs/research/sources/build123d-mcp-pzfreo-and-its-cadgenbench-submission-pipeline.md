## What it is

DOCUMENTED: an unusually broad agent-facing CAD workbench: incremental code execution, measurements and analytic face inventory, renders, snapshots, comparison, clearance, sections, validity gates, source-backed execution and parameter robustness audits. It is an interface around build123d/OCCT, not a new geometry kernel. The companion evaluates an entire model + pinned MCP version + generic task prompt system, not a bare model. [README](https://github.com/pzfreo/build123d-mcp/blob/6b71c5c61ec6d2e50cb46b8c9d7ebd780bf7264b/README.md), [harness README](https://github.com/pzfreo/cadgenbench-build123d/blob/4fede660a48e3cfff1da150ccd35f8e7c2d07763/README.md).

## How it works

1. DOCUMENTED: `Session` owns a persistent namespace, current shape, named objects, execution history and snapshots. Successful `execute()` chooses explicit `show()` first, then `result`, then sorted newly introduced shape variables; diagnostics append changed geometry/scalars. **Atomic execution is not universal:** assertion/SIGALRM failure restores bindings with shallow copies for list/dict/set, but ordinary exceptions deliberately preserve partial execution state. Snapshot restore restores geometry/objects/provenance, not the Python namespace. A failed call can therefore leave successful earlier `show()` side effects. Do not copy the blanket llms.md claim that failed execution never advances state. [Implementation, lines 744–998](https://github.com/pzfreo/build123d-mcp/blob/6b71c5c61ec6d2e50cb46b8c9d7ebd780bf7264b/src/build123d_mcp/session.py#L744-L998), [conflicting guidance](https://github.com/pzfreo/build123d-mcp/blob/6b71c5c61ec6d2e50cb46b8c9d7ebd780bf7264b/llms.md#common-mistakes).
2. DOCUMENTED: `execute_file_code()` is the stronger transactional pattern: verify SHA-256, install clean working state, execute, require a produced shape/result name, restore old active state/history on failure, otherwise attach source path/hash and optionally snapshot. Read bounded UTF-8 source before execution (default 2 MiB). INFERRED: immutable wonky model roots make staged evaluation plus root promotion simpler and stronger than copying Python object graphs. [execute_file.py](https://github.com/pzfreo/build123d-mcp/blob/6b71c5c61ec6d2e50cb46b8c9d7ebd780bf7264b/src/build123d_mcp/tools/execute_file.py).
3. DOCUMENTED: measurement uses OCCT surface adapters and mass properties, returning volume, topology and surface types with cylinder diameter/axis, cone angle, sphere/torus radii. The LLM inventory condenses identical rounded records; nonanalytic faces smaller than `max(0.01 mm², total_area*1e-4)` are summarized, but analytic faces are retained. Sections cut planes from 1% to 99% of bbox extent, connect section edges into wires at `1e-7`, classify area, and expose `area_uncertain` when unresolved. This is sampled evidence, not complete wall-thickness proof. [measure.py](https://github.com/pzfreo/build123d-mcp/blob/6b71c5c61ec6d2e50cb46b8c9d7ebd780bf7264b/src/build123d_mcp/tools/measure.py#L85-L349).
4. DOCUMENTED: clearance is not just closest distance. It computes `distance(A,B)`, `V(A-B)`, `V(B-A)`, `V(A∩B)`; outside volume below `1e-6` signals containment, intersection above `1e-6` interpenetration, distance below `1e-9` touching, otherwise apart. Compound normalization handles import wrapper differences. **Important weakness:** failed Boolean volume probes become `None`, but failed intersection is serialized as `intersection_volume: 0.0` and containment can fall through to `neither`. INFERRED: wonky should return `unknown` and per-probe status, never infer no interference from a failed operation. [clearance implementation](https://github.com/pzfreo/build123d-mcp/blob/6b71c5c61ec6d2e50cb46b8c9d7ebd780bf7264b/src/build123d_mcp/tools/measure.py#L458-L511).
5. DOCUMENTED: snapshot diff is a cheap aggregate comparison of rounded volume, f/e/v counts and bbox dimensions, not topological identity or spatial equivalence. Named objects can print `unchanged` when volume changes by at most 0.001 and face count matches, despite translation or hole relocation. `shape_compare()` adds symmetric nearest-vertex mesh distances using cKDTree, connected significant-change regions and local Boolean added/removed volumes where affordable. Deflection `d=max(diag*1e-3,1e-4)`; detection threshold `eps=max(3d,0.05 mm)`; minimum region span `max(2.5d,0.1 mm)`; Boolean clipping skipped for >150 mm clip diagonal or insufficient budget; below 1 mm³ total Boolean change treated as effectively unchanged. Raw sampled Hausdorff tail is reported separately. Exact means OCCT Boolean-derived here, not exact arithmetic or a certified mathematical bound. [diff.py](https://github.com/pzfreo/build123d-mcp/blob/6b71c5c61ec6d2e50cb46b8c9d7ebd780bf7264b/src/build123d_mcp/tools/diff.py), [surface comparison](https://github.com/pzfreo/build123d-mcp/blob/6b71c5c61ec6d2e50cb46b8c9d7ebd780bf7264b/src/build123d_mcp/_shape_compare_subprocess.py#L239-L421).
6. DOCUMENTED: `design_audit(epsilon=0.1,max_params=8)` extracts literal top-level numeric assignments, rebuilds at ±epsilon and reruns validity, in a disposable bounded process. Derived expressions are not separate parameters. `verify_spec` reports measured/structural/recognized evidence with PASS/FAIL/UNVERIFIED; `conforms = no FAIL and at least one checked`, so it can be true with unchecked requirements. Default comparison tolerances are 0.1 absolute / 1% relative. `suggest_spec` drafts from the current shape, not independent design intent. [audit](https://github.com/pzfreo/build123d-mcp/blob/6b71c5c61ec6d2e50cb46b8c9d7ebd780bf7264b/src/build123d_mcp/tools/design_audit.py), [spec](https://github.com/pzfreo/build123d-mcp/blob/6b71c5c61ec6d2e50cb46b8c9d7ebd780bf7264b/src/build123d_mcp/tools/verify_spec.py#L651-L722).
7. DOCUMENTED: harness fetches public inputs, separates development/reportable fixtures, uses generic generation/edit prompts, records model/effort/resolved server version/commit in run metadata, packs all 81 directories including explicit missing outputs, and calls its local gate a **proxy**. Editing banks the unchanged input as a fallback, which can earn nonzero baseline credit without performing the edit. `score.py` searches uniform scales and 24 axis rotations and uses 60,000 sampled points per shape; this is explicitly **not** the official CADGenBench metric, which forbids scale fitting. Latest packaging adds a 50,000,000-byte STEP ceiling. [harness README](https://github.com/pzfreo/cadgenbench-build123d/blob/4fede660a48e3cfff1da150ccd35f8e7c2d07763/README.md), [score.py](https://github.com/pzfreo/cadgenbench-build123d/blob/4fede660a48e3cfff1da150ccd35f8e7c2d07763/harness/score.py), [packager](https://github.com/pzfreo/cadgenbench-build123d/blob/4fede660a48e3cfff1da150ccd35f8e7c2d07763/package_submission.py).

## Robustness and guarantees

DOCUMENTED: gate combines OCCT `BRepCheck_Analyzer`, nondegenerate B-rep edge incidence (two incident faces), positive volume/solid presence, and tessellation checks for open/nonmanifold edges, nonmanifold vertices, missing faces and vertex deflection. It does not trust build123d's imported-shape `is_manifold`. Exact topology stitching is bounded; fallback/skipped coverage is emitted in `mesh_check` and warnings. Critically, `passes_gate` need not be false when the mesh check is skipped. INFERRED: copy the coverage decomposition, not the binary PASS semantics; wonky should have PASS / FAIL / UNVERIFIED for each invariant and require all mandatory invariants verified before print certification. [validate.py](https://github.com/pzfreo/build123d-mcp/blob/6b71c5c61ec6d2e50cb46b8c9d7ebd780bf7264b/src/build123d_mcp/tools/validate.py#L351-L609).

DOCUMENTED: the guidance requires measure → clearance for assemblies → render → snapshot/diff; a plausible render is not proof. It recommends overlapping additive features instead of exactly coincident faces. INFERRED: unchanged counts are only a warning for a no-op Boolean, not proof that a cut failed or succeeded; exact deltas/provenance and requested feature checks are stronger. [llms.md workflow](https://github.com/pzfreo/build123d-mcp/blob/6b71c5c61ec6d2e50cb46b8c9d7ebd780bf7264b/llms.md#recommended-workflow).

## Parallelism and performance

DOCUMENTED: one WorkerSession serializes requests over a pipe lock; multiple HTTP sessions use separate workers. Expensive read-only OCC calls are isolated in hard-bounded subprocesses to preserve session state; comparison persists mesh evidence before attempting costly Booleans. cKDTree queries use `workers=-1`. This is process/thread coordination, not Bend-style uniform GPU work. [worker](https://github.com/pzfreo/build123d-mcp/blob/6b71c5c61ec6d2e50cb46b8c9d7ebd780bf7264b/src/build123d_mcp/worker.py), [comparison](https://github.com/pzfreo/build123d-mcp/blob/6b71c5c61ec6d2e50cb46b8c9d7ebd780bf7264b/src/build123d_mcp/tools/shape_compare.py).

DOCUMENTED author report, **unreproduced**: README reports same-model CAD Score 0.360→0.457 and validity 88%→100% in June 2026. Treat as HEARSAY for causal benefit/generalization until independently reproduced, not a controlled proof that MCP alone caused the gain. Changelog reports 90,840-triangle exact stitching in 5.8 s after raising a former 80k limit to 300k in isolation; environment/control details are insufficient for a wonky performance forecast. No builds, tests or benchmark runs performed in this reading. [README](https://github.com/pzfreo/build123d-mcp/blob/6b71c5c61ec6d2e50cb46b8c9d7ebd780bf7264b/README.md#L25-L27), [v0.3.69 changelog](https://github.com/pzfreo/build123d-mcp/blob/6b71c5c61ec6d2e50cb46b8c9d7ebd780bf7264b/CHANGELOG.md#L399-L431).

## Known failures, limitations, war stories

- DOCUMENTED: [#381](https://github.com/pzfreo/build123d-mcp/issues/381) found 15 PASSes for fixture 240 while every export found four mesh open edges: fast fallback literally pinned open-edge count to zero. Fixed with isolated exact check and explicit unverified warning, not a stronger theorem about all fallback cases.
- DOCUMENTED author observation: v0.3.67 disabled `verify_spec`/`suggest_spec` by default because callers scored worse in two sweeps; `conforms:true` appeared to become a premature stopping signal. This is observational, not randomized causal evidence. [#362](https://github.com/pzfreo/build123d-mcp/issues/362), [changelog](https://github.com/pzfreo/build123d-mcp/blob/6b71c5c61ec6d2e50cb46b8c9d7ebd780bf7264b/CHANGELOG.md#L422-L431).
- DOCUMENTED: v0.3.68 made measure/clearance/sections/recognizers callable inside `execute()` returning native objects, and hid inapplicable tool groups to reduce discovery overhead. Its SpatialClaw “roughly half” attribution is secondary evidence only; that paper was not read for this source. [#366](https://github.com/pzfreo/build123d-mcp/issues/366), [changelog](https://github.com/pzfreo/build123d-mcp/blob/6b71c5c61ec6d2e50cb46b8c9d7ebd780bf7264b/CHANGELOG.md#L414-L420).
- DOCUMENTED: sampled surface comparison can miss sub-resolution/tangential changes and labels its detection floor; `unchanged_elsewhere` is a centroid-spread heuristic (40% of diagonal), not certification. INFERRED: the source's broad claim that surface-distance metrics cannot detect a relocated hole is too strong mathematically; this is a limitation of its sampling/threshold/region strategy, not of all surface distances. [implementation](https://github.com/pzfreo/build123d-mcp/blob/6b71c5c61ec6d2e50cb46b8c9d7ebd780bf7264b/src/build123d_mcp/_shape_compare_subprocess.py#L239-L421).
- DOCUMENTED: executing a successful-step replay after worker death does not reconstruct imported-tool state or snapshots and can diverge for nondeterministic code. Python sandbox introspection is not a security boundary. [recovery changelog](https://github.com/pzfreo/build123d-mcp/blob/6b71c5c61ec6d2e50cb46b8c9d7ebd780bf7264b/CHANGELOG.md#L430-L431), [security.py](https://github.com/pzfreo/build123d-mcp/blob/6b71c5c61ec6d2e50cb46b8c9d7ebd780bf7264b/src/build123d_mcp/security.py).

## Relevance for wonky

INFERRED from the linked implementations: highest-value adoption is the **agent contract**, not geometric algorithms. Implement immutable source-hash/model-root transactions, independent invariant coverage, machine-readable deltas, bounded probes and composable FeatureScript queries. Preserve numeric results inside programs rather than copying JSON numbers through model text. Keep a compact core tool surface with discoverable specialist resources. Test an agent's stopping behavior as well as tool correctness.

INFERRED: measurement/inventory are good Bend ports: parallel map faces and balanced reductions for mass/topology; parallel independent section planes and audit variants; hierarchical BVH nearest-distance traversal for compare. CPU fork-join suits irregular B-rep operations better than uniform GPU call trees. Primitive constants/rounded Python/OCCT double values are not directly portable: define mm/mm²/mm³ tolerance budgets, use F32x2 for geometry/integrals and U32 multi-limb predicates where needed, preserve native scalar precision until presentation, and expose bound/coverage metadata. Do not copy 1e-9 distance or 1 mm³ “unchanged” thresholds blindly for FDM. Clearance's Boolean probes must explicitly fail on wonky's unsupported curved cases. Neither this server nor its pure-Python wrapper solves wonky's missing curved SSI, general Boolean or fillets. [numeric/algorithm evidence](https://github.com/pzfreo/build123d-mcp/blob/6b71c5c61ec6d2e50cb46b8c9d7ebd780bf7264b/src/build123d_mcp/tools/measure.py), [compare evidence](https://github.com/pzfreo/build123d-mcp/blob/6b71c5c61ec6d2e50cb46b8c9d7ebd780bf7264b/src/build123d_mcp/_shape_compare_subprocess.py).
