## What it is

DOCUMENTED: 17,900 execution-verified CadQuery programs in 106 named industrial families, 2,400 paired image/code QA items and 748 edit pairs. Only 52/106 families (49%) are standard-anchored, using 47 specification codes; not all parts are standards-certified. Four tasks: Vision2Code, Vision QA, Code QA, Code Edit. Motivation is separating visual recognition, operation understanding, industrial parameter relations and compositional reasoning rather than rewarding coarse shape only. [Paper §§3–4, Appendix I](https://arxiv.org/pdf/2605.10865v2).

## How it works

DOCUMENTED paper design:

- A family has a typed parameter schema, sampler, validator and deterministic builder. Easy/medium/hard expand parameter ranges and optional features; instantiate standards-constrained parameters, emit CadQuery, execute, render, obtain expert visual sign-off. The four construction quarantine classes are parse/import error, runtime exception (bad radius/empty selector), 30 s timeout, degenerate volume ≤1e-6 mm³ or negative-determinant transform chain. **These are data-generation rules in Appendix E, not the current harness defaults.** [Paper §§3.1, Appendix E](https://arxiv.org/pdf/2605.10865v2).
- QA pairs ask the same property of code and images; image/code performance gap diagnoses visual interpretation versus symbolic reasoning. Four levels L1 recognition, L2 operations, L3 parameter abstraction, L4 compositional spatial/code reasoning. Ratio answers use ±5% acceptance in the paper; integers exact. Current QA code has separate scoring details and documented fixes, so pin revision for comparisons. [Paper §§3.2–4.3](https://arxiv.org/pdf/2605.10865v2).
- Edit types T1 literal replacement (180), T2 transform chain (104), T3 relative computation (111), T4 add/remove feature (199), T5 multi-feature geometry rebuild (154). Target and original are executed, verified, then instruction ambiguity reviewed. Score is mean `clip((IoU(generated,target)-IoU(original,target))/(1-IoU(original,target)),0,1)`; original-target IoU <0.99 in paper. Thus 0 means no useful improvement and 1 closes all original-target headroom. This is not the proportion of perfectly correct edits. Non-target preservation is separately defined on the complement of the edited feature's bounding region. [Eq.1, Appendix N/Tables 15–16](https://arxiv.org/pdf/2605.10865v2).

DOCUMENTED inspected implementation:

- [`benchcad_core/scoring/exec_cq.py`](https://github.com/BenchCAD/BenchCAD-main/blob/52087ef4b08811c21c09b8b16d0ae36c70844865/benchcad_core/scoring/exec_cq.py): extracts code, patches export path/appends export for `result`, prepends CadQuery/OCP compatibility and `show_object` stubs, executes a temporary Python file with inherited environment via subprocess; default timeout **300 s**, requires output STEP. This is process isolation/time limiting, not a secure untrusted-code sandbox: no filesystem/network denial is shown. Do not run generated scripts on a trusted workstation merely because the paper says sandbox.
- [`benchcad_core/scoring/iou.py`](https://github.com/BenchCAD/BenchCAD-main/blob/52087ef4b08811c21c09b8b16d0ae36c70844865/benchcad_core/scoring/iou.py): STEP → CadQuery tessellation tolerance 0.05 → NumPy float64 vertices / int64 triangle indices → independently center each bbox and scale longest extent to 1 → trimesh filled voxels at pitch 1/64 → center-pad matrices to 68³ → intersection/union counts. Exceptions become 0.0. This conflates evaluator failure with genuinely disjoint shapes unless wrapped with explicit status.
- [`Vision2Code/scoring/composite_metrics.py`](https://github.com/BenchCAD/BenchCAD-main/blob/52087ef4b08811c21c09b8b16d0ae36c70844865/Vision2Code/scoring/composite_metrics.py): sampled CD = mean nearest squared distance A→B plus B→A, 2,048 surface samples each; sampled HD = max of both nearest-distance maxima. CD score is 1 below .001, 0 above .2, linear between; HD score 1 below .05, 0 above .5. Combined score = .60 fixed-frame IoU + .20 essential-operations + .10 Feature-F1 + .05 CD-score + .05 HD-score; missing family essential spec drops that term and rescales remaining .80. It explicitly ignores `iou_rot` in the score.
- Feature extraction is not full semantic verification: regex detects fillet/chamfer operations; hole heuristic prefers a REVERSED cylindrical STEP face radius ≥0.5 mm. Family essential operations are AND-of-OR-alternatives from YAML, matched by regex on source. This can reward syntactically present but unused operations; arbitrary equivalent FS constructions will not match CadQuery spellings. [composite_metrics.py](https://github.com/BenchCAD/BenchCAD-main/blob/52087ef4b08811c21c09b8b16d0ae36c70844865/Vision2Code/scoring/composite_metrics.py), [canonical_ops.py](https://github.com/BenchCAD/BenchCAD-main/blob/52087ef4b08811c21c09b8b16d0ae36c70844865/Vision2Code/scoring/canonical_ops.py), [canonical_ops.yaml](https://github.com/BenchCAD/BenchCAD-main/blob/52087ef4b08811c21c09b8b16d0ae36c70844865/Vision2Code/scoring/canonical_ops.yaml).
- Rotation diagnostic in paper Appendix M: `max_{g in G} IoU(g·Vpred,Vgt)` over either six face-up orientations or 24 proper cube rotations (not arbitrary SO(3), not 24 independent axes). The inspected simple scorer does no rotation search; the composite file retains a section heading and unused rotation argument, not a current executable 24-rotation implementation. Treat the paper protocol and current default runner separately. [Paper M](https://arxiv.org/pdf/2605.10865v2), [current metrics](https://github.com/BenchCAD/BenchCAD-main/blob/52087ef4b08811c21c09b8b16d0ae36c70844865/Vision2Code/scoring/composite_metrics.py).

## Robustness and guarantees

DOCUMENTED execution/visual verification certifies corpus examples under authors' environment, not all parameter values or manufacturing intent. IoU at 64³ cannot certify small holes, chamfers, minimum wall, tolerances or manifoldness. Independent normalization intentionally removes absolute scale and translation; high score can accompany unusable dimensions. Sampled HD is not certified Hausdorff distance. No exact arithmetic, error bounds or tolerance propagation is provided. [Paper limitations/Appendices M/O](https://arxiv.org/pdf/2605.10865v2), [scorer](https://github.com/BenchCAD/BenchCAD-main/blob/52087ef4b08811c21c09b8b16d0ae36c70844865/benchcad_core/scoring/iou.py).

INFERRED: retain aligned/raw-dimensional metrics and exact parameter assertions alongside normalized shape metrics; use rotation only to explain wrong frame, never to make an incorrectly oriented mounting part pass. Do not adopt the negative determinant quarantine literally for wonky: a reflection can be a valid modeling operation if shell orientation is handled correctly.

## Parallelism and performance

DOCUMENTED paper Table 14: GPT-4o on 164 valid extrusion examples has mean `(IoUrot24-IoUfixed)` of .0463 for XY (n=70), .2305 for XZ (n=40), .2140 for YZ (n=54), supporting a workplane bias diagnosis. Table 3 edit scores .865/.853/.837 for its three top thinking models are normalized improvement, not strict edit pass rates. [Paper](https://arxiv.org/pdf/2605.10865v2).

DOCUMENTED author erratum: 185/185 `double_simplex_sprocket` ground-truth scripts rebuilt successfully in pinned CadQuery 2.3.0 / cadquery-ocp 7.9.3.0, slowest 39 s under six-way contention on an unspecified fast Apple-silicon workstation. Different hardware previously omitted 26 records through timeouts; timeout increased 90→300 s. No own execution performed. [ERRATA](https://github.com/BenchCAD/BenchCAD-main/blob/52087ef4b08811c21c09b8b16d0ae36c70844865/docs/ERRATA.md).

INFERRED Bend fit: 24 signed-axis permutation rotations and voxel count reductions are regular fork-join/GPU work; 68³ occupancy can use U32 bitsets with bounded counts. Generate occupancy and tessellation from Bend, never link CadQuery/OCCT into wonky. Chamfer nearest-neighbor searches are irregular; use an independently implemented bounded hierarchy or CPU path, with F32x2 scale-aware distances and explicit approximate labels.

## Relevance for wonky

INFERRED concrete prototype plan:

1. Define an execution result enum separating parse/name-resolution, invalid parameter/empty selection, unsupported geometry, resource timeout, empty/invalid solid and internal failure. Keep these apart from semantic F01–F08 failures and evaluator errors.
2. Build a **small supported-family subset**, manually translate CadQuery recipes to unmodified FeatureScript syntax, preserve source attribution and record intentional unsupported operations (threads/helices/fillets etc.). Store immutable source/parameter/expected topology/volume/dimension/provenance assertions and reference artifact hashes. Do not pretend translating the syntax validates equivalent geometry.
3. Run paired code-vs-render questions, axis-permuted versions and minimal edit tasks. Every sketch report includes world origin, in-plane axes, outward normal and units. For edits, verify unaffected attachments/features and parameter dependency changes, not just voxel similarity.
4. Compute raw-unit checks first; report normalized fixed-frame IoU, optional 24-rotation diagnostic and approximate mesh distances separately. Add FDM wall/gap/hole/clearance assertions where IoU is blind. Tag tessellation/voxel tolerances and evaluator completeness.
5. Freeze renderer resolution/camera, fixture versions, kernel revision, timeout, sample seed, provider budget and cohort denominator. Corpus generation, inference and scoring errors each get separate logs. Precomputed references avoid hardware-sensitive dropped tests.

Bend numeric fit: source relies on binary64 and OCCT, unsuitable as embedded code. Pure F32x2 metrics plus U32 IDs/occupancy can implement the protocol, but exact B-rep geometry/certified predicates must come from wonky. Multi-limb exact predicates help classify boundary samples if needed; no such implementation is contributed by BenchCAD.

## Verdict: adapt

Excellent test taxonomy and family/parameter/edit coverage; use a versioned attributed subset and independently implement wonky metrics. Do not adopt scale-free IoU as dimensional acceptance, regex operations as design-intent proof, or ordinary subprocess execution as a security sandbox. The paper and evolving harness must remain separately identified.
