## What it is

DOCUMENTED: a naming layer over OCCT topology, not a new B-rep geometry kernel. It maps unstable local names such as `Face3` to names encoding feature/object tags, operation codes and ancestor relations. Unchanged entities can retain aliases; operations wrap OCCT Modified/Generated history and derive names for remaining vertices, edges and faces using incidence. The 1.0 release notes explicitly say the topological naming problem is **not completely solved**. [ElementMap interface][emap-h], [operation implementation][topo], [release notes](https://wiki.freecad.org/Release_notes_1.0).

INFERRED: it is a valuable reference for identity storage, persistence, source-history adapters and migration traps. It is **not** a lossless many-to-many provenance database and must not be used as one without redesign. Several details below materially differ from the simplified historical asm3 pseudocode. [Actual naming loop][topo-naming].

## How it works

### Representation and lookup contracts

1. DOCUMENTED: `IndexedName` stores a shared/interned type string plus an integer index, e.g. `Edge` + `12`; printable names use a positive suffix, with null/zero sentinel handling internally. Types accept ASCII letters and underscore. This is local enumeration, not stable geometric identity. [IndexedName.h][indexed].
2. DOCUMENTED: `MappedName` is a two-part byte sequence, an effectively immutable/shared `data` prefix and appendable `postfix`; comparisons access them as one logical string. `MappedNameRef` adds `ElementIDRefs` and a linked list of additional names. [MappedName.h][mapped].
3. DOCUMENTED: `ElementMap` is **not a mathematical bijection**: one indexed entity can have multiple mapped names, but any one mapped name identifies at most one indexed entity in that map. `indexedNames` holds per-type deques of alias records and child ranges; `mappedNames` is an ordered reverse map. `find(index)` returns its primary stored name; `findAll(index)` exposes aliases. The no-overwrite test checks that adding an alias retains the first name as primary; overwrite removes previous aliases. [ElementMap.h][emap-h], [implementation][emap-c], [tests][emap-tests].
4. DOCUMENTED: `MappedChildElements` contains `indexedName`, `count`, `offset`, `tag`, a shared child `ElementMap`, postfix bytes and referenced string IDs. Copies and compounds can share child maps rather than flatten/rebuild every name. Lookup strips the child's postfix, recursively resolves inside the child, verifies type/range and applies its index offset. Occurrence/postfix/tag information is therefore essential when instancing repeated topology. [Child representation][emap-h], [lookup][emap-c], [copy/compound adapters][topo].

### Actual upstream naming passes

DOCUMENTED: `TopoShape::makeShapeWithElementMap(shape, mapper, inputs, op, policy)` first installs the result, handles explicit drop policy, rejects a null result, and checks which inputs are mappable. `Tag == -1` disables mapping; an untagged shape without a map is also unsuitable. It builds vertex/edge/face ancestry caches and invokes `mapSubElement(inputs)` **without** appending the operation, copying names of unchanged OCCT subshapes. It then collects new-name candidates. [Entry and collection][topo-naming], [mappability/unchanged mapping][topo].

DOCUMENTED collection and priorities:

- Visit source **vertices, then edges, then faces**. For each, obtain its mapped name and string references, query `mapper.modified` and `mapper.generated`, and retain candidates that actually appear in the final output. Already-named survivors take precedence. Higher-level Modified results are warned/skipped by this path; generated wires expand into edges and generated shells/solids/compounds into faces. An operation can report intermediates absent from the final shape, so final-result membership is a required filter. [Code][topo-naming].
- `NameKey` sorts by source kind rank, input tag and mapped name. Generated higher-level ancestry is assigned a rank offset of three, delayed when more precise low-level lineage is available. Example: a profile face generates an entire extruded solid, but each side face should preferably depend on its profile edge, not every unrelated hole in the profile. [NameKey and generator handling][topo-naming].
- A positive `NameInfo.index` denotes Modified; a negative index denotes Generated. These are **positions in the mapper's returned sequence**, not stable geometric keys. Two special signed sentinel values identify the first parallel/coplanar generated cap face. Relation type and ordinal are combined in this C++ representation; Bend should separate them. [Collection and encoding][topo-naming].

DOCUMENTED encoding and fallback passes:

1. Derive a name from the first sorted candidate and append `;:M`, `;:G` or mixed `;:MG`, with an ordinal where necessary, operation and source tag. Crucially, the loop stores **at most four additional candidate names** after the first. It also discards higher-level candidates when precise lower-level ones exist. This is deliberate bounded name construction, not complete provenance preservation. [Encoding loop][topo-naming].
2. Traverse downward, face→edge then edge→vertex. Collect potential names from already-named parents and append `;:U` plus a subentity ordinal. Although the comment discusses multiple aliases, this implementation chooses **only the first sorted candidate** (`nameInfoMap.begin()`) for each unnamed lower entity. The container supports aliases; this particular pass does not retain all candidate parents. [Reverse pass][topo-naming].
3. Traverse upward, vertex→edge then edge→face. Require all examined lower entities to be named, sort their names, and derive `;:L`. For faces, inspect **only `BRepTools::OuterWire`**, excluding hole-wire edges. Repeated seam-edge occurrences are deduplicated by the same mapped name. Again, retain the first lower name plus **at most four additional names**. This deliberately reduces sensitivity to some edits, but is not an injective encoding of complete topology. [Forward pass][topo-naming].
4. If unnamed entities remain and delayed candidates exist, perform one delayed round using higher-level history. There is no proof here that every conceivable operation result receives a stable, unique cross-edit name. [Loop termination][topo-naming].

DOCUMENTED grammar correction: current upstream constants define `;:H` as the normal **hexadecimal** tag marker and `;:T` as the **decimal** tag marker; this is not identical to the historical wiki's examples. `;:M`, `;:G`, `;:MG`, `;:U`, `;:L`, `;D`, `?`, child and external markers have separate meanings. A tested encoded face is `Face6;:M2;FUS;:H1:8,F`. Parse/version the representation; do not assume a wiki example is current wire format. [Constants][constants], [encoding][emap-c], [test assertion][emap-tests].

### Reversible interning, persistence and duplicate handling

DOCUMENTED: `StringHasher` ordinarily **interns complete byte strings**, with byte equality checked in a Boost bidirectional table and `long` IDs allocated using `lastID()+1`. Default `Threshold == 0`, so normal names are not replaced with cryptographic digests. The `MappedName` overload factors type/index/postfix and tracks related string IDs. The raw-byte overload only substitutes SHA-1 if Hashable is enabled, threshold is positive and input exceeds it; that value cannot be dehashed. A table-local ID is not a globally stable content hash. [StringHasher.cpp][hasher-c], [StringHasher.h][hasher-h].

DOCUMENTED: before saving, `ElementMap::beforeSave` marks referenced IDs and recursively visits child maps; `StringID::mark` propagates to related IDs. ElementMap serializes child maps/postfix tables and alias references; restore checks stream structure and warns on missing hash tables/IDs. This preserves hidden intermediate name dependencies that would otherwise vanish when temporary shape objects are destroyed. The encoder also intentionally collapses repeated same-object-tag history to avoid accumulating many unobservable internal steps. INFERRED: this is another reason not to reconstruct a full operation event log from final names. [Save/restore and encoder][emap-c], [ID marking/compaction][hasher-c].

DOCUMENTED: `setElementName` validates strings and inserts into the reverse map. A duplicate name already bound to another entity is renamed with `;D`. **Debug builds use the retry counter, but non-debug builds use `std::mt19937` seeded from `std::random_device`, drawing integers 1..10000**, formatted as hexadecimal. The loop logs an unresolved duplicate after 100 attempts and returns the original name; it does not guarantee a successful new binding at that point. INFERRED: never copy this fallback into a deterministic/reproducible identity contract, and never treat its returned string alone as proof of a valid binding. [setElementName / renameDuplicateElement][emap-c].

DOCUMENTED: `traceElement` stops at external-link markers, tracks seen tags and imposes a **50-iteration limit**. Its code explains that looking up an external name against the wrong document string table can create circular mappings. Name resolution requires its document/occurrence/hasher namespace, not just a byte string. [traceElement][emap-c].

### Numeric model and operation adapters

DOCUMENTED: basic map/string operations are combinatorial, but the full implementation is **not precision-free**. `checkForParallelOrCoplanar` finds planes, tests axes with OCCT `Precision::Angular()`, and tests both normal-projected origin separations against `Precision::Confusion()`, using `gp_Pln`, `gp_Vec` and `Standard_Real`. It gives special cap indices to stabilize extrusions when profile holes change. The tolerance values are delegated to the OCCT build, not parameters of ElementMap. [Cap heuristic][topo-naming].

DOCUMENTED: `MapperMaker`, `MapperHistory`, `MapperSewing`, `MapperThruSections` and others normalize different OCCT history APIs. For example, sewing checks `Modified` then `ModifiedSubShape`; through-sections can fall back to `GeneratedFace` and end profiles. Several adapters catch `Standard_Failure`, log and return the collected list rather than exposing a history-completeness error. `makeElementRefine` populates a separate Modified mapper and attempts solid orientation repair. No `IsDeleted` set is retained by the core naming loop. INFERRED: operation history must remain a separate complete/partial relation, not be inferred from an empty mapper list or absent alias. [Adapters/refine][topo].

## Robustness and guarantees

DOCUMENTED guarantees are local data-structure contracts: one stored mapped-name key maps to one indexed entity; multiple aliases can point to that entity; default interning compares actual bytes rather than assuming collision-free hashes; lower-derived names are not assigned while required examined lower names are missing. These are useful invariants, not a proof of persistent naming across arbitrary parameter edits. [Interfaces][emap-h], [StringHasher equality][hasher-c], [naming passes][topo-naming].

INFERRED limits follow directly from the inspected implementation: output order affects split/generated ordinals; bounded parent lists and winner selection lose ancestry information; symmetry cannot be resolved by strings alone; duplicate renaming can be nondeterministic; optional lossy SHA-1 storage prevents history reconstruction; tag history can be collapsed; geometry-based stabilization inherits OCCT precision. Complete native operation lineage is therefore a stronger and different contract than the names generated here. [Naming loop][topo-naming], [encoding/duplicates/tracing][emap-c], [hashing][hasher-c].

DOCUMENTED migration detail: `getElementMapVersion()` combines an operation-code version, a deliberately frozen OCCT-version field `0x070200`, and ComplexGeoData's map version. The code freezes that field for compatibility with LinkStage3 rather than reporting the actual linked OCCT release. INFERRED: do not use it as a kernel dependency fingerprint; wonky should persist its actual identity algorithm version separately from geometry provenance. [Version implementation][topo].

## Parallelism and performance

DOCUMENTED: these naming routines use nested sequential loops, mutable ordered/unordered maps, linked aliases, reference counting and shared child maps. `makeElementGeneralFuse` sets OCCT `SetRunParallel(true)`, but that is a geometric Boolean setting, not evidence that name construction is parallel. [Naming and GeneralFuse code][topo], [containers][emap-h].

No isolated, measured runtime/memory benchmark for this naming layer was found in the inspected files, release documentation or issue discussions; no speedup claim or Bend/GPU timing is justified. DOCUMENTED as an **author claim, not a measured result**: V2's draft PR says StringHasher decreases performance for a small file-size improvement, and proposes removing it. This is a useful reason to benchmark interning overhead, not proof that every interning design is slow. [PR #31040](https://github.com/FreeCAD/FreeCAD/pull/31040).

INFERRED Bend model: flat immutable relation arrays can be built with balanced map/flatten, lexicographic sort, unique and segmented reductions. For R emitted relation rows, a comparison-sort prototype is O(R log R) work; its actual fork-join span depends on the chosen sorting implementation. Hierarchical child-map/DAG reuse avoids repeated flattening. Variable-depth string expansion/history walks are irregular GPU work; batch fixed-width IDs and incidence relations instead. CPU-first identity is reasonable until profiling justifies GPU padding/bucketing. [Workload evidence][emap-h], [naming loop][topo-naming].

## Relevance for wonky

INFERRED priority: **adapt the architecture, not the name grammar**. Keep a complete typed immutable provenance DAG in Bend, with entity kind/index, revision/occurrence namespace, unchanged/Modified/Generated relation, operation, semantic role, and a history-completeness state. Build compact display/reference names as a view of that data. Do not truncate parent sets to five or discard legitimate split descendants simply to shorten a label. This addresses the revision-local Boolean identity gap identified in `<repo>/kernel/identity.bend::boolean_result` and `<repo>/src/identity.mjs::matchTopologyReference` (local baseline inspected earlier in this batch). Source basis is the separation between history collection, name encoding and reverse-map lookup in [upstream code][topo-naming].

INFERRED concrete prototype design:

1. In each modeling operation, emit complete relation rows to final B-rep entities, including history through analytic recovery, sew/refine and later fillets. A tagged mesh face alone is not enough for all generated edges/vertices. Distinguish a complete empty descendant set from unsupported history. [Adapter lessons][topo].
2. Sort/group canonical structural tuples into a shared immutable DAG. Use U32 type/role/tag fields; use multiple U32 limbs or explicitly bounded identifiers where FreeCAD uses platform-sized `long` and `size_t`. Use tagged variants for Modified/Generated/cap-role/sentinel cases instead of negative ordinals or INT_MIN tricks. No F64 or exact-rational arithmetic is needed in this base layer. [Fields and sentinels][topo-naming], [StringID types][hasher-h].
3. Maintain both entity→name aliases and name→entity lookup, but expose **known split/merge successor sets** separately. A single-valued reverse-name lookup cannot represent the full translation relation across revisions. Ambiguous selection must remain ambiguous rather than taking the first sorted or random candidate. [ElementMap contract][emap-h], [V2 multi-child proposal](https://github.com/FreeCAD/FreeCAD/pull/31040).
4. Hash limbs may accelerate structural comparisons, but verify collisions against complete keys. Persist the reachable DAG, all referenced intern records, namespaces and algorithm versions in the native format; a JS-only string table is insufficient for standalone native Bend save/reload. Deterministic allocation/order policy is needed if identifiers are expected to survive parallel scheduling. [Interning/persistence basis][hasher-c], [map persistence][emap-c].
5. Prefer explicit operation semantic roles such as start-cap/end-cap over rediscovering them by geometry. Where geometry fallback is needed, use qualified F32x2 error bounds/tolerances; multi-limb U32 predicates only help for exactly represented algebraic predicates. Never silently imitate unknown OCCT tolerance constants with plain F32 equality. [Current cap heuristic][topo-naming].
6. Separate proven lineage from heuristic repair in the API and review UI. Even FreeCAD's `chooseMatchingSubShapeByPlaneOrLine` rejects multiple coplanar/same-edge candidates rather than choosing arbitrarily. A single coplanar face is still a repair suggestion, not proof of design intent. [Repair helper][topo].

INFERRED regression fixtures worth adding later, not executed here: two names→one entity; same name→two outputs; split→merge→split; more than five parents; internal-hole edits versus outer-wire edits; repeated identical occurrences; reversed operation input order; concurrent schedule permutations; mapper returns an intermediate absent from final output; refine changes orientation; partial/failed history; persistence after temporary nodes disappear; external namespace mismatch; algorithm-version migration. Measure silent wrong retargets separately from unresolved selections. These tests target naming/diff/LLM ergonomics and reliable fillet/FDM feature review, not SSI accuracy or watertightness. [Implementation failure surfaces][topo-naming], [duplicates/tracing][emap-c], [reported regressions](https://github.com/FreeCAD/FreeCAD/issues/29154).

## Verdict: adapt

Adapt the alias/child-map separation, operation-specific history adapters, final-result filtering, reversible persistence and explicit naming versions. Independently implement a **complete provenance relation** in Bend; make display naming a secondary view. Do not translate this implementation literally: the current algorithm truncates ancestry, uses unstable ordinals and randomized duplicate suffixes, and relies on tolerance-based geometric heuristics in places. Read V2 before considering any string-format compatibility investment. No production files changed.
