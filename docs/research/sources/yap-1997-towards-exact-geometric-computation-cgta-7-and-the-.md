## What it is
DOCUMENTED: EGC is a semantic contract, not an instruction to calculate every intermediate decimal digit: mathematical objects must be represented exactly and decisions must never be wrong. Equality and sign are central. Yap allows approximate internal evaluation and even approximation problems with explicit output guarantees. An algebraic number can be represented by an integer polynomial plus a rational interval containing exactly one root; a floating-point approximation alone is not that representation. The 1997 paper is a research framework; Core is later software realizing much of it. [Yap §§3–4](https://cs.nyu.edu/~exact/doc/towards.pdf).

## How it works
1. **DOCUMENTED: bounded derivation, not merely bounded inputs.** In a rational bounded-depth (RBD) algorithm, s-bit rational inputs imply intermediate rational sizes at most D·s+O(1) for a constant D depending on the computation. For fixed machine-sized inputs this admits fixed-word exact arithmetic with constant-factor overhead. General operation depth d gives a coarse D=2^d; determinant-specific analysis is much tighter. Repeated CAD transforms/Booleans are explicitly given as a counterexample to assuming bounded depth for an indefinitely edited model. [Yap §4, printed pp.12–14](https://cs.nyu.edu/~exact/doc/towards.pdf).
2. **DOCUMENTED: exact construction identity with lazy approximation.** The proposed expression variable stores its defining expression E, approximate value v, and error certificate. Composite precision [a,r] permits either absolute error ≤2^-a or relative error ≤2^-r. BigEval preprocesses whole expressions, enabling static bounds, algebraic restructuring, runtime filters and lazy evaluation rather than isolated arbitrary-precision arithmetic calls. [Yap §§6.1–6.2](https://cs.nyu.edu/~exact/doc/towards.pdf).
3. **DOCUMENTED: constructive zero bounds.** Core computes B(E)>0 such that a defined nonzero algebraic E satisfies |E|>B(E). Refine a certified enclosure until it excludes zero, or until the enclosure/absolute error together with B proves E=0. Merely observing repeated approximations near zero is not a proof. Default Core 2 separates Rootbd, Filter and Kernel template modules and uses BF(M)SS k-ary algebraic bounds. [Core 2 §§1,3](https://cs.nyu.edu/~exact/doc/core2.pdf), [RootBounds.h](https://github.com/fmi-alg/core2/blob/f27752ecbd1784aa5cd9556da13056cd7d91fcd8/inc/CORE_TWO/RootBounds.h).
4. **DOCUMENTED: concrete evaluation pipeline.** get_sign() tries certified filter, cached sign, existing interval, operator-specific recursive sign rule, then refine(). Multiplication often needs only child signs, not accurate magnitudes. refine() initializes precision at 53 bits in the inspected code, chooses a constructive bound for algebraic nodes or an escape bound for transcendental ones, applies a global cutoff, doubles requested absolute precision with a cap at that bound, and queries whether the resulting interval has a sign. Caches include sign and upper/lower logarithmic magnitude bounds (uMSB/lMSB). Node categories distinguish integer, dyadic, rational, algebraic and transcendental. [ExprRep.h, get_sign/refine](https://github.com/fmi-alg/core2/blob/f27752ecbd1784aa5cd9556da13056cd7d91fcd8/inc/CORE_TWO/ExprRep.h), [Core 2 §3.3](https://cs.nyu.edu/~exact/doc/core2.pdf).
5. **DOCUMENTED: numeric engine.** Core 1 used interval-like (mantissa,error,exponent) triples; Core 2 separates MPFR-backed BigFloat from endpoint-pair BigFloat2 intervals with directed rounding. Exact ring operations can allocate enough mantissa bits to preserve a result; approximate operations deliberately round to requested precision. Multiplying two p-bit approximations exactly creates needless 2p-bit work when only p output bits are requested. [Core 2 §4](https://cs.nyu.edu/~exact/doc/core2.pdf), [BigFloat2.h](https://github.com/fmi-alg/core2/blob/master/inc/CORE_TWO/BigFloat2.h).
6. **DOCUMENTED: useful earlier optimization.** Rational point/hyperplane coordinates should share a homogeneous denominator. For three planes with s-bit integer coefficients, intersection numerator/denominator determinants need roughly 3s+log2(6) bits, versus much worse naive rational intermediates. Common-denominator conversion uses a balanced bottom-up product tree followed by top-down sibling products, avoiding repeated division and gcd. [Yap §6.3, printed pp.19–20](https://cs.nyu.edu/~exact/doc/towards.pdf).

## Robustness and guarantees
- DOCUMENTED: algebraic sign determination rests on certified approximations **and valid zero bounds**. Arbitrary precision without a zero test is not EGC. Division-by-zero and invalid root domains still need decisions; exact arithmetic does not repair a logically incorrect geometric algorithm. [Yap §3; Core 2 §§1,3.3](https://cs.nyu.edu/~exact/doc/core2.pdf).
- DOCUMENTED: Core 2's transcendental escape bound and optional algebraic cutoff provide only **conditional correctness**. If refinement reaches one, the code reports a ZERO ASSERTION then sets the value/sign to zero. Default cutoff is infinity in the paper; selecting a finite budget changes the contract. This is emphatically not a certified “near zero means zero” theorem. [Core 2 §3.3, steps 6–7 and §11](https://cs.nyu.edu/~exact/doc/core2.pdf), [actual refine code](https://github.com/fmi-alg/core2/blob/f27752ecbd1784aa5cd9556da13056cd7d91fcd8/inc/CORE_TWO/ExprRep.h).
- INFERRED: wonky should return Unknown/PrecisionBudgetExceeded at that point, retaining expression and enclosure as diagnostics; never convert budget exhaustion into topological equality. A proved nonzero lower bound b combined with an enclosure strictly inside (-b,b) certifies zero; use rigorously directed integer/interval comparisons for that test.

## Parallelism and performance
DOCUMENTED: the 1997 paper is not a benchmark study. Its historical slowdowns are explicitly anecdotes from other work, not measurements of Core or evidence for Metal performance. Core 2 reports measurements on Intel Core Duo 2.4 GHz, 2 GiB, Cygwin 1.5, g++ 3.4.4: MPFR-based square roots improve by about 22–25× over Core 1 at 1,000–100,000-bit precision (Fig.8); small filtered determinants can instead be nearly 2× slower (Fig.4). A chain-form harmonic sum segfaults at n=100,000 in their experiment; an anary summation representation completes (Fig.9). Treat these as architecture lessons, not current throughput predictions. [Core 2 §§1,3.2,4.1,5.1](https://cs.nyu.edu/~exact/doc/core2.pdf).

INFERRED: independent predicates and balanced arithmetic subtrees fit fork-join. The stock engine's mutable reference-counted DAG, lazy per-node allocation, std::map-based radical deduplication, adaptive precision and recursion are not uniform GPU work. Repeated use of a radical must be counted once in a degree bound; immutable node IDs plus sorted unique radical sets or a conservative overbound can replace visited flags/maps. [Core 2 §§3.2–3.3](https://cs.nyu.edu/~exact/doc/core2.pdf).

## Known failures, limitations, war stories
- DOCUMENTED: Core 2.1 announcement lists fixes for **root-bound overflow** and printing garbage digits. Root-bound metadata itself can overflow even when operand arithmetic is exact. [Announcement](https://github.com/fmi-alg/core2/blob/master/ANNOUNCEMENT).
- DOCUMENTED: inspected get_sign() disables filters and cached-interval sign shortcuts for transcendental nodes; the comment specifically records a wrong sign from a Log node at insufficient precision. This is a code comment about a workaround, not a newly reproduced bug. [ExprRep.h](https://github.com/fmi-alg/core2/blob/f27752ecbd1784aa5cd9556da13056cd7d91fcd8/inc/CORE_TWO/ExprRep.h).
- DOCUMENTED: deep expression chains caused stack overflow in the published harmonic-sum example; repeated construction depth can grow exact representations exponentially. [Core 2 §5.1](https://cs.nyu.edu/~exact/doc/core2.pdf), [Yap §4.1](https://cs.nyu.edu/~exact/doc/towards.pdf).
- DOCUMENTED: no issues are exposed by the inspected fork's issue API; this is not evidence of bug-freedom or recent upstream maintenance. No builds/tests were run. [Issue API](https://api.github.com/repos/fmi-alg/core2/issues?state=all).

## Relevance for wonky
**INFERRED from the sources above and supplied constraints:**
- Adopt EGC semantics across the hybrid Boolean boundary. Preserve analytic construction provenance and exact predicate inputs; let tessellation/rendering use separate tolerance-certified approximations. Exact decisions on a rounded surrogate do not certify the original curved solid.
- Start with RBD polynomial/rational predicates, emitted as fixed-width U32 limb programs. A single finite binary32 is an exact dyadic rational; F32x2 raises significand precision but does not give arbitrary exponent range or algebraic equality. State input exponent/bit bounds and expression-depth limits explicitly.
- For plane/cylinder SSI, root ordering, tangency and eventual fillets, use bounded algebraic expression nodes plus isolating intervals and degree/height certificates. Allocate limbs from checked per-operation bounds, not a universal guessed width. Budget overflow returns a typed unsupported result. Arbitrary constructions may exceed any practical preselected budget; the paper does not prove all CAD operations fit.
- Represent immutable evaluation state separately from expression structure; process fixed precision tiers in separate balanced passes. Compute a filtered result for all work items, compact or partition unresolved items with pure scans, then run a uniform limb/root-refinement tier. A single adaptive recursive Core evaluator would diverge badly on GPU.
- Provenance and numeric certificates improve diff/LLM diagnostics: report predicate expression, input object IDs, interval, required/available bit count, and whether failure is arithmetic budget, unsupported transcendental comparison or geometric degeneracy.

## Verdict: adopt
Adopt the **EGC contract, bounded-depth accounting and filter/root-bound/approximation separation**. Study Core as an implementation and cautionary case, not a backend or literal port. Root bounds, extended exponent handling and immutable staged evaluation remain engineering work; transcendental cutoff-to-zero is explicitly unsuitable for wonky.
