## What it is

DOCUMENTED: code-CAD selectors organize three questions: what an entity is (geometry/type/size), how it sits in its containing shape (selection route, convexity, adjacency distance), and when it came to be (last-operation history). `ShapeHistory` wraps OCCT history; `topo_path` records the route through which a wrapper was selected. These are distinct kinds of provenance. **Neither is a complete persistent naming solution across arbitrary source-code regeneration.** [Docs](https://build123d.readthedocs.io/en/latest/topology_selection.html), [history.py](https://github.com/gumyr/build123d/blob/e22d34dae17111e5b9fdb361317e055d0daae466/src/build123d/topology/history.py).

## How it works

### Forward history and reverse classification

DOCUMENTED: `ShapeHistory` holds an OCCT `BRepTools_History`, `before` inputs, `brought` inputs and a lazy cached pair of reverse `Trace` indexes. Tracked types are vertices, edges, faces and solids; wires/shells/compounds are untracked containers. Forward queries return `modified(source)`, `generated(source)`, and `is_removed(source)`. Modified is same-kind rebuilding/splitting; generated is new topology originating from another entity. A source may be removed while generating another entity: the fillet tests explicitly record consumed edges and generated fillet faces together. Do not model these relations as four mutually exclusive input states despite the module's introductory wording. [history.py lines 61–63,98–176,284–372](https://github.com/gumyr/build123d/blob/e22d34dae17111e5b9fdb361317e055d0daae466/src/build123d/topology/history.py), [fillet test](https://github.com/gumyr/build123d/blob/e22d34dae17111e5b9fdb361317e055d0daae466/tests/test_direct_api/test_history.py#L109-L119).

DOCUMENTED: `Trace` scans each distinct input subshape, puts its identity in an `untouched` membership map and builds result-keyed `modified_from` and `generated_from` maps. The raw untouched map is not filtered for survival; selectors query only actual result entities, so membership means an input identity survived. Reverse maps store one source value per result key, sufficient for the boolean membership predicates, but not a complete many-origin provenance relation. [Trace](https://github.com/gumyr/build123d/blob/e22d34dae17111e5b9fdb361317e055d0daae466/src/build123d/topology/history.py#L335-L372). INFERRED: wonky must retain a multimap if it needs every contributor after clean/merge.

DOCUMENTED predicates, expressed as set equations from the code: let R be result subshapes, I₀/M₀ the identities/modified descendants of `before`, and I₁/M₁ those of `brought`.

- `ALL = R`.
- `NEW = R \ (I₀ ∪ M₀ ∪ I₁ ∪ M₁)`.
- `LAST = (R ∩ (I₁ ∪ M₁)) ∪ NEW`.

Thus LAST includes a modified descendant of a tool that was brought in, but not a merely rebuilt descendant of the preexisting object. A result descending from both before and brought counts as LAST. NEW is **not exactly the Generated relation**: it includes anything not attributable through unchanged/modified identity, even a new solid or an unreported result. Generated relations remain useful for origin queries. [is_last/is_new](https://github.com/gumyr/build123d/blob/e22d34dae17111e5b9fdb361317e055d0daae466/src/build123d/topology/history.py#L290-L310).

DOCUMENTED: Algebra mode uses left operand as before, right operand as brought. Consequently the same commutative geometric union can have different LAST sets when operands are swapped; this is operation context, not geometric identity. In Builder mode `_add_to_context` supplies the pre-operation object and newly integrated objects; REPLACE brings no new input and uses the replacement's history. [Builder integration](https://github.com/gumyr/build123d/blob/e22d34dae17111e5b9fdb361317e055d0daae466/src/build123d/build_common.py#L504-L600), [Boolean wrapper](https://github.com/gumyr/build123d/blob/e22d34dae17111e5b9fdb361317e055d0daae466/src/build123d/topology/shape_core.py#L2769-L2879).

### Collection and composition

DOCUMENTED: booleans use `operation.History()` directly; `clean()` uses `ShapeUpgrade_UnifySameDomain.History()`. `_bool_op` builds, then merges cleanup history before attaching the record to the final result. Without this composition, selectors would describe pre-clean topology rather than returned faces. `merge` mutates the wrapper and invalidates reverse caches. [history.py constructors/merge](https://github.com/gumyr/build123d/blob/e22d34dae17111e5b9fdb361317e055d0daae466/src/build123d/topology/history.py#L131-L176), [Boolean clean](https://github.com/gumyr/build123d/blob/e22d34dae17111e5b9fdb361317e055d0daae466/src/build123d/topology/shape_core.py#L2840-L2860).

DOCUMENTED: generic MakeShape collection asks Modified/Generated for each tracked input. It deliberately avoids `IsDeleted` because some algorithms guess for unsupported entity kinds. Instead, the actual code marks a source removed if it has no Modified answers and its identity is absent from the result. `_answers` catches any exception and returns an empty list because OCP binds several unrelated kernel failures directly to Python `Exception`. This is a pragmatic adapter, not certified complete history. Sewing separately queries Modified faces and ModifiedSubShape edges/vertices. [history.py lines 74–84,147–203](https://github.com/gumyr/build123d/blob/e22d34dae17111e5b9fdb361317e055d0daae466/src/build123d/topology/history.py#L74-L203).

### Selection route and adjacency

DOCUMENTED: `_extracted_from(source)` sets `topo_path = source.topo_path + (source,)`. `topo_parent` is the first element and `topo_owner` the last. Selecting an edge through a face yields `(box,face)`, whereas selecting directly from the box supplies no face owner. This captures the side/context intended for operations that need it; the route is metadata, excluded from geometry equality, and held by reference through copies. It is not a serialized stable ID or regeneration recipe. [shape_core.py lines 336–371](https://github.com/gumyr/build123d/blob/e22d34dae17111e5b9fdb361317e055d0daae466/src/build123d/topology/shape_core.py#L336-L371), [docs route section](https://build123d.readthedocs.io/en/latest/topology_selection.html#selection-route).

DOCUMENTED: `topo_distance_to` builds adjacency in a common topo_parent and runs a multi-source BFS: faces connect through edges; edges/wires through vertices; shells/solids through faces; vertices through edges. It checks shared parent and homogeneous type, returns 0 for sources and infinity for unreachable peers, and evaluates against the full parent topology rather than just the filtered selection list. [implementation](https://github.com/gumyr/build123d/blob/e22d34dae17111e5b9fdb361317e055d0daae466/src/build123d/topology/shape_core.py#L3125-L3305).

## Robustness and guarantees

DOCUMENTED: selection history uses topology identity, not geometric coordinate equality or nearest-face heuristics. OCCT IsSame includes underlying TShape plus location, ignoring orientation; it is not durable semantic identity. Geometry uses Python float/OCP real-valued APIs; the project defines `TOLERANCE = 1e-6`, but the record classifier itself has no distance tolerance. No exact predicates or F32-only model are provided. [is_same/deepcopy](https://github.com/gumyr/build123d/blob/e22d34dae17111e5b9fdb361317e055d0daae466/src/build123d/topology/shape_core.py), [geometry.py constants](https://github.com/gumyr/build123d/blob/e22d34dae17111e5b9fdb361317e055d0daae466/src/build123d/geometry.py#L104-L105). INFERRED: keep wonky's history layer U32-only, while reimplementing geometric predicates with F32x2/error bounds or exact U32 limbs; don't inherit a global 1e-6 indiscriminately.

DOCUMENTED: shape-level LAST/NEW raises if `_history is None`. A Builder fallback can instead attach an empty record, classifying every nonidentical result as new. Therefore “no answer from history” can become “new” rather than an explicit unknown. Fresh Rectangle without history is tested to raise. [selector](https://github.com/gumyr/build123d/blob/e22d34dae17111e5b9fdb361317e055d0daae466/src/build123d/topology/shape_core.py#L1518-L1536), [fallback](https://github.com/gumyr/build123d/blob/e22d34dae17111e5b9fdb361317e055d0daae466/src/build123d/build_common.py#L579-L599), [test](https://github.com/gumyr/build123d/blob/e22d34dae17111e5b9fdb361317e055d0daae466/tests/test_direct_api/test_history.py#L266-L269).

INFERRED from inspected code: generic wires/shells selection accepts LAST/NEW, but those containers are excluded from tracked_subshapes, so an untracked container is unattributed and falls through as NEW. Do not assume identical lineage semantics for every shape type from the documentation sentence “all three are available for every shape type.” This is static code reasoning, not a runtime reproduction. [tracked types](https://github.com/gumyr/build123d/blob/e22d34dae17111e5b9fdb361317e055d0daae466/src/build123d/topology/history.py#L61-L95), [generic wires selection](https://github.com/gumyr/build123d/blob/e22d34dae17111e5b9fdb361317e055d0daae466/src/build123d/topology/shape_core.py#L2743-L2745).

## Parallelism and performance

DOCUMENTED: `_bool_op` enables OCCT's parallel builder, but history collection, reverse-map construction and adjacency BFS are mutable sequential Python/C++ operations. No standalone selector benchmark suite was run here. [Boolean code](https://github.com/gumyr/build123d/blob/e22d34dae17111e5b9fdb361317e055d0daae466/src/build123d/topology/shape_core.py#L2840-L2847).

DOCUMENTED author-reported measurement, not independently reproduced: the [2026-09-10 commit](https://github.com/gumyr/build123d/commit/1a7751a1c8d1acde46edac76a032cfeafa89dc48) says iterating an OCP TopTools list through its Python protocol costs about 1.3 ms per list even when empty; copying then popping reduced topological-distance sorting of a plate with 60 holes from 0.33 s to 2 ms. [kernel.list_shapes](https://github.com/gumyr/build123d/blob/e22d34dae17111e5b9fdb361317e055d0daae466/src/build123d/topology/kernel.py#L36-L51) implements that adapter. This measures binding/container overhead for a particular workload, NOT a general Boolean/history speedup and NOT a Bend forecast.

INFERRED: reverse-index construction and result filtering fit balanced fork-join via immutable sort/group/join. Cached indexes should be snapshot-owned rather than invalidated through mutation. GPU-friendly record filtering can use fixed-width U32 bitsets/tags; transitive history and adjacency BFS need level-synchronous/bucketed work or a CPU path. No FFI/kernel embedding is necessary or allowed in the proposed port.

## Known failures, limitations, war stories

- DOCUMENTED [open #1453](https://github.com/gumyr/build123d/issues/1453): moving a recorded holed box makes all seven faces classify as NEW although none did before movement, because the copied history still names old-location shapes. Code inspection confirms `_history` is shared in `__deepcopy__`, while `moved`, `located` and `_apply_transform` replace/move wrapped geometry without chaining a relocation record. Not executed locally. `ShapeHistory.from_relocation` exists, but its existence alone does not fix callers. The issue also requires copying the record before extension to avoid corrupting the original.
- DOCUMENTED [#1452](https://github.com/gumyr/build123d/issues/1452) proposes universal operation/primitive history and is closed citing the original history commit. Nevertheless pinned `Solid.make_box` attaches no record, docs still warn about fresh primitives and the unit test expects Rectangle NEW to raise. Closed issue status is not proof that its entire proposed acceptance table is implemented.
- DOCUMENTED [open #1454](https://github.com/gumyr/build123d/issues/1454): persistent semantic tags are a PROPOSAL, not a shipped feature to cite as complete naming. Suggested propagation duplicates tags on split, reconciles merge conflicts, drops removed tags and makes Generated inheritance opt-in. The issue explicitly acknowledges unresolved topological-naming intent problems.
- DOCUMENTED [#455](https://github.com/gumyr/build123d/issues/455): historical Select.NEW/chamfer empty-selection confusion, reported in 2024. Its comments describe the old geometric-comparison implementation; don't apply those semantics unchanged to the September 2026 record-based implementation. [#1071](https://github.com/gumyr/build123d/issues/1071) likewise remains open while source now supports NEW for more entity types.
- DOCUMENTED: generic collection swallows kernel query errors into empty histories; unreported results can appear new. INFERRED: wonky should instead propagate a history-completeness flag and distinguish Unknown from Generated. [history adapter](https://github.com/gumyr/build123d/blob/e22d34dae17111e5b9fdb361317e055d0daae466/src/build123d/topology/history.py#L74-L84).

## Relevance for wonky

INFERRED: expose operation provenance as a first-class query service, including Created/Generated/Modified/Deleted/Unchanged and an explicit operand-role distinction. “Fillet the edges I just created” must exclude merely rebuilt old edges; “select walls introduced by this cutter” must include tool descendants even when not NEW. Keep LAST operation-relative, not a global timestamp or alias for Modified.

INFERRED data model: immutable rows `(operationId,inputEntityId,outputEntityId,evolution,inputRole)` plus snapshot input/result sets and a completeness flag. Compose Boolean→clean/recovery histories, preserve every source on merges, and distinguish semantic owner from geometric TShape-like identity. Stable entity keys should not include placement; occurrence/placement identity is a separate layer. Copies, placements, pattern instances and analytic-recovery coalescing must each define their mapping contract.

INFERRED: add a selection-context value `(rootOccurrence, ownerFace/coedge, selectedEntity, route)` so fillet/convexity/offset queries can use the correct side. Use a serializable recipe with stable IDs rather than live Python wrapper pointers for persistent references. Keep route metadata separate from operation lineage and from feature-domain semantic names.

INFERRED conformance tests worth porting: cylinder standing on box (existing circle LAST but not NEW); through-cylinder (two newly generated circle edges); fillet (old faces Modified, fillet faces Generated, source edges Deleted); clean merges preserving original-face ancestry; split one source into many; several sources merge into one; move/copy preserving selection without modifying the original record; missing-history returning Unknown/Unsupported. Test predicate counts and origin relations, not only valid output geometry. These test ideas can run in Bend without Python/OCCT and matter directly to FDM wrong-edge-fillet prevention and explainable model diffs.
