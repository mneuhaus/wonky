## What it is
DOCUMENTED: Predicates on explicit and *constructed* points without first rounding the constructed Cartesian coordinates. Supported implicit kinds include 2D segment/line intersection (SSI), 3D line–plane (LPI), three-plane (TPI), linear combination (LNC), triangle barycentric point (BPT), and tetrahedron barycenter (TBC). Cascades can contain other implicit points. Operations include orientation, incircle/insphere, comparisons and dot-product signs. This is directly relevant to mesh arrangement vertices; it is not curved-surface intersection/root isolation. [Point API](https://github.com/MarcoAttene/Indirect_Predicates/blob/74960591e0381f85d94bcee603829451f016b4a2/include/implicit_point.h#L45-L165).

## How it works
1. **Retain construction, not rounded position.** DOCUMENTED: point objects hold references to their generators and cached interval homogeneous coordinates. For 3D, x=lx/d, y=ly/d, z=lz/d. LPI/TPI compute numerator and denominator polynomials; exact evaluation recursively follows the original input provenance. Explicit points have denominator 1. [Construction/evaluation](https://github.com/MarcoAttene/Indirect_Predicates/blob/74960591e0381f85d94bcee603829451f016b4a2/include/implicit_point.hpp#L59-L96).
2. **Clear divisions in a predicate.** DOCUMENTED: orient3d_IEEE forms v1=p2-p4, v2=p3-p4, v3=lambda(p1)-d1*p4, then a determinant-like polynomial. Its sign equals the Cartesian orientation only under the denominator-sign invariant. Normalize all homogeneous components when d is negative; reject an interval stage if d's sign cannot be certified. General combinations IIEE/IIIE/IIII have separate formula files. [Readable input formula](https://github.com/MarcoAttene/Indirect_Predicates/blob/74960591e0381f85d94bcee603829451f016b4a2/JPCK_V2/predicates/indirect/orient3d_indirect_IEEE.txt), [generated routine](https://github.com/MarcoAttene/Indirect_Predicates/blob/74960591e0381f85d94bcee603829451f016b4a2/include/indirect_predicates.h#L3151-L3190).
3. **Important current-version staging correction.** DOCUMENTED: default JPCK_V2 output uses **interval → exact bigfloat for indirect predicates**. For direct predicates it uses a static double filter, then expansions only when polynomial degree <5, then bigfloat. The templated body supports all number types, but that does not mean every runtime wrapper executes all stages. GEN_STATISTICS takes a different path. [Generator dispatch](https://github.com/MarcoAttene/Indirect_Predicates/blob/74960591e0381f85d94bcee603829451f016b4a2/JPCK_V2/jpck.cpp#L1207-L1266).
4. **Generator input and analysis.** DOCUMENTED: an ordered list of named inputs and single-assignment polynomial equations; genericPoint(p:l1,l2,l3,d) introduces homogeneous inputs. Expression trees support +, -, *, powers 2/3, fmadd/fmsub. getComposedPolynomial substitutes prior definitions for whole-expression analysis; getErrorBound propagates magnitude, absolute error and degree. For multiplication, E=E1*E2+E1*V2+E2*V1+rounding_error; addition sums operand errors plus rounding error. Direct filters accept only when |computed| > C*max_var^degree, where max_var includes translated coordinate differences. Constants and ulp analysis are binary64-specific. [Analysis](https://github.com/MarcoAttene/Indirect_Predicates/blob/74960591e0381f85d94bcee603829451f016b4a2/JPCK_V2/jpck.cpp#L576-L830), [composition and emission](https://github.com/MarcoAttene/Indirect_Predicates/blob/74960591e0381f85d94bcee603829451f016b4a2/JPCK_V2/jpck.cpp#L977-L1205).
5. **Numeric backend is separate now.** DOCUMENTED: CMake fetches NFG main (unpinned). Inspected NFG a5ab699, last commit 2026-09-04: 316 KiB repository metric, 10 stars, 2 contributors, no releases. bignatural uses mutable base-2^32 limb arrays; bigfloat is an exact dyadic sign*magnitude*2^exponent for polynomial arithmetic, not a fixed-precision approximate float. Exponent is signed 32-bit; limb operations use uint64 intermediates and thread-local pools. [NFG numeric definitions](https://github.com/MarcoAttene/NFG/blob/a5ab69965a32c761c2cb29bbba2a63616f2801eb/include/numerics.h#L692-L986), [metadata](https://api.github.com/repos/MarcoAttene/NFG), [contributors](https://api.github.com/repos/MarcoAttene/NFG/contributors), [releases](https://api.github.com/repos/MarcoAttene/NFG/releases).

## Robustness and guarantees
- DOCUMENTED: interval arithmetic requires upward rounding; generator emits setFPUModeToRoundUP/NEAR. Expansion stages check FE_UNDERFLOW|FE_OVERFLOW and escalate. Build requires strict rounding semantics and explicitly disables accidental FMA contraction with -ffp-contract=off; MSVC uses /fp:strict. These are correctness conditions, not optional performance settings. [Build](https://github.com/MarcoAttene/Indirect_Predicates/blob/74960591e0381f85d94bcee603829451f016b4a2/CMakeLists.txt), [generated fenv handling](https://github.com/MarcoAttene/Indirect_Predicates/blob/74960591e0381f85d94bcee603829451f016b4a2/JPCK_V2/jpck.cpp#L1142-L1174).
- DOCUMENTED / INFERRED caution: UNDEFINED exists in the public enum, but getLambda3D(bigfloat) unconditionally returns true after computing lambdas, and the inspected generated indirect routine does not test d=0 before returning determinant sign. Exact-coordinate accessors do check d=0. A Bend port must explicitly reject undefined constructions rather than assume the enum enforces validity everywhere. Static inspection only, not an executed repro. [API](https://github.com/MarcoAttene/Indirect_Predicates/blob/74960591e0381f85d94bcee603829451f016b4a2/include/implicit_point.h#L265-L277), [accessors](https://github.com/MarcoAttene/Indirect_Predicates/blob/74960591e0381f85d94bcee603829451f016b4a2/include/implicit_point.hpp#L1450-L1525).
- DOCUMENTED: generator's translation-filter bound carries an author comment questioning its derivation, and static filters for all predicates remain TODO. INFERRED: treat the generator as an architectural specimen, not a certified compiler to mechanically retarget by replacing double with float. [Source](https://github.com/MarcoAttene/Indirect_Predicates/blob/74960591e0381f85d94bcee603829451f016b4a2/JPCK_V2/jpck.cpp#L734-L788).

## Parallelism and performance
DOCUMENTED: SIMD options SSE2/AVX2/NEON+SIMDE exist; NFG allocation pools are thread-local. No GPU kernel or measured fork–join benchmark was found in the inspected material. No tests/builds were run here. INFERRED: independent predicates batch well, but recursive construction DAGs and variable-width big integers create uneven work; cache once in an immutable construction table and batch by construction signature/limb budget. [CMake](https://github.com/MarcoAttene/Indirect_Predicates/blob/74960591e0381f85d94bcee603829451f016b4a2/CMakeLists.txt), [NFG](https://github.com/MarcoAttene/NFG/blob/a5ab69965a32c761c2cb29bbba2a63616f2801eb/include/numerics.h).

## Known failures, limitations, war stories
- DOCUMENTED upstream report, merged fix, not locally reproduced: [PR #15](https://github.com/MarcoAttene/Indirect_Predicates/pull/15) repairs cascaded LNC/BPT/TBC interval denominators incorrectly reported reliable. Reported 233,200 wrong orientations in 355,200 answered stress queries and 6 negative-volume tetrahedra in a 10.5M-tet arrangement; zero after fix. Critical lesson: **permutation consistency did not detect the wrong sign**. Current inspected code includes the guard and normalization.
- DOCUMENTED upstream report, merged: [PR #14](https://github.com/MarcoAttene/Indirect_Predicates/pull/14) exact accessors returned homogeneous numerators without dividing by d. Explicit-only tests passed because d=1; nested LPI→LNC midpoint (2,0,0) was returned as (4,0,0). Test cascades, not only direct inputs.
- DOCUMENTED upstream report: [PR #13](https://github.com/MarcoAttene/Indirect_Predicates/pull/13) describes header-only weak-symbol collisions across translation units with different FMA flags. Mathematical correctness can fail at the build/link boundary.
- DOCUMENTED: [issue #11](https://github.com/MarcoAttene/Indirect_Predicates/issues/11) reports reversed equality logic in old limb comparison; [issue #5](https://github.com/MarcoAttene/Indirect_Predicates/issues/5) reports allocation-pointer propagation defects; [issue #6](https://github.com/MarcoAttene/Indirect_Predicates/issues/6) has an author response saying WebAssembly was not tested. Do not interpret that as a verified impossibility.

## Relevance for wonky
INFERRED design proposal, based on the linked formulas and dispatch:
- Plug into tagged-mesh Boolean topology and plane arrangements: explicit vertex, line–plane vertex, three-plane vertex become immutable construction variants with provenance IDs. Do not feed rendered/rounded coordinates back to predicates.
- Reimplement formula DSL → typed expression DAG → magnitude/error/bit-width analysis → Bend. Emit small, checked F32 or F32x2 filters plus a fixed-width U32 exact polynomial fallback. Correct F32x2 filters require newly derived error bounds; ~48 mantissa bits do not expand F32's exponent range.
- Neither fenv directed rounding nor uint64 carry/product temporaries port directly to Metal/Bend. Use explicitly outward-enclosed F32 intervals only after proving the arithmetic/runtime assumptions; otherwise skip that stage. Implement 32x32→64 with U32 halves (e.g. 16-bit partial products) and explicit carry pairs; use software exponent bookkeeping or a bounded common dyadic scale.
- Bound construction depth and input exponent span per supported operation before sizing limbs. On unsupported growth, zero denominator, NaN/Inf, or violated filter preconditions, return structured failure. No “near zero” tolerance substitutes for exact sign.
- Batch filter and exact stages separately using balanced fork–join, grouping unresolved cases by fixed shape to avoid irregular GPU call trees. This changes scheduling, not mathematics. Does not solve nonlinear plane/cylinder SSI, fillets or offsets, but removes a major robustness trap in the hybrid Boolean's polygonal topology oracle.
