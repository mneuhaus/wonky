## What it is

DOCUMENTED: an algorithm for matching faces, edges, and vertices between an original and an edited B-rep **without shared construction history at inference time**, to preserve downstream references when a model is reimported into another CAD system. It learns from history-derived correspondences produced while synthetic edits are generated inside Onshape. It is not a persistent-name generator, a Boolean history recorder, or a certified geometric equality test. [Paper §§1–4](https://arxiv.org/pdf/2306.03169).

DOCUMENTED core insight: unchanged entities supply conservative initial correspondences; already matched neighbors help identify entities whose geometry has changed. An iterative neural scorer uses geometry, topology, and the growing partial correspondence to select the next match. Importantly, the final method is **one-to-one** and can abstain; one-to-many and many-to-one matching are explicitly future work. [Paper §§5,6.3](https://arxiv.org/pdf/2306.03169).

## How it works

### Representation and exact/coincidence bootstrap

DOCUMENTED: B-rep graphs contain vertices, edges, loops, and faces. Loops aggregate boundary geometry and distinguish inner/outer boundaries; the matched primary entities are faces/edges/vertices. Node inputs include analytic/parametric geometry, numerical descriptors such as bounding box, area, center of mass, and topology. [Paper §§3,5.2](https://arxiv.org/pdf/2306.03169).

DOCUMENTED: the bootstrap checks **coincidence of actual entities** with a geometry kernel such as Parasolid. A centroid-nearness candidate filter accelerates this, followed by the real coincidence test. This is not 'identical surface parameters imply identical face': two differently trimmed faces can share one support surface. The paper's use of 'exact' means its conservative geometry-matching baseline, not arbitrary-precision exact arithmetic. [Paper §5.3](https://arxiv.org/pdf/2306.03169).

DOCUMENTED shifted-grid candidate scheme (Fig.7): for tolerance δ in D dimensions, use **D+1 grids**, cell side `(D+1)δ`, shifted relative to one another. Points within δ share a cell in at least one grid, but candidates may be as far as `(D+1)√D δ`, so distance verification remains mandatory. In 1D two grids with cell length `2δ` suffice; merely using two grids in higher dimensions does not. In 3D this means four grids of side `4δ`. The text supplies a geometric coverage argument, not a floating-point robustness proof. [Paper Fig.7 and §5.3](https://arxiv.org/pdf/2306.03169).

DOCUMENTED implementation discrepancy: the inspected C++ release uses **nested all-face/all-edge/all-vertex loops**, not the paper's shifted-grid accelerator in `make_matching`. `COINCIDENCE_TOL=1e-5`, `BOOL_MAX_TOL=1e-5`, and a mass-property control constant `MASS_PROP_TOL=0.999` are `double`; units are not declared beside those constants. Faces use `PK_FACE_is_coincident` (accepting reversed coincidence), edges use coincident support curves plus endpoint and midpoint checks, vertices use `PK_GEOM_is_coincident`. It asserts exactly one body in each input and requires `BTI/ExportId` attributes. Do not cite the theoretical candidate filtering as implemented in this file or assume the explicit tolerance controls every Parasolid call. [cm_lib.cpp](https://github.com/deGravity/brepmatching/blob/ab553a9c13b35de64b4c0387ab469e92cc0d1010/coincidence_matching/src/cm_lib.cpp).

### Iterative learned matching

DOCUMENTED equations and network:

- Maintain partial matching `M_n`; candidates `C` are unmatched same-type entity pairs. Score `pθ(i,j | B_old,B_new,M_n)` and add the highest-scoring pair. Stop when its probability falls below a user-selected threshold. This is greedy, not a globally optimal assignment. [Eq.1, §5](https://arxiv.org/pdf/2306.03169).
- A **6-layer SB-GCN**, 64-dimensional embeddings, first encodes each B-rep. A joint graph combines their topology with cross-graph prior-match edges. Undirected edge types encode vertex-edge, edge-loop, loop-face, face-face, and prior matches. [§5.2, Figs.5–6](https://arxiv.org/pdf/2306.03169).
- A **4-layer graph attention network**, 8 attention heads per layer, 64-dimensional embedding space, conditions embeddings on the partial matching. A 2-layer MLP on pairs produces scores. [§5.2](https://arxiv.org/pdf/2306.03169).
- Weighted binary cross entropy emphasizes incorrect positive matches: `L(y,p)=−[y log p + w(1−y) log(1−p)]`, with `w=2`. At each training epoch the partial prior is a random 50% of ground-truth matches; train 1,000 epochs and select using fixed validation priors. [Eqs.2–4, §5.1](https://arxiv.org/pdf/2306.03169).

DOCUMENTED code pointers: `PairEmbedder.forward` explicitly assembles a typed joint graph and reverses every graph edge to make it undirected. `MatchingModel.forward` builds per-type pair grids, concatenates 64D embeddings into 128D pair features, and computes logits only for enabled candidates. `do_iteration` recomputes scores, selects one maximum per item in a batch, appends its match, and masks **the entire matched row and column**, enforcing one-to-one correspondence. Equal scores take the first maximum; the constructor defaults to threshold 0.75, whereas the paper's main table uses 0.7. [models.py](https://github.com/deGravity/brepmatching/blob/ab553a9c13b35de64b4c0387ab469e92cc0d1010/brepmatching/models.py), [matching_model.py](https://github.com/deGravity/brepmatching/blob/ab553a9c13b35de64b4c0387ab469e92cc0d1010/brepmatching/matching_model.py).

### Deterministic baselines worth understanding, not confusing with the learned method

DOCUMENTED: after coincidence matching, a second baseline accepts edge/face pairs with identical supports and overlap ≥80% of the **smaller** entity. This is a heuristic correspondence, not equality or proven design intent. The C++ implementation computes intersection measure from `measure(A)+measure(B)−measure(union)` using Parasolid Boolean operations on sheet/wire copies. [Paper p.8](https://arxiv.org/pdf/2306.03169), [cm_lib.cpp](https://github.com/deGravity/brepmatching/blob/ab553a9c13b35de64b4c0387ab469e92cc0d1010/coincidence_matching/src/cm_lib.cpp).

DOCUMENTED adjacency-propagation baseline: assign indices to current matches; traverse neighbors in boundary order; record matched indices and `−1` for unmatched neighbors; canonicalize loop starting points lexicographically and aggregate loop signatures in lexicographic order. Prioritize signatures with a larger matched/unmatched ratio, accept a unique matching signature or use extra geometric disambiguation (support type/coaxial cylinders), update affected neighborhoods, repeat to convergence. The paper says this deterministic baseline was in Onshape's reimport workflow, not that the neural paper algorithm was deployed there. [Paper p.9](https://arxiv.org/pdf/2306.03169).

DOCUMENTED related patent makes additional implementation detail explicit: distinguish unmatched, loop separator, and no-face sentinels (`−1`, `−2`, `−3` in the described embodiment); preserve cyclic traversal order and choose the lexicographically greatest rotation; sort loop arrays; maintain a signature hash table plus a priority queue. These details occur in a **patented reference**, not an invitation to assume legal clearance. [US11288411B2 description and claims](https://patents.google.com/patent/US11288411B2/en).

## Robustness and guarantees

DOCUMENTED: the learned scorer has no correctness guarantee for CAD references. Precision is deliberately prioritized over recall because a missing reference raises a visible error whereas a wrong match may silently drive the wrong downstream feature. A stopping probability is not a geometric error tolerance, and the paper does not establish probability calibration or a universal safe threshold. [Paper §§5.1,6](https://arxiv.org/pdf/2306.03169).

DOCUMENTED: the reference labels are themselves heuristic. The authors explicitly note that Onshape tracking can disagree with user intent; if tracking produced one-to-many correspondence, a random one-to-one match was selected for their ground truth. Therefore their measured accuracy does not certify the full split/merge relation. [Paper §6.3](https://arxiv.org/pdf/2306.03169).

INFERRED for wonky: support equality, centroid equality, and adjacency equality each provide evidence, not unique persistent identity. Repeated holes/gear teeth, symmetric shapes, changed trims, periodic curve parametrizations, and seam topology require disambiguation or an explicit unresolved result. Bootstrap on complete trimmed geometry plus topology, not just exact surface coefficients. Even exact arithmetic does not solve semantic ambiguity. [Counterexamples and limitations](https://arxiv.org/pdf/2306.03169).

## Parallelism and performance

DOCUMENTED measurements, not reproduced:

- Training took **12 hours on average on one NVIDIA RTX 2080 Ti**. The paper does not provide a comparably concrete per-model inference latency table in the inspected 13 pages. Training time is not evidence that inference or a Bend implementation is fast. [Paper §6](https://arxiv.org/pdf/2306.03169).
- Evaluation dataset: 2,400 source CAD models initially, 3 variations each; after filtering import failures and extreme scale outliers, **2,266 originals / 6,257 variations**, split by original model 80/10/10%. The general generator described elsewhere creates 4–18 variations; do not conflate that generator capability with this stated evaluation collection. [Paper §§4,6.1](https://arxiv.org/pdf/2306.03169).
- At threshold 0.7, **correct-label** percentages for faces/edges/vertices are **91.5 / 92.1 / 94.9%**, including true negatives. Incorrect-label fractions are **2.8 / 1.9 / 1.1%**; missed matches are **5.6 / 6.0 / 4.0%**. The correct-label figure is **not matching recall or precision**. Exact baseline true positives are only 11.0 / 14.0 / 17.1% of all updated entities in Table 1. [Table 1](https://arxiv.org/pdf/2306.03169).
- The initial expert collection has 25 models (5 reimports, 20 revision pairs); evaluation retained 16 manageable cases for manual annotation. Correct-label percentages: **89.5 / 87.1 / 88.8%**; incorrect: **2.3 / 1.7 / 1.4%**; missed: **8.2 / 11.1 / 9.9%**. Small, filtered expert sample, not a broad production guarantee. [§6.2, Table 2](https://arxiv.org/pdf/2306.03169).

INFERRED complexity/parallelism: the inspected code's pair tensors and C++ nested loops can require quadratic work in each entity class; greedy recomputation adds a sequential chain proportional to accepted matches. Pair scoring, graph-edge aggregation, centroid candidates, and max reduction can use fork-join; the next-match dependence remains sequential. Dense padded neural batches are GPU-friendly, irregular graph degrees and growing match lists are not automatically uniform. No Rust/C++/Python/PyTorch library can be embedded under wonky's no-FFI rule. [Code evidence](https://github.com/deGravity/brepmatching/blob/ab553a9c13b35de64b4c0387ab469e92cc0d1010/brepmatching/matching_model.py).

## Known failures, limitations, war stories

- DOCUMENTED: large geometric changes yield misses; topology changes can confuse neighboring entities; radically replacing an `I` profile by a `B` can produce spurious matches along the letter outlines. Repeated gear teeth confuse deterministic adjacency matching, and fillets create one-to-many edge situations it handles poorly. [Paper Figs.10,13](https://arxiv.org/pdf/2306.03169).
- DOCUMENTED: published evaluation is single-body; 8 of 25 expert models were originally multibody, handled by selecting or unioning bodies. Body matching and full many-to-many relations are future work. [Paper §§6.3,7](https://arxiv.org/pdf/2306.03169).
- DOCUMENTED: issue #5 reports dependence on Onshape export attributes, with no response present at inspection; code verifies it reads `BTI/ExportId` and asserts named entities. Arbitrary unlabeled STEP/Parasolid input is not automatically a drop-in supported workflow. [Issue #5](https://github.com/deGravity/brepmatching/issues/5), [read_attributes](https://github.com/deGravity/brepmatching/blob/ab553a9c13b35de64b4c0387ab469e92cc0d1010/coincidence_matching/src/cm_lib.cpp).
- DOCUMENTED: license/dependency clarification required direct author discussion; a user published a fork after reimplementing the Parasolid frustrum layer. This establishes integration friction, not proof that every dependency is permissively licensed. [Issue #6](https://github.com/deGravity/brepmatching/issues/6).
- DOCUMENTED IP caution: related PTC patent **US11288411B2**, inventors Ilya Baran and Adriana Schulz, priority 2019-01-04, grant 2022-03-29. Google Patents displays active status and an adjusted expiration date but expressly disclaims legal-status accuracy. ## Relevance for wonky

INFERRED best use: a **history-free diff/reimport assistant**, not the source of truth for native Boolean lineage. Native operations know which faces were split/merged; preserving that history is safer and cheaper than relearning it afterward. For foreign revisions, maintain `proven by shared history`, `verified geometric coincidence`, `heuristic suggestion`, and `ambiguous/unmatched` as different evidence classes. Learned or adjacency-only guesses should not silently retarget production fillets, mates, or dimensions. [Motivation and failure trade-off](https://arxiv.org/pdf/2306.03169).

INFERRED Bend prototype, with separate patent review: represent the incidence graph in flat U32-indexed immutable arrays; normalize analytic supports while handling orientation/axis sign; bucket candidate centroids with tolerance-aware indices; verify actual trimmed coincidence in Bend; propagate only uniquely justified constraints in deterministic rounds; retain competing candidates for UI review. Replacing the neural scorer with deterministic propagation is a **new, weaker method**, not a reproduction of the paper's accuracy, and the paper directly demonstrates failures of that baseline. [Paper §§5.3,6.1](https://arxiv.org/pdf/2306.03169).

INFERRED precision boundary: neural inference could use F32, but the supplied coincidence/overlap machinery is f64 Parasolid and must be independently replaced. F32x2 can support toleranced centroid and analytic-support checks at qualified scales; multi-limb U32 predicates can settle exact algebraic comparisons where represented. Neither recreates Parasolid's trimming, integration, or Boolean functionality for free. Grid floor/bucket computations near boundaries need checked error margins or exact scaled integer arithmetic to preserve candidate coverage. Sentinel values should be tagged U32 values, not accidental signed casts. [Numeric/code basis](https://github.com/deGravity/brepmatching/blob/ab553a9c13b35de64b4c0387ab469e92cc0d1010/coincidence_matching/src/cm_lib.cpp), [grid bound](https://arxiv.org/pdf/2306.03169).

INFERRED testing value: use constructed edit pairs with known history as ground truth, **retaining the full many-to-many relation** instead of collapsing it randomly. Include symmetry, repeated holes, split/merge, large translations, edge direction reversal, seam relocation, changed analytic parameterization, and entirely replaced details. Measure silent wrong retargets separately from misses; overall correct-label rate is misleading when most entities legitimately have no match. FDM watertightness and dimensional accuracy remain separate acceptance gates. [Dataset and evaluation lessons](https://arxiv.org/pdf/2306.03169).

## Verdict: learn-from

Strong evidence for conservative bootstrap + neighborhood reasoning and for **explicit abstention** in history-free model diffing. Do not directly adopt the released stack: it depends on Parasolid/PyTorch, lacks complete split/merge semantics, has nonzero silent mismatch rates, and raises separate license/patent questions. Adopt its evaluation discipline and study its candidate/index ideas; native wonky identity should first use operation-emitted exact provenance.
