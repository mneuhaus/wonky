## What it is

DOCUMENTED: 81 mechanical-part tasks, 49 engineering-drawing generation and 32 STEP edits. Public inputs include raster drawings, descriptions, editing input STEPs, trusted input mesh sidecars and renders; solved parts/interface sub-volumes are private. Output is one `output.step`/`output.stp` per fixture. There is no official train/test split in the dataset. A submission row is initially unvalidated; methodology review is a separate status from geometric validity. [Dataset card](https://huggingface.co/datasets/HuggingAI4Engineering/cadgenbench-data/blob/f76f965585817c621d6ea0d150d745adf670e66e/README.md), [submission contract](https://github.com/huggingface/cadgenbench/blob/33304cf771fc5639144b1df9611e347251052cf8/docs/benchmark/submission.md), [methodology validation](https://github.com/huggingface/cadgenbench/blob/33304cf771fc5639144b1df9611e347251052cf8/docs/benchmark/validation.md).

## How it works

### Validity, alignment and shape

DOCUMENTED: reject a raw candidate before scoring if OCCT BRepCheck fails, shells are not closed, or tessellation is not a closed consistently wound edge- and vertex-manifold mesh. Meshing uses a deflection ladder and bounded subprocess; defaults include 50,000,000-byte STEP ceiling, 1,000,000 triangles and 180 s mesh timeout. Sliver area <0.001 mm², aspect ratio >1000 and B-rep tolerance >0.1 mm are advisory, not score gates. [validity.py](https://github.com/huggingface/cadgenbench/blob/33304cf771fc5639144b1df9611e347251052cf8/src/cadgenbench/common/validity.py), [mesh validation](https://github.com/huggingface/cadgenbench/blob/33304cf771fc5639144b1df9611e347251052cf8/src/cadgenbench/common/mesh.py#L539-L671), [validity doc](https://github.com/huggingface/cadgenbench/blob/33304cf771fc5639144b1df9611e347251052cf8/docs/metrics/cad_validity.md).

DOCUMENTED: align using identity + 24 octahedral PCA orientation candidates, multiscale point-to-plane ICP and deterministic shape-based tie-breaking, rotation/translation only, never scale. Base tessellation error `δ=clamp(0.001*GT_diagonal,0.005,0.5) mm`, shared across both shapes. `MetricContext` lazily caches meshes, Manifold objects and 50,000 area-weighted samples with normals, seed 0. Surface hit: closest point on the *other triangle surface*, distance ≤`max(1e-6,0.005*GT_diagonal)` and **absolute** normal dot >cos(20°). Then `P=hits_candidate/N`, `R=hits_GT/N`, `F1=2PR/(P+R)`. Shape score is mean of F1 and mesh-volume IoU `I/(VA+VB-I)`. Code uses abs(dot), contrary to older prose implying signed outward-normal agreement. [alignment](https://github.com/huggingface/cadgenbench/blob/33304cf771fc5639144b1df9611e347251052cf8/src/cadgenbench/eval/alignment.py), [shape code](https://github.com/huggingface/cadgenbench/blob/33304cf771fc5639144b1df9611e347251052cf8/src/cadgenbench/eval/shape_similarity.py#L524-L634), [mesh policy](https://github.com/huggingface/cadgenbench/blob/33304cf771fc5639144b1df9611e347251052cf8/src/cadgenbench/common/mesh.py#L100-L125).

### Interface score, including a consequential implementation caveat

DOCUMENTED: author files `jig_<context>__<index>__KOR.step` / `...__KIR.step` define required void/material. Given region R, inflate its AABB by `max(2 mm,0.2*longest_region_side)`. For a keep-out, verification shell is inflated-box∩GT; for keep-in it is inflated-box−GT. Fixed comparison domain B=R∪shell. Candidate region C is B−candidate for KOR, B∩candidate for KIR. Compare posed R to C using IoU. This penalizes both over- and undersized features, unlike checking only that a pin fits inside an oversized hole. [cache/domain construction](https://github.com/huggingface/cadgenbench/blob/33304cf771fc5639144b1df9611e347251052cf8/src/cadgenbench/eval/interface_match.py#L298-L437).

DOCUMENTED: default search is 32 deterministic poses (zero first, then unscrambled six-dimensional Sobol), ±1% GT diagonal translation per axis, ±1° XYZ rotations about world origin. IoU ≥0.99 saturates to 1; scoring ramp `clamp((IoU-0.80)/0.15,0,1)`. Minimum feature score within a context; mean across contexts. **Code caveat, INFERRED consequence of directly read loops:** `best_iou_in_context()` maximizes each feature independently across sampled poses before taking the minimum. It computes `min_i max_p fit(i,p)`, not the physically necessary common-pose `max_p min_i fit(i,p)`. Two features requiring incompatible compensating translations can both score well even though no rigid jig fits both at once. The code visits common poses but discards the winning-pose association per feature. Do not port this aggregation as proof of simultaneous assembly fit. [search loops](https://github.com/huggingface/cadgenbench/blob/33304cf771fc5639144b1df9611e347251052cf8/src/cadgenbench/eval/interface_match.py#L492-L617), [aggregation](https://github.com/huggingface/cadgenbench/blob/33304cf771fc5639144b1df9611e347251052cf8/src/cadgenbench/eval/interface_match.py#L668-L735).

### Topology and score composition

DOCUMENTED: despite README shorthand about boundary Betti numbers, implementation derives **solid** Betti counts from the validated boundary. Deduplicate unordered mesh edges, χ=V−E+F; union-find obtains boundary components; inward-nudged triangle-centroid probes and even/odd ray containment classify even-depth shells as solid components b0 and odd-depth shells as cavities b2; `b1=b0+b2−χ/2`. Per-axis score `((min(bc,bg)+1)/(max(bc,bg)+1))²`; multiply the three. Blind pockets/fillets do not change Betti. [topo_match.py](https://github.com/huggingface/cadgenbench/blob/33304cf771fc5639144b1df9611e347251052cf8/src/cadgenbench/eval/topo_match.py).

DOCUMENTED: invalid →0. Generation weights shape/interface/topology =0.4/0.4/0.2; absent or uncomputed axes are omitted and remaining weights renormalized. Editing uses `s'=max(0,(s−b)/(1−b))`, where b is input-vs-GT shape score stored in `edit_baseline.json`; weights 0.6/0.3/0.1. Baseline version mismatch hard-errors; authoring headroom floor is 0.002. A no-op may still score up to 0.4 when all axes exist. The benchmark therefore measures improvement but does not demand every requested edit as a binary requirement. [composition](https://github.com/huggingface/cadgenbench/blob/33304cf771fc5639144b1df9611e347251052cf8/src/cadgenbench/eval/evaluate.py#L368-L418), [edit baseline](https://github.com/huggingface/cadgenbench/blob/33304cf771fc5639144b1df9611e347251052cf8/src/cadgenbench/eval/edit_baseline.py).

DOCUMENTED: reference agent executes build123d/CadQuery code, injects numeric validity/watertight/solid count/face count/volume/bbox/errors and an iso render after execution. It reuses the validity mesh for rendering, rather than remeshing. It is not purely visual self-review. [baseline feedback](https://github.com/huggingface/cadgenbench/blob/33304cf771fc5639144b1df9611e347251052cf8/src/cadgenbench/baseline/agent.py#L383-L487).

## Robustness and guarantees

DOCUMENTED: closest-point-to-surface removes nearest-sample cloud artifacts, but F1 remains sampled, thresholds are scale-relative, and volume is computed after tessellation. Interface constraints are authored only for selected features. INFERRED: none is an engineering tolerance certificate or injective shape identity; equal Betti does not imply geometric/functional equivalence. Numeric gate success also is not a proof against all geometric self-intersections. [metric definitions](https://github.com/huggingface/cadgenbench/blob/33304cf771fc5639144b1df9611e347251052cf8/docs/metrics.md), [mesh checks](https://github.com/huggingface/cadgenbench/blob/33304cf771fc5639144b1df9611e347251052cf8/src/cadgenbench/common/mesh.py#L539-L671).

DOCUMENTED: containment uses step `max(1e-6,1e-4*component_diagonal)`, determinant epsilon 1e-12, grazing epsilon 1e-9 and up to eight deterministic ray directions. If all graze it returns false; no interval/exact predicate proof. Euler keys use `int64` packed vertex pairs, component union-find mutates arrays. [topology implementation](https://github.com/huggingface/cadgenbench/blob/33304cf771fc5639144b1df9611e347251052cf8/src/cadgenbench/eval/topo_match.py#L263-L434).

DOCUMENTED: `StepArtifacts` treats an existing `<stem>.mesh.npz` sidecar as trusted and bypasses ordinary verification/remeshing. INFERRED: external evaluators must strictly separate trusted dataset sidecars from untrusted submission content; this reading did not audit the Space's upload filtering, so this is a trust-boundary warning, not a demonstrated submission exploit. [artifacts.py](https://github.com/huggingface/cadgenbench/blob/33304cf771fc5639144b1df9611e347251052cf8/src/cadgenbench/common/artifacts.py).

## Parallelism and performance

DOCUMENTED: independent fixtures/processes, cached artifact meshes, thread-parallel pose×region jobs with default workers=1 to avoid nested oversubscription; default 32 poses and 50k points determine concrete work sizes. booleans.py claims sub-millisecond Boolean operations without a reproducible benchmark table, so no speed claim is adopted here. NumPy/OCP normally use f64 geometry, but `mesh_to_manifold` explicitly casts coordinates to float32 and indices to uint32. No tests, builds or performance runs performed. [interface threading](https://github.com/huggingface/cadgenbench/blob/33304cf771fc5639144b1df9611e347251052cf8/src/cadgenbench/eval/interface_match.py#L583-L616), [Boolean conversion](https://github.com/huggingface/cadgenbench/blob/33304cf771fc5639144b1df9611e347251052cf8/src/cadgenbench/eval/booleans.py#L44-L71), [dependencies](https://github.com/huggingface/cadgenbench/blob/33304cf771fc5639144b1df9611e347251052cf8/pyproject.toml).

## Relevance for wonky

INFERRED from the linked STEP submission/evaluation contract: use as an **external oracle/benchmark**, never a production backend. Wonky exports STEP already; candidates can be sanity-checked externally without violating Bend-only production geometry. Full official scoring is not offline-reproducible from public inputs alone because GT and interface jigs are private; use the Space or authored local GT fixtures. Editing additionally needs STEP import/retained input representation, which the task context does not establish as available in wonky merely because export exists.

INFERRED: port concepts selectively: three independent score axes, requested material/void regions, no-op-relative edit evaluation, explicit invalid/missing status and reuse of a validated certified mesh for both analysis and render. For real FDM fits replace scale-relative soft windows with requested mm tolerances and use one common mating pose per group. Keep a kernel-only structured-spec suite separate from image perception and LLM generation tests. [metric contract](https://github.com/huggingface/cadgenbench/blob/33304cf771fc5639144b1df9611e347251052cf8/docs/metrics.md).

INFERRED Bend implementation: U32 pairs rather than packed int64 edges; sort/merge plus immutable connected-component passes instead of mutable union-find; F32x2 compensated volume sums; multi-limb exact orientation/ray predicates or explicit uncertainty instead of epsilon/retry=false; balanced fork-join for fixed pose/sample maps and face/edge reductions. Pose/sample work is GPU-friendly if padded/bucketed, while ICP, BVHs and general Booleans remain irregular. The external evaluator's float32 Manifold adapter does not establish end-to-end F32 robustness. It contributes no curved SSI/fillet algorithm. [topology and numeric evidence](https://github.com/huggingface/cadgenbench/blob/33304cf771fc5639144b1df9611e347251052cf8/src/cadgenbench/eval/topo_match.py), [mesh Boolean boundary](https://github.com/huggingface/cadgenbench/blob/33304cf771fc5639144b1df9611e347251052cf8/src/cadgenbench/eval/booleans.py).
