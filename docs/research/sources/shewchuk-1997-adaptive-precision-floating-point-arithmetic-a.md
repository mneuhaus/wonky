## What it is
DOCUMENTED: exact-sign orient2d, orient3d, incircle and insphere predicates for the supplied floating-point coordinates, using expansions and adaptive computation. This is not an exact construction library and does not make previously rounded intersection coordinates exact. Functions ending in “fast” are deliberately non-robust. Other “exact” and “slow” variants are mostly comparison baselines. [Code header](https://www.cs.cmu.edu/afs/cs/project/quake/public/code/predicates.c), [paper §§1, 4](https://people.eecs.berkeley.edu/~jrs/papers/robustr.pdf).

## How it works
DOCUMENTED [paper §§2–4](https://people.eecs.berkeley.edu/~jrs/papers/robustr.pdf), [C macros and functions](https://www.cs.cmu.edu/afs/cs/project/quake/public/code/predicates.c):
1. An expansion is an array plus length, ordered from least to greatest magnitude. Components have nonoverlapping significant bits; fast merge needs the stronger nonoverlap invariant. The sign of the most significant nonzero component is the exact sum's sign. An expansion is not merely “two floats giving 48 bits.” Its length grows to preserve every term.
2. Error-free primitives: TwoSum(a,b) returns (hi,lo) with hi+lo=a+b; FastTwoSum uses three operations but requires |a|≥|b|. TwoDiff also supplies the exact subtraction tail. Split multiplies by 2^ceil(p/2)+1 and separates significands; TwoProduct uses split operands to recover the multiplication residual without FMA. Preserve EACH indicated rounding operation, not just algebraic equivalence.
3. GrowExpansion inserts a scalar; FastExpansionSum merges magnitude-ordered streams in O(m+n), using TwoSum and zero elimination; ScaleExpansion multiplies by one scalar in O(n). These routines have carry-like serial dependency chains. Compress reduces unnecessary components; Estimate sums an expansion approximately. Arrays can be statically capacity-bounded for a fixed predicate, but actual lengths and zero elimination are data dependent.
4. orient2d translates to c: D=(ax-cx)(by-cy)−(ay-cy)(bx-cx). orient3d uses the 3×3 determinant of differences to d. Incircle has polynomial degree 4; insphere has degree 5. Translation typically tightens the filter because the error depends on local coordinate differences, not world-space magnitude. Translation must still retain subtraction tails in the exact stage.
5. Four orient2d stages: A computes an ordinary determinant and bound; B computes the determinant of the rounded differences exactly as a four-component expansion; recover all four difference tails, returning immediately if all vanish; C adds first-order tail corrections to Estimate(B); D incorporates every tail product into at most 16 components (B[4], C1[8], C2[12], D[16] in orient2dadapt). Orient3d's final adaptive expansion is bounded by 192 components. Insphere's final stage recomputes from scratch rather than recycling all earlier work.
6. exactinit determines u and splitter, then constructs symbolic-in-u constants. For orient2d: A=(3+16u)u; B=(2+12u)u; C=(9+64u)u²; result=(3+8u)u. Stage A compares against A·detsum; stage C compares against C·detsum + result·|previous det|. Orient3d A=(7+56u)u; incircle A=(10+96u)u; insphere A=(16+224u)u. “Permanent”-like sums of absolute monomials supply each scale; it is NOT a fixed world-space epsilon.

**INFERRED F32 instantiation:** p=24 gives u=2^-24 and splitter=4097. The paper's formulas are parameterized by precision and the C explicitly supports float or double; the coefficients 3,16,7,56 etc. do not all need new derivations merely because p changes. Instantiate/revalidate their finite-precision evaluation at F32, and separately prove the exponent/underflow guards. Importing already-evaluated binary64 constants is wrong. [Paper Table 1 and §2.5; exactinit](https://www.cs.cmu.edu/afs/cs/project/quake/public/code/predicates.c).

## Robustness and guarantees
- DOCUMENTED: proofs assume binary, correctly rounded arithmetic; FastExpansionSum assumes ties-to-even. Paper §2.1 explicitly excludes overflow/underflow and treats exponents as unbounded. Its sufficient input-exponent range [−142,201] is for all four predicates in IEEE binary64, NOT an F32 guarantee. [Paper pp.3–4](https://people.eecs.berkeley.edu/~jrs/papers/robustr.pdf).
- DOCUMENTED: compiler reassociation and wider internal registers/double rounding invalidate error-free-transform reasoning. “Volatile” is not a complete cure for double rounding. [Paper §5](https://people.eecs.berkeley.edu/~jrs/papers/robustr.pdf).
- INFERRED: explicit Bend operations need strict F32 rounding in JS, C and Metal paths. No reassociation or implicit FMA contraction is admissible without a new proof. A safe high input range must also account for splitter*a overflowing before a*b would. FTZ breaks residual preservation even with finite, normal-looking final output.
- DOCUMENTED/INFERRED: the return magnitude is not generally an exact determinant, only its sign is guaranteed; exact zero is meaningful. Preserve three outcomes −/0/+ and distinguish inconclusive filter from zero. Do not use the return value as volume or distance. Exact signs do not settle degeneracies automatically; Boolean topology still needs explicit coincident/coplanar handling. [Paper §§4.1–4.3](https://people.eecs.berkeley.edu/~jrs/papers/robustr.pdf).

## Parallelism and performance
DOCUMENTED: DEC 3000/700, 225 MHz Alpha, Table 2: orient2d uniform random approximate 0.15 µs, adaptive A 0.28 µs, nonadaptive translated exact 8.35 µs; near-collinear adaptive B 1.89 µs, C 2.14 µs, D 8.35 µs. Table 8: one-million-point uniform 2D triangulation 57.3 s approximate vs 61.7 s robust. Table 9: 3D tilted-grid approximate code failed to terminate; robust run 108.5 s. These are historical CPU measurements, not modern/Bend/GPU predictions. [Paper Tables 2,8,9](https://people.eecs.berkeley.edu/~jrs/papers/robustr.pdf).

INFERRED: parallelize independent predicates/independent minors with balanced fork-join; do not expect parallel speedup from the serial merge accumulator. The highly adaptive stages are nonuniform GPU work. Prefer a uniform F32 filter pass, partition unresolved jobs, then fixed-shape exact integer kernels grouped by predicate. Affine arrays can express pure expansion operations but will need explicit capacities and ownership, not C in-place aliases.

## Known failures, limitations, war stories
DOCUMENTED: the tilted-grid infinite loop above is a real roundoff-induced topology inconsistency. Paper §4.1 explicitly explains why exact predicates over inexact constructions still need care, including irrational constructions. §5 provides hardware/compiler pitfalls, not a claim of universal portability. [Paper](https://people.eecs.berkeley.edu/~jrs/papers/robustr.pdf). No canonical issue tracker was found for this standalone release. Later [Bartels et al. §2.3](https://arxiv.org/pdf/2208.00497) provides an explicit underflow counterexample to a naive Shewchuk-style filter outside its assumptions.

## Relevance for wonky
INFERRED from [the arithmetic assumptions and code](https://www.cs.cmu.edu/afs/cs/project/quake/public/code/predicates.c):
- Adopt the filter/exact-sign architecture for triangulation, plane-side tests, mesh Boolean topology and planar arrangements. Keep construction provenance so intersection points are not rounded before predicates (see Attene).
- Use F32/F32x2 only as certified fast stages. For the production exact fallback, prefer fixed-width U32 limbs over F32 expansions unless a restricted exponent contract is enforced and proven across every backend. Decode original dyadic input values without a lossy float conversion; an F32x2 input means the exact SUM of two dyadics, not just the high word.
- Preserve expression trees, orientation convention and per-stage error metadata in a generated predicate module. Expose stage and fallback counters to wonky's introspection. This is a numerical sign certificate, not an FDM modeling tolerance.
- Needed future tests (not run): exact-zero and near-zero determinants; every argument permutation; wide exponent spans; overflow in splitting; subnormal residuals/FTZ; strict comparison with a multi-limb oracle across JS/C/Metal. Recover analytic B-rep geometry separately; this paper supplies neither SSI nor fillets.

## Verdict: adapt
Port the proven error-free transforms and staged sign-certification design, not an unconditional “float replacement” of the C library. F32 exponent range and backend arithmetic semantics are the missing contract; U32 exact fallback is the safer common denominator. No production files changed. The outstanding work is an executable F32/FTZ contract, bounded integer fallback and cross-backend validation.
