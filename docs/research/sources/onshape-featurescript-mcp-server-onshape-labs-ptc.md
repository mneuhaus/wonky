## What it is

DOCUMENTED: **text → reusable FeatureScript → CAD**, not merely prompting for a static mesh. User describes functionality, an AI client helps build/test/debug/refine the custom feature, and resulting code runs as a normal Onshape custom feature and can be shared. Examples include standardized hydraulic ports, parameterized systems/design rules, calculations/validation utilities and consolidation of repeated modeling steps. Introduction distinguishes the MCP server from Co-Complete, which supplies inline Feature Studio completions. [Introduction](https://www.onshape.com/en/blog/featurescript-mcp-server-enables-text-code-cad), [PTC release](https://www.ptc.com/en/news/2026/onshape-launches-featurescript-mcp-server).

DOCUMENTED: setup requires an active signed-in Onshape account, subscribing to Onshape Labs FeatureScript MCP in the App Store and configuring the HTTP endpoint in an AI client. “No recurring AI costs” refers to **reusing the generated feature without invoking the model**, not a promise that Onshape subscriptions, initial inference or all service usage are free. [Introduction](https://www.onshape.com/en/blog/featurescript-mcp-server-enables-text-code-cad), [PTC release](https://www.ptc.com/en/news/2026/onshape-launches-featurescript-mcp-server).

## How it works

DOCUMENTED at product level: natural-language functionality request → generated FeatureScript → testing/debugging/refinement → reusable custom feature. Public announcements do **not** expose a tools/list schema, exact MCP method names, edit transactions, error payloads, geometry inspection schema, model budgets, rollback behavior or automatic success criteria. Therefore “insert into a Part Studio, run, evaluate, fix” is a plausible conceptual workflow, not a verified sequence of public tool calls. Nothing in this reading establishes whether render, numeric measurement or human review supplies the feedback. [PTC release](https://www.ptc.com/en/news/2026/onshape-launches-featurescript-mcp-server), [use-case article](https://www.onshape.com/en/blog/featurescript-mcp-server-use-cases-text-code-cad).

The **public FeatureScript language and standard library**, rather than undocumented MCP internals, provide concrete implementable contracts relevant to wonky:

- DOCUMENTED: `qCreatedBy(featureId, entityType)` returns newly created entities, not merely modified ones. A split child is attributed to both original creator and split operation; a merged entity to all merged creators plus merge operation. This is a provenance-set semantics, not a single parent ID. [qCreatedBy](https://cad.onshape.com/FsDoc/library.html#qCreatedBy-Id-EntityType).
- DOCUMENTED: `qNthElement(query,n)` uses a deterministic but arbitrary query order, supports zero-based positions and negative indexing. INFERRED: matching syntax alone must not be mistaken for stable semantic face naming after edits; prefer predicates/provenance over positional picks. [qNthElement](https://cad.onshape.com/FsDoc/library.html#qNthElement-Query-number).
- DOCUMENTED: `evDistance(context,{side0,side1,...})` accepts queries/points/lines/planes and returns distance plus side parameters/index information; arbitrary tie breaking for equal minima/maxima, optional extension to unbounded underlying edge/face geometry, default arc-length edge parameterization. Infinite/extended geometry restricts maximum-distance mode. [evDistance](https://cad.onshape.com/FsDoc/library.html#evDistance-Context-map).
- DOCUMENTED: `evArea` sums matched faces and returns zero if none; `evVolume` sums matched 3D bodies and returns zero if none. `evAxis` requires a single axis-bearing entity, otherwise throws. `evBox3d` has tight(default)/fast-conservative options; `evCollision` returns structured clashes with tool/target/body queries. INFERRED: wonky should preserve FS-compatible semantics while exposing query cardinality in diagnostics so empty selection is not misread as physically zero area/volume. [evArea](https://cad.onshape.com/FsDoc/library.html#evArea-Context-map), [evVolume](https://cad.onshape.com/FsDoc/library.html#evVolume-Context-map), [evAxis](https://cad.onshape.com/FsDoc/library.html#evAxis-Context-map), [evBox3d](https://cad.onshape.com/FsDoc/library.html#evBox3d-Context-map), [evCollision](https://cad.onshape.com/FsDoc/library.html#evCollision-Context-map).
- DOCUMENTED: FS `number` is IEEE 64-bit double, supports infinity, and does not expose NaN: operations that would produce NaN throw immediately. Values behave as copied on assignment except explicit `box` sharing. This is value semantics, **not** a prohibition on variable reassignment. [Language variables/values](https://cad.onshape.com/FsDoc/variables.html).

Use-case examples of standards compliance and analysis are not proof that the MCP server independently certifies engineering correctness. INFERRED: FeatureScript's documented units, query contracts, explicit error semantics and feature attribution are an excellent conformance target, but they do not prove a replacement kernel will reproduce numerical behavior. ## Relevance for wonky

INFERRED: this is the closest commercial **frontend workflow** peer: capture a reusable feature/program, not only an output solid. Prioritize compatibility for `qCreatedBy`, query filters, `evDistance`, `evArea`, `evVolume`, `evBox3d`, `evCollision` and source-located errors, plus deterministic program replay and versioned reusable features. Familiar APIs plausibly reduce the model's need to learn an unfamiliar CAD DSL, but neither training-corpus coverage nor an automatic quality gain is established by these sources. [FS contracts](https://cad.onshape.com/FsDoc/library.html), [product positioning](https://www.onshape.com/en/blog/featurescript-mcp-server-enables-text-code-cad).

INFERRED Bend fit: provenance sets/query filtering and immutable model states fit affine arrays and balanced fork-join; geometric evaluations can batch independent entities. Dynamic interpreter flow and irregular geometry queries need CPU scheduling or carefully uniform GPU batches. F32x2 (~48 mantissa bits and F32 exponent range) **does not equal** FS's 53-bit significand and double exponent range. Define a supported numeric domain and explicit range/precision failure rather than claiming full numeric compatibility; use multi-limb U32 predicates for topology. Mirror NaN-as-error and dimensional values, but implement all production geometry in Bend. No commercial service/Parasolid linkage is an acceptable shortcut, and these pages supply no SSI/Boolean/fillet algorithm to port. [numeric mismatch source](https://cad.onshape.com/FsDoc/variables.html), [query source](https://cad.onshape.com/FsDoc/library.html#qCreatedBy-Id-EntityType).

## Verdict: learn-from

Study the reusable FeatureScript feature workflow and adopt the public FS query/evaluation contracts as compatibility tests. Do not claim to have reverse-engineered the MCP protocol internals.
