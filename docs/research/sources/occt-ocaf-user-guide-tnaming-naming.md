## What it is

DOCUMENTED: OCAF separates operation history, its registration in a document, and selection recomputation. A persistent reference is not merely a shape ID: `TNaming_NamedShape` records evolution, while `TNaming_Naming` stores a recipe for reconstructing a selection. The recipe is solved against updated history after regeneration. See [guide §§5.1–5.8](https://occt3d.com/dev/doc/overview/html/occt_user_guides__ocaf.html#occt_ocaf_5).

## How it works

1. DOCUMENTED: the document root owns `TNaming_UsedShapes`, a map of used topology. Other labels hold NamedShape hooks to `(oldShape,newShape)` pairs and one evolution tag per attribute. PRIMITIVE has no old shape; GENERATED links a generating shape to new topology, e.g. edge → extrusion face; MODIFY links old topology to its successor; DELETE has no new shape; SELECTED does not affect evolution. Multiple pairs with the same tag are permitted, and the value can be a compound of new shapes. `GetShape` reads the stored new shapes; `CurrentShape` follows evolution to latest versions. These are different queries. [Guide §§5.1–5.5](https://occt3d.com/dev/doc/overview/html/occt_user_guides__ocaf.html#occt_ocaf_5_1).
2. DOCUMENTED: history coverage is an operation contract. Solid/closed-shell results require all faces; open shells also require open-boundary edges; closed wires require edges; open wires add endpoint vertices. Compound results recurse. Seam edges on periodic surfaces need explicit tracking, and degenerated entities are excluded. Histories are registered on children beneath an operation's result label. This is application work, not automatically inferred from arbitrary final geometry. [Guide §5.6.1–2](https://occt3d.com/dev/doc/overview/html/occt_user_guides__ocaf.html#occt_ocaf_5_6_1).
3. DOCUMENTED: `TNaming_Name` stores `type`, expected `shapeType`, argument NamedShapes, optional stop NamedShape, integer index, original shape, context label, and orientation. Types include IDENTITY, MODIFUNTIL, GENERATION, INTERSECTION, UNION, CONSTSHAPE, FILTERBYNEIGHBOURGS, ORIENTATION, WIREIN and SHELLIN. SUBSTRACTION exists in the enum but its Solve arm throws `Standard_NotImplemented`. [Name header](https://github.com/Open-Cascade-SAS/OCCT/blob/3d097a0328e71b826377d4814ab05ec3c3d23871/src/ApplicationFramework/TKCAF/TNaming/TNaming_Name.hxx), [types](https://github.com/Open-Cascade-SAS/OCCT/blob/3d097a0328e71b826377d4814ab05ec3c3d23871/src/ApplicationFramework/TKCAF/TNaming/TNaming_NameType.hxx), [Solve implementation](https://github.com/Open-Cascade-SAS/OCCT/blob/3d097a0328e71b826377d4814ab05ec3c3d23871/src/ApplicationFramework/TKCAF/TNaming/TNaming_Name.cxx#L1906-L1971).
4. DOCUMENTED: INTERSECTION first excludes descendants of the stop label, resolves every argument to its current shapes within the valid-label scope, enumerates their subshapes of the requested type, and intersects those sets by topology identity. An edge selected from adjacent faces is therefore an adjacency/set-intersection query, NOT a numerical surface/surface intersection. IDENTITY returns current descendants; MODIFUNTIL adds a forbidden-descendant boundary. FILTERBYNEIGHBOURGS retains candidates whose boundaries share an entity with each required neighbor's current shape. [Name implementation, Intersection, ModifUntil, FilterByNeighbourgs](https://github.com/Open-Cascade-SAS/OCCT/blob/3d097a0328e71b826377d4814ab05ec3c3d23871/src/ApplicationFramework/TKCAF/TNaming/TNaming_Name.cxx#L521-L728).
5. DOCUMENTED: ambiguous edge intersections have an additional packed index: edge index/count use 8 bits each; wire index/count and argument-face index use 4 bits each. It tries the indexed wire/edge if child counts are unchanged. Otherwise it stores all remaining common subshapes. This is conditional positional disambiguation, not a guarantee of semantic identity. [Intersection lines 645–725](https://github.com/Open-Cascade-SAS/OCCT/blob/3d097a0328e71b826377d4814ab05ec3c3d23871/src/ApplicationFramework/TKCAF/TNaming/TNaming_Name.cxx#L645-L725).
6. DOCUMENTED: `Selector.Select(selection,context,geometry,keepOrientation)` constructs naming if needed and stores a SELECTED NamedShape plus an IDENTITY wrapper. It explicitly supports selection type migration to a compound. `Naming.Solve(validLabels)` recursively solves child naming attributes first, then regenerates itself and adds its label to a nonempty valid scope. Empty scope means all labels are valid. `Regenerate` solves only the local recipe. [Selector](https://github.com/Open-Cascade-SAS/OCCT/blob/3d097a0328e71b826377d4814ab05ec3c3d23871/src/ApplicationFramework/TKCAF/TNaming/TNaming_Selector.cxx#L285-L383), [recursive Solve](https://github.com/Open-Cascade-SAS/OCCT/blob/3d097a0328e71b826377d4814ab05ec3c3d23871/src/ApplicationFramework/TKCAF/TNaming/TNaming_Naming.cxx#L138-L179).

## Robustness and guarantees

DOCUMENTED: correct operation history, registration and solving must stay synchronized. The guide's language about unique names is conditional on this contract; it must not be read as immunity to arbitrary topology change. The actual Intersection solver can succeed with several results, and Name::Solve catches `Standard_Failure` and returns its completion flag. A boolean success is therefore insufficient to establish unique resolution. [Guide §5.6](https://occt3d.com/dev/doc/overview/html/occt_user_guides__ocaf.html#occt_ocaf_5_6), [solver](https://github.com/Open-Cascade-SAS/OCCT/blob/3d097a0328e71b826377d4814ab05ec3c3d23871/src/ApplicationFramework/TKCAF/TNaming/TNaming_Name.cxx#L1906-L1971).

DOCUMENTED: these central naming operations use identity, integer counts, adjacency and history, rather than a geometric matching epsilon. The containing OCCT geometry stack uses floating-point geometry; this is not an exact-predicate theorem. INFERRED: wonky need not import f64 to port this naming layer; F32x2 or exact arithmetic only enters optional geometric disambiguation and the correctness of the upstream B-rep. [Name implementation](https://github.com/Open-Cascade-SAS/OCCT/blob/3d097a0328e71b826377d4814ab05ec3c3d23871/src/ApplicationFramework/TKCAF/TNaming/TNaming_Name.cxx).

## Parallelism and performance

DOCUMENTED: examined code is recursive, mutable, pointer/handle-based C++ with maps/lists, sequential subname solving and document updates. No naming throughput, latency or scalability benchmark was found in the guide or these files; no local build/test was run. INFERRED: immutable operation-history relations and sorted adjacency indexes are a better Bend port than OCAF's mutable object framework. Resolve independent same-depth recipes by balanced fork-join, merge outputs deterministically, and keep variable-depth history traversal on CPU unless flattened/bucketed. Do not claim uniform GPU work from arbitrary recursive naming. [Solve](https://github.com/Open-Cascade-SAS/OCCT/blob/3d097a0328e71b826377d4814ab05ec3c3d23871/src/ApplicationFramework/TKCAF/TNaming/TNaming_Naming.cxx#L138-L179).

## Known failures, limitations, war stories

- DOCUMENTED: [issue #758](https://github.com/Open-Cascade-SAS/OCCT/issues/758), filed 2025-10-23 and closed the next day, reports a crash looking up a selected shape after its deletion from the document; reporter expected a null result. This is a reported historical failure, not evidence that the pinned release remains affected.
- DOCUMENTED: multi-edge intersections can fall back to compound candidates; CONSTSHAPE and packed-index disambiguation depend on positions; subtraction naming is unimplemented. [Name.cxx](https://github.com/Open-Cascade-SAS/OCCT/blob/3d097a0328e71b826377d4814ab05ec3c3d23871/src/ApplicationFramework/TKCAF/TNaming/TNaming_Name.cxx).
- DOCUMENTED: Selector source warns that an old selection shape already present in the used-shape map can complicate naming and create cycles. [Selector lines 332–337](https://github.com/Open-Cascade-SAS/OCCT/blob/3d097a0328e71b826377d4814ab05ec3c3d23871/src/ApplicationFramework/TKCAF/TNaming/TNaming_Selector.cxx#L332-L337).

## Relevance for wonky

INFERRED design, based on the documented recipe/evolution split: add immutable `SelectionExpr` separately from lineage. Minimal expression algebra: semantic feature face; descendants at operation scope; common boundary of face sets; generated-from entity; adjacency filter; orientation/region filter. Represent IDs, recipe tags, offsets and cardinalities with U32 (multiword IDs if needed), with no floating arithmetic required for the core. Store scope explicitly to prevent accidentally resolving against downstream operations.

INFERRED contract: resolve to `Unique(entity) | Split(set) | Missing(reason) | Ambiguous(candidates) | Unsupported(reason)`, not a boolean plus a shape. A caller can request ONE or ALL descendants. Store face-pair references in canonical order only for orientation-independent edge identity; retain coedge orientation separately. Never select the first edge merely because two faces intersect in several components. Handle cylinder seams independently because a sorted pair of two distinct face IDs cannot describe a self-adjacent seam. These proposals directly address the documented compound fallback and seam-history requirements above.

INFERRED integration: Boolean and fillet operations must emit Generated/Modified/Deleted before reliable selections or diffs exist. NamedShape evolution can drive lineage diffs; selection recipes make FeatureScript queries and diagnostics explainable. For FDM/LLM ergonomics, report the failed recipe and candidate roles rather than silently filleting a different edge. This is not itself a general Boolean or interference algorithm.

## Verdict: adapt

Adopt the history-plus-solvable-selection architecture, but redesign storage as immutable indexed relations and expose ambiguity/cardinality explicitly. Do not port the mutable framework wholesale, copy positional fallbacks as guarantees, or treat LGPL-with-exception as permissive. No production files changed.
