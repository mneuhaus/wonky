## What it is
DOCUMENTED: rigorous operation-level error analysis for an unevaluated sum x=xh+xl of two radix-2 precision-p floating-point numbers, normalized by **xh=RN(x)**. It covers DW±DW, DW×DW, DW÷DW, and mixed DW/FP operations. It is not IEEE arithmetic with precision 2p, not correctly rounded DW arithmetic, not arbitrary precision, and not exact predicates. [2017 §§1–7](https://hal.science/hal-01351529v3/document).

## How it works
DOCUMENTED numerical model: round to nearest, ties to even, u=2^-p, unlimited exponent range in the analysis. Real implementations inherit the results only when relevant underflow and overflow do not occur. Exact error-free primitives feed approximate DW operations. Fast2Sum(a,b) requires an exponent-order condition, normally ensured by |a|≥|b|; general 2Sum has no magnitude precondition. 2Prod(a,b) gives (h,l) with h+l=ab exactly, via either Dekker splitting (17 FP operations) or an FMA residual (2). The 2017 operation counts assume the FMA implementation even for algorithms that otherwise need no FMA. [2017 pp.2–4](https://hal.science/hal-01351529v3/document).

**Concrete no-FMA-capable candidates; every RN below is a separate rounding, not algebraic shorthand:** [2017 Algorithms 4,6,7,8,10,15,17](https://hal.science/hal-01351529v3/document).
- DWPlusFP: (sh,sl)=2Sum(xh,y); v=RN(xl+sl); return Fast2Sum(sh,v). Relative error ≤2u².
- AccurateDWPlusDW, Algorithm 6: (sh,sl)=2Sum(xh,yh); (th,tl)=2Sum(xl,yl); c=RN(sl+th); (vh,vl)=Fast2Sum(sh,c); w=RN(tl+vl); return Fast2Sum(vh,w). Bound 3u²/(1−4u), or 3u²+13u³ for p≥6. The final Fast2Sum preconditions follow from the whole algorithm's proof; blindly replacing arbitrary 2Sum calls by Fast2Sum does not.
- DWTimesFP1, Algorithm 7: (ch,c1)=2Prod(xh,y); c2=RN(xl·y); (th,t1)=Fast2Sum(ch,c2); t2=RN(t1+c1); return Fast2Sum(th,t2). Bound 1.5u²+4u³. Algorithm 8 is cheaper: return Fast2Sum(ch,RN(c1+c2)), but its bound is 3u².
- DWTimesDW1, Algorithm 10: (ch,c1)=2Prod(xh,yh); t1=RN(xh·yl); t2=RN(xl·yh); c2=RN(t1+t2); c3=RN(c1+c2); return Fast2Sum(ch,c3). The omitted xl·yl is deliberately included in the error budget. Original bound <7u²; **use the later proven <5u² bound under ties-to-even**, not the obsolete pessimistic constant.
- DWDivFP3, Algorithm 15: th=RN(xh/y); (ph,pl)=2Prod(th,y); dh=RN(xh−ph); dl=RN(dh−pl); d=RN(dl+xl); tl=RN(d/y); return Fast2Sum(th,tl). The first two subtractions are proved exact in the stated range. Bound 3u²; denominator must be nonzero. The rearrangement of residual terms relative to Algorithms 13/14 matters.
- DWDivDW2, Algorithm 17: th=RN(xh/yh); (rh,rl)=DWTimesFP1(yh,yl,th); ph=RN(xh−rh); dl=RN(xl−rl); d=RN(ph+dl); tl=RN(d/yh); return Fast2Sum(th,tl). Bound 15u²+56u³ for p≥7. This removes provably useless operations from Algorithm 16 without changing its result.

DOCUMENTED FMA alternatives: DWTimesFP3 (Algorithm 9), DWTimesDW2/3 (Algorithms 11/12), and DWDivDW3 (Algorithm 18) use fused residual accumulation; these are not available by simply writing a*b+c in a backend with no specified fused operation. Algorithm 18 implements one Newton reciprocal correction followed by a DW multiplication; bound 9.8u². [2017 §§4–7](https://hal.science/hal-01351529v3/document).

### Essential 2022 follow-up
DOCUMENTED: Muller and Rideau formally proved all 15 analyzed DW algorithms using Coq/Flocq. The 2017 bounds remain valid, but one published proof used a false lemma: ab≤2 with a,b≥1 does **not** imply a+b≤2√2 (a=1,b=2 is a counterexample). They repaired the proof and improved multiplication bounds: DWTimesDW1 <5u² under ties-even, <5.5u² for general nearest tie rules; DWTimesDW2 <5u²; DWTimesDW3 <4u². They also constructed a family attaining almost 3u² for accurate addition, showing why observed maxima around 2.25u² were not a safe bound. [2022 §2, Table 1, Theorems 2.6–2.8](https://hal.science/hal-02972245v2/document).

**Portable adversarial addition family, DOCUMENTED [2022 Property 2.1](https://hal.science/hal-02972245v2/document):** xh=1, xl=u−u², yh=−1/2+u/2, yl=−u²/2+u³. The relative error is (3u²−2u³)/(1+3u−3u²+2u³), asymptotically 3u². This is a better regression fixture than millions of random pairs. The formal proof archive is [linked by the authors](https://www-sop.inria.fr/members/Laurence.Rideau/DW_arithmetic-submitted_paper_release.zip); archive not independently compiled or audited here.

## Robustness and guarantees
- DOCUMENTED: Algorithm 5 SloppyDWPlusDW can return zero when the true sum is nonzero, with relative error 1. The original article recommends it only for situations such as same-sign operands, not arbitrary cancellation-prone geometry. Algorithm 6 is the safe general addition choice within its arithmetic contract. [2017 §3](https://hal.science/hal-01351529v3/document).
- DOCUMENTED: normalization is an input and output invariant, not optional decoration. These proofs do not apply to arbitrary overlapping pairs or pairs created by an uncontrolled parser conversion. A [2024 follow-up on moderate overlap](https://arxiv.org/pdf/2404.05948) was inspected for context (pp.1–6); its separate hypotheses are not a blanket license to delete renormalization.
- INFERRED from the explicit exponent premise: FTZ/DAZ, overflowing splitter products, subnormal residual loss, reassociation, wider JS intermediates, or unintended contraction can invalidate 2Sum/2Prod and every composed bound. `hi` being normal does not suffice. The scale u·hi reaches min-normal near hi≈2^-102 in binary32, but this is only a useful warning scale: a nonzero low word/residual can be arbitrarily smaller than u·hi, even for much larger hi. There is no universal 'all safe above 2^-102' theorem. [2017 numerical model, pp.2–4](https://hal.science/hal-01351529v3/document).
- INFERRED: for F32, corrected no-FMA candidates give roughly 46.4 relative-error bits for addition, 45.7 for multiplication, and 44.1 for DW division (−log2 of their worst-case per-operation bounds). These numbers describe error guarantees, not a fixed representational precision. The pair still has F32's exponent limitations; it is not binary48 or binary64.
- INFERRED: per-operation relative error does not certify the final sign of a cancellation-heavy determinant whose operands already contain upstream approximation errors. Carry an absolute error radius through the expression, use a generated filter proof, and fall back when zero lies in the enclosure. Approximate zero never establishes exact coincidence. [2017 error definitions](https://hal.science/hal-01351529v3/document).

## Parallelism and performance
DOCUMENTED: Table 1 counts FP operations, not measured end-to-end throughput: accurate DW addition 20; mixed DW+FP 10; DWTimesDW1 9; DWDivDW2 18, assuming a two-operation FMA-based 2Prod. Using a 17-operation Dekker 2Prod increases the latter two by 15 operations to 24 and 33 respectively (INFERRED count). Do not advertise the FMA counts for Bend. The 2022 paper's 4,000,000-sample error-distribution figure demonstrates rarity of adversarial cases, not a performance benchmark. [2017 Table 1](https://hal.science/hal-01351529v3/document), [2022 Figure 1](https://hal.science/hal-02972245v2/document).

INFERRED: short immutable scalar DAGs are an excellent Bend fit; no heap, FFI or variable-length expansion is required. Independent high/low sums and cross products can fork, but each renormalization/residual chain is serial. Parallelize many coordinates/predicates rather than spawning tiny arithmetic tasks. Fixed algorithm variants provide uniform GPU work; keep range-error and exact-fallback batches separate.

## Known failures, limitations, war stories
DOCUMENTED: an older claimed accurate-add bound 2u² was false; the 2017 multiplication proof contained a false inequality; random experiments missed the true nearly-3u² addition cases. Formalization fixed the reasoning without invalidating the algorithms. These are primary-source numerical 'war stories', not repository issues. No canonical issue tracker belongs to the paper. [2017 Algorithm 6 counterexample](https://hal.science/hal-01351529v3/document), [2022 §§2.2–2.4](https://hal.science/hal-02972245v2/document).

INFERRED: neither paper supplies transcendental functions, square-root error bounds, matrix-condition estimates, SSI root isolation, exact algebraic numbers, or a finite-exponent/FTZ implementation. F32 division must actually meet the assumed RN contract; a hardware approximate reciprocal is not interchangeable.

## Relevance for wonky
INFERRED from [the algorithms and corrected guarantees](https://hal.science/hal-02972245v2/document):
1. Make the F32x2 module's public contract explicit: normalized pair, exact interpretation of the input pair as a sum of dyadics, bounded-error operations, valid range/status, no promise of exact construction. Use Algorithms 6,10,15,17 with non-FMA 2Prod as the conservative initial set.
2. Audit current operation schedules against these exact variants. Pin the theorem/version beside each bound; conservatively evaluate all bound arithmetic. Do not adopt a faster schedule based only on approximate numerical similarity.
3. Use this as a middle precision tier for geometry evaluation, certified sign filters, curve parameter refinement, and bounded FDM tessellation/deviation calculations. Exact U32 predicates should still decide Boolean topology and homogeneous-coordinate comparisons.
4. For analytic SSI and fillets, combine DW approximate candidates with certified intervals and root isolation; this paper alone cannot prove that a root exists or that topology is correct.
5. Outstanding validation (not run): corrected adversarial families at p=24; cancellation and signed zeros; underflow in low words and splitter overflow; cross-target strict-rounding checks; exact dyadic oracle comparisons. Expose range/fallback metadata to the viewer and LLM-facing diagnostics rather than silently accepting a rounded zero.

Adopt as the specification and verification basis for bounded F32x2 arithmetic, including the 2022 corrections. This is a strong fit for immutable fixed-work Bend operations, but not an exact-number replacement. FTZ/range proofs and implementation validation remain open; no production code changed.
