## What it is
DOCUMENTED: a compositional generator of static, almost-static and semi-static floating-point sign filters for arbitrary polynomial expression trees. Exact arithmetic is a subsequent stage; a filter returns negative, zero, positive, or uncertain. Its key contribution is branch-efficient error bounds that remain sound in the presence of gradual underflow and overflow. This is not a universal exact construction engine or a theorem for flush-to-zero arithmetic. [Paper §§2–4](https://arxiv.org/pdf/2208.00497).

## How it works
DOCUMENTED [Definition 12, Lemmas 14–15, Theorem 16](https://arxiv.org/pdf/2208.00497): preserve a chosen floating-point evaluation tree q-tilde and recursively attach a pair (a,m). Here a is a compile-time polynomial in u, m a nonnegative runtime magnitude expression, with invariants |q-tilde|≤m and |q-tilde−q|≤a(u)m, unless m is Inf/NaN, in which case certification must fail.
- Constants and input leaves: (0,|x|). A sum/difference of two input leaves: (u,|RN(x±y)|). A product of leaves: (u,|RN(xy)|), or the underflow-protected magnitude |RN(xy)| plus the smallest normal uN.
- General sum/difference: a=(1+u)max(a1,a2)+u, m=RN(m1+m2).
- General product: a=(1+u)(a1+a2+a1a2)+u, m=RN(m1m2); UFP variant adds uN to m. A specialized rule for a product of two input differences/sums gives a tighter polynomial (Definition 12 rule 5, citing Ozaki). Implement the simpler compositional rules first rather than mistranscribing this optimization.
- At a final sum/difference, choose representable constants a3>max(a1,a2)/(1−u), a4≥a3(1+u)². Error estimate e=RN(a4·RN(m1+m2)). With UFP, add uS, the smallest positive subnormal. Accept only |p-tilde|>e. The theorem's non-UFP variant can also accept e=0, under its no-underflow assumptions. Inf/NaN bounds make the strict comparison false under ordinary IEEE semantics. Fast-math assumptions that discard NaNs destroy this protection.
- UFP cannot certify exact zero, so a separate symbolic zero filter proves common degeneracies: a leaf is zero iff its input is zero; a sum/difference of direct floating inputs can establish exact zero; a composite sum is certainly zero if both children are; a product if either is. This uses gradual-underflow facts, not an arbitrary “computed result==0” test. A custom rectangle incircle filter short-circuits a common structured exact-zero case.
- A static filter prebounds the magnitude expression over the input domain; an almost-static filter recomputes such bounds when the domain changes. The paper also shows a rounded-input rule (Example 21); original real/rational inputs must remain available for exact fallback.

**Actual code details, DOCUMENTED [v1 ZIP](https://zenodo.org/records/6836062):** header-only C++20 plus STL/Boost.Mp11. Expression templates form a deduplicated postorder DAG shared by predicate and bound, avoiding repeated subexpressions. Bound coefficients are constexpr integer arrays. forward_error_bound.hpp implements first-applicable-rule dispatch, coefficient rounding and collapse_underflow_guards. The artifact uses 2·uN guards, with an optional BOOST_GEOMETRY_GRP_AVOID_DENORM multiplier 1/u; these implementation details differ from the paper's simplified presentation. That macro is NOT, by its name alone, a proof of correctness on FTZ/DAZ hardware. semi_static_filter::apply uses strict det>bound / det<−bound and then a separate bound==0 && det==0 clause (its old prose comment says ≥; read executable code). zero_pattern.hpp implements the structural zero proof. Keep the theorem-to-code mapping explicit when porting.

## Robustness and guarantees
- DOCUMENTED: standard gradual-underflow model, u=2^-p, uN=min normal, uS=2u·uN. Underflowed addition/subtraction of representable inputs is exact; multiplication has an absolute uS/2 term. These facts are proof premises, not valid under FTZ. [Paper Definition 3, Lemma 11](https://arxiv.org/pdf/2208.00497).
- DOCUMENTED counterexample (Example 7): a=(0,0), b=(2^emin,0), c=(2^emin,2^emin) are not collinear. A naive stage-A evaluation produces determinant=0 and bound=0 after underflow and can certify the false zero. For binary32 substitute emin=−126. A strict comparison plus separate *proved* zero handling is essential.
- DOCUMENTED (Remark 5): contraction of ab−cd into FMA(a,b,−RN(cd)) need not be the negative of the swapped expression FMA(c,d,−RN(ab)); argument swapping can cease to reverse orientation. This does NOT mean properly analyzed FMA is inherently unsuitable; it means a different arithmetic tree needs different error proofs.
- INFERRED: F32 parameters can instantiate the symbolic analysis, but uS=2^-149 cannot survive an FTZ backend. Worse, the zero filter's leaf subtraction can flush a nonzero difference to zero. Replacing only the final uS constant cannot repair all of this. Disable such acceptance paths or derive rules for the actual backend model, including input DAZ and fused operations. [Same premises](https://arxiv.org/pdf/2208.00497).

## Parallelism and performance
DOCUMENTED: GNU/Linux i7-6700HQ, GCC 11.1 -O3 -march=native, CGAL 5.4, GMP 6.2.1, MPFR 4.1.0, Boost 1.79, turbo disabled. UFP cost 4.2% on continuous-random million-point 2D triangulation, around 1% on mesh refinement, and no measured cost on the polyhedral-envelope benchmark. CGAL predicates added around 28% runtime in the latter benchmark; mesh-refinement difference was only about 3.4%. On the grid, UFP and CGAL were within about 0.2%, not a universal large speedup. Table 2 orientation first-filter failures: 49,375 without UFP, 624,400 with UFP, 49,641 CGAL, out of 4,121,216 calls. [Paper §4.2/Table 2](https://arxiv.org/pdf/2208.00497).

INFERRED: the generated expression and bound DAGs are excellent uniform GPU candidates and can be emitted as straight-line Bend code; sibling subtrees and batched predicates fit balanced fork-join. Variable-depth exact stages should run in separated batches. Host-side code generation is compatible with the constraint that production geometry executes in Bend; embedding the C++ kernel is not.

## Known failures, limitations, war stories
DOCUMENTED: architecture-dependent within/touches classifications (Table 1), FMA antisymmetry failure (Remark 5), explicit underflow false-zero (Example 7), increased fallback on exact degeneracies (Table 2). No archived issue tracker accompanies the ZIP. Generalizations to non-polynomial predicates and implicit construction points are explicitly future work, not completed capabilities. [Paper §§2,4/conclusion](https://arxiv.org/pdf/2208.00497).

INFERRED: don't blindly copy displayed benchmark determinant formulas: the v1 incircle/weighted-sphere display contains repeated coordinate terms inconsistent with the standard squared norm. Generate from a tested algebraic specification and inspect the artifact expression definitions. Compiler scheduling/rewriting after generation remains part of the soundness boundary.

## Relevance for wonky
INFERRED, grounded in [the theorem and artifact](https://zenodo.org/records/6836062): build a small offline predicate DSL → Bend generator, carrying expression degree, exact-input semantics, F32 bound expression, explicit range status, and U32 fallback limb budget. Prioritize orient2d/orient3d, LPI/TPI side tests and homogeneous-coordinate comparisons for the Boolean bake-off. F32x2 is an optional middle filter only if its own bounds are composed; it is not an automatic exact backend. Rational/implicit values need symbolic denominator-sign handling and input provenance. Curved SSI/fillets need additional algebraic/interval machinery. Emit introspective certainty/stage counters for comparing the prototypes without hiding unsupported cases.
