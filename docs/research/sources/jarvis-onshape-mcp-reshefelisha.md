## What it is

DOCUMENTED: an coordination/introspection layer, not a geometry kernel. Python builds Onshape BTMFeature/BTMSketch payloads, calls its remote regeneration engine, retrieves classified geometry and images, and supplies structured feedback. Its greatest transferable value is the action-observation contract, not Boolean/fillet code. [README](https://github.com/ReshefElisha/jarvis-onshape-mcp/blob/b0e725852280ebcfda5d46a4f2ed2d0b720beace/README.md).

## How it works

DOCUMENTED implementation details (links pinned to the inspected revision):

1. **One call, several independent observations.** `PartStudioDescriber.describe_part_studio` launches feature tree, classified entities, bounding box, mass properties, multiview renders, and face-area probe with `asyncio.gather(..., return_exceptions=True)`. It formats physical summary and images; raw data live in the snapshot object. It is one agent call, NOT one HTTP request and NOT a revision-pinned atomic snapshot. Failures are replaced with empty/default sections. Text `_body_topology_text` prints every face, but only edge counts, not every edge descriptor, despite broad schema wording. [describe.py](https://github.com/ReshefElisha/jarvis-onshape-mcp/blob/b0e725852280ebcfda5d46a4f2ed2d0b720beace/onshape_mcp/api/describe.py).
2. **Selection without guessing IDs.** `EntityManager.list_entities` fetches `/bodydetails`, optionally probes `evFaceTangentPlane` at UV (0.5,0.5), derives Y by cross(normal,X), and emits ID/type/origin/defining normal/outward normal/sketch X/Y/radius plus readable descriptors. Axis labels require normalized component >0.999 in magnitude. Type, outward axis, origin-Z or midpoint-Z, radius and edge-length filters apply before serialization; original/filtered counts and echoed filters preserve context. Default Z-window is 0.5 mm, a selector convenience, not kernel tolerance. All geometry is fetched first, so this saves agent tokens, not necessarily CAD-server work. Probe failure falls back to defining normals, which can point inward. [entities.py](https://github.com/ReshefElisha/jarvis-onshape-mcp/blob/b0e725852280ebcfda5d46a4f2ed2d0b720beace/onshape_mcp/api/entities.py).
3. **Do not confuse coordinates with clearance.** `MeasurementManager.measure` chooses surface origin / edge midpoint / vertex point. It returns Euclidean point distance, sign-independent acute angle `acos(clamp(abs(dot(a,b)),0,1))`, and some projected distances `abs(dot(p-o,n))`. Parallel/perpendicular threshold is 1e-4 radians. It is not closest-point distance between trimmed entities. Edge direction and reported edge length use the endpoint chord, not a curved-edge tangent or arc length. Important static finding: projected face-point distance is nested inside `da != None and db != None`, so vertex-plane pairs do not get their documented projected distance; vertices have no direction. No runtime reproduction was performed. [measurements.py](https://github.com/ReshefElisha/jarvis-onshape-mcp/blob/b0e725852280ebcfda5d46a4f2ed2d0b720beace/onshape_mcp/api/measurements.py), [edge classification](https://github.com/ReshefElisha/jarvis-onshape-mcp/blob/b0e725852280ebcfda5d46a4f2ed2d0b720beace/onshape_mcp/api/entities.py).
4. **Mutation result is more than HTTP 200.** `apply_feature_and_check` reads `featureState.featureStatus`, falls back to refetching features, and returns `{ok,status,feature_id,feature_name,feature_type,error_message,changes}`. Actual code treats both OK and INFO as `ok=true` despite a stricter class docstring. On non-OK status it fetches a FeatureScript status enum for explanation. Optional before/after geometry diffs compare body count, volume, face/edge signatures, and bounding boxes. Face signatures are `(id,type,round(origin,6))` in meters; edge signatures contain rounded endpoints. This is a heuristic diff, not topological history or a proof of no change. [feature_apply.py](https://github.com/ReshefElisha/jarvis-onshape-mcp/blob/b0e725852280ebcfda5d46a4f2ed2d0b720beace/onshape_mcp/api/feature_apply.py), [geometry_diff.py](https://github.com/ReshefElisha/jarvis-onshape-mcp/blob/b0e725852280ebcfda5d46a4f2ed2d0b720beace/onshape_mcp/api/geometry_diff.py).
5. **Silent no-op repair.** REMOVE extrudes from picked faces default to the opposite sketch normal because outward extrusion may remove nothing while returning INFO. Explicit `forceOppositeDirection` overrides this; the extra field exists because MCP clients can materialize default boolean parameters, making presence of `oppositeDirection` unreliable as an intent signal. Adapt the explicit intent/normal reporting, not hidden automatic direction changes. [server.py, create_extrude branch](https://github.com/ReshefElisha/jarvis-onshape-mcp/blob/b0e725852280ebcfda5d46a4f2ed2d0b720beace/onshape_mcp/server.py#L2860).
6. **Sketch edits retain identity.** Constraint-first entities have caller IDs and subpoint references (`line.start`, `circle.center`); Onshape solves dimensions/tangencies. `edit_sketch` fetches the full sketch, serializes new specs, removes requested entity/constraint IDs, cascades deletion to old constraints referencing deleted entity bases, checks ID collisions, then reposts. Same-call remove+add allows retargeting. Returns cascaded constraint removals for audit. The pure `_merge` is a useful model for immutable edits. [sketch_edit.py](https://github.com/ReshefElisha/jarvis-onshape-mcp/blob/b0e725852280ebcfda5d46a4f2ed2d0b720beace/onshape_mcp/api/sketch_edit.py), [constraint serializers](https://github.com/ReshefElisha/jarvis-onshape-mcp/blob/b0e725852280ebcfda5d46a4f2ed2d0b720beace/onshape_mcp/builders/sketch_constraints.py).
7. **Interference is broad phase only.** Transform eight local-AABB corners, form world AABBs, test every pair with `o_i=min(maxA_i,maxB_i)-max(minA_i,minB_i)` and require all three overlaps >1e-8 meters. Reports box-overlap volume in cubic inches. Only direct root Part instances are processed; subassemblies/suppressed/missing-bbox parts are skipped. Missing boxes are logged, not necessarily returned as incomplete coverage. [interference.py](https://github.com/ReshefElisha/jarvis-onshape-mcp/blob/b0e725852280ebcfda5d46a4f2ed2d0b720beace/onshape_mcp/analysis/interference.py).

## Robustness and guarantees

DOCUMENTED: IDs are current Onshape deterministic IDs, not a cross-regeneration naming guarantee; diff source explicitly concedes ID drift. Outward frame enrichment and snapshot components are best-effort. Double-precision Python `float` arithmetic processes remote values in meters; output display converts to mm (some assembly diagnostics still inches). No exact predicates, interval certificates or shape-validity proof are supplied. [entities](https://github.com/ReshefElisha/jarvis-onshape-mcp/blob/b0e725852280ebcfda5d46a4f2ed2d0b720beace/onshape_mcp/api/entities.py), [diff](https://github.com/ReshefElisha/jarvis-onshape-mcp/blob/b0e725852280ebcfda5d46a4f2ed2d0b720beace/onshape_mcp/api/geometry_diff.py), [interference](https://github.com/ReshefElisha/jarvis-onshape-mcp/blob/b0e725852280ebcfda5d46a4f2ed2d0b720beace/onshape_mcp/analysis/interference.py).

INFERRED: for wonky, observation failures must be `unknown/unavailable`, not `empty/no interference`; a query needs revision, units, coordinate frame, method and tolerance. Even exact bounding boxes can overlap for disjoint solids, so label this method `aabb_candidate`, never `solid_intersection`. AABB rounding needs outward error bounds before it can safely reject close pairs.

## Parallelism and performance

DOCUMENTED author-reported, not independently reproduced: snapshot docstring says roughly 1–2 seconds and face-area probe roughly 50 ms; `list_entities` comments report 80–100 KB unfiltered dogfood responses. These are anecdotes, not a benchmark distribution. [describe](https://github.com/ReshefElisha/jarvis-onshape-mcp/blob/b0e725852280ebcfda5d46a4f2ed2d0b720beace/onshape_mcp/api/describe.py), [entities](https://github.com/ReshefElisha/jarvis-onshape-mcp/blob/b0e725852280ebcfda5d46a4f2ed2d0b720beace/onshape_mcp/api/entities.py).

DOCUMENTED exploratory author eval: for mm_2025, human spec composite 1.000 in 57 turns/7 minutes versus agent spec 0.533 in 147 turns/40 minutes; for mm_2021, 0.615/102 turns/27 minutes versus 0.000/no export at 151 turns. Tiny comparison and composite grading, not general success probabilities. [RESEARCH.md](https://github.com/ReshefElisha/jarvis-onshape-mcp/blob/b0e725852280ebcfda5d46a4f2ed2d0b720beace/RESEARCH.md).

INFERRED: classification/filtering maps and area/volume/count reductions fit Bend balanced fork-join. Network gather is host coordination, not evidence of geometry parallelism. AABB pair enumeration is O(n²); use a broad-phase hierarchy for large models. Strings/JSON/cache management stay in the JS frontend; numeric geometry stays Bend.

[hedless PR #25](https://github.com/hedless/onshape-mcp/pull/25) and [#29](https://github.com/hedless/onshape-mcp/pull/29) show the alternative receiving API payload fixes/regression guards. Do not trust upstream's success-path demos as current compatibility certification.
- DOCUMENTED reporter evidence: [#12](https://github.com/ReshefElisha/jarvis-onshape-mcp/issues/12) reports revolve axis query selecting four datum-plane edges and STL export 1000× too small. The issue names revisions different from the inspected default HEAD; treat this as a reported deployment failure, not a reproduced HEAD finding.
- DOCUMENTED reporter evidence: [#16](https://github.com/ReshefElisha/jarvis-onshape-mcp/issues/16) describes unbound custom-feature booleans/quantities and bodies left after failed operations. Useful transactional rollback/provenance test cases, not verified facts about Onshape internals.
- [#6](https://github.com/ReshefElisha/jarvis-onshape-mcp/issues/6) reports wrong `assignVariable` parameter ID accepted as OK. **Contrary static evidence:** inspected `update_feature_params_and_check` explicitly raises when IDs are missing. The general lesson (verify effective parameter delta, not only regeneration status) survives; claiming this bug is established in inspected HEAD does not.
- DOCUMENTED large-model pressure: [#20](https://github.com/ReshefElisha/jarvis-onshape-mcp/issues/20), [open PR #21](https://github.com/ReshefElisha/jarvis-onshape-mcp/pull/21) propose bounded observations, server-side raw payloads, read tracking, dependency slices. Not merged capability.

## Relevance for wonky

INFERRED, grounded in the files above: adopt the observation loop and port its semantics, not the remote backend. Suggested immutable result: revision + typed feature statuses + operation delta + entity descriptors + frame/units + volume/bbox + diagnostic method/completeness + render handles. Query accepts selectors and budgets; fetching a detailed entity uses stable provenance-aware IDs. Preserve a machine-readable numeric record even when display text is rounded. Parameter edits should reject unknown keys and report effective changed values; failed modeling is atomic, and successful intentional no-ops are distinguished from accidental no-ops.

INFERRED Bend fit: IDs/enums/index lists are U32; filters and frame math can be pure F32x2 functions. Affine arrays support rebuilding the sketch/constraint arrays after a deletion mask; dependent constraints can be marked with a balanced map/reduction, reporting all cascades. Bound checking/nearest distance must use wonky's certified arithmetic, not copy Python epsilon constants or the arc-chord bug. No multi-limb integer algorithm or SSI/fillet machinery is provided here. Uniform GPU work fits fixed-size frame/bbox classification; dependency traversal and JSON stay CPU/frontend. A real narrow-phase interference/clearance/section API is a strong differentiator for FDM mating checks.

High-value LLM ergonomics and diagnostics design; not a reliable geometry substrate or a ready-made wonky verifier. Keep snapshot/filter/frame/cascade patterns, replace heuristic geometry and incomplete-success semantics, retain provenance and explicit numeric guarantees.
