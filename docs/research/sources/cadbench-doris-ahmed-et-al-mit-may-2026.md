## What it is

DOCUMENTED: 18,000 shapes, six families of 3,000 each: Base/DeepCAD, Fusion/Fusion 360, Extrude/ABC sketch-extrude, All-Ops/ABC richer operations, Mechanical/MCB, Organic/Objaverse. Five input modalities: clean mesh, noisy mesh, single grayscale view, four-view composite, photorealistic rendering. Eleven specialized or general models, >1.4M generated programs. This is geometric reconstruction from observations, **not text-to-CAD or interactive-agent evaluation**. Fixed-prompt VLM runs do not use tools, self-correction, or multi-turn refinement; evaluated specialized algorithms may have their own search, e.g. CADFit. [Paper §§3–5](https://arxiv.org/pdf/2605.10873v2).

## How it works

1. DOCUMENTED: filter to individual solids, remove duplicates, reject pseudo-STEP mesh wrappers and image/text sketch entities from ABC. Four STEP families get three B-rep face-count tiers. Mesh-only families do not use triangle count as complexity. DINOv3 ViT-B/16 produces 768D embeddings for eight grayscale isometric views, averaged per object; k-means with k=1,000 per tier or k=3,000 for a mesh family, then nearest example to each centroid. This controls geometric diversity as well as rough complexity. The ABC operation split examines original Onshape FeatureScript histories. [Paper App. A.1–A.3](https://arxiv.org/pdf/2605.10873v2), [selection code](https://github.com/anniedoris/CADBench/tree/99e41a2eeb351f04611e83980f9f23cb0ca216c7/get_bench).
2. DOCUMENTED: meshes normalized to a [-1,1]^3 bounding box; noisy variants use isotropic remeshing, Gaussian vertex noise sigma=0.005, then Laplacian smoothing. Single-view images are 1200×1200. This is one synthetic noise distribution, not a complete sensor/noise model. [Paper App. A.4](https://arxiv.org/pdf/2605.10873v2).
3. DOCUMENTED: prediction interface is JSONL with file_id and generated CadQuery Python, plus a specified final solid variable. Evaluator executes it, exports STL, computes metrics, and returns per-case status/details. Source is necessary for compactness, though geometry functions can receive a mesh directly. [README](https://github.com/anniedoris/CADBench/blob/99e41a2eeb351f04611e83980f9f23cb0ca216c7/README.md), [perform_evaluation](https://github.com/anniedoris/CADBench/blob/99e41a2eeb351f04611e83980f9f23cb0ca216c7/CADBenchEval/CADBench/Eval/_main.py#L50-L144).
4. DOCUMENTED: paper metrics are volume IoU, symmetric squared Chamfer distance, thresholded bidirectional surface coverage called SIoU, valid shape rate, token count and operation count. Paper SIoU = 0.5(mean[nearest distance pred→GT < tau] + mean[nearest distance GT→pred < tau]), tau=1% GT bounding-box diagonal. It is **not** set-theoretic intersection-over-union or an F-score despite its name. Per-split median IoU/SIoU includes failed cases as zero; median CD includes only successful cases. Aggregate scores weight split summaries by sample counts, not a single global median. [Paper §3.2, App. A.5](https://arxiv.org/pdf/2605.10873v2).
5. DOCUMENTED: alignment uses center of mass, inertia-based scale and principal axes. Code computes s=sqrt(trace(I)/mass), normalizes both solids, tries the four proper principal-axis sign choices plus an unrotated candidate, chooses maximum IoU, then restores target scale/translation. This is a finite principal-axis alignment, not unrestricted optimization over SO(3). [align_shapes](https://github.com/anniedoris/CADBench/blob/99e41a2eeb351f04611e83980f9f23cb0ca216c7/CADBenchEval/CADBench/Eval/geometry/_utils.py#L41-L112).

### Important paper/implementation discrepancies

These are DOCUMENTED source observations at the pinned commit, not measurements of how the published numbers were produced. Do not silently claim to reproduce the paper with the current checkout.

- Paper writes squared nearest-neighbor CD. Code pc_chamfer_distance sums means of **unsquared** cKDTree distances. It samples 10,000 points per mesh through Open3D. [Code](https://github.com/anniedoris/CADBench/blob/99e41a2eeb351f04611e83980f9f23cb0ca216c7/CADBenchEval/CADBench/Eval/geometry/_utils.py#L158-L172).
- Paper uses tau=1% bounding-box diagonal; code defaults to a **fixed 0.02** after longest extent has been normalized to 2. These coincide only for a degenerate/one-dimensional bounding box, not general solids. [surface_iou](https://github.com/anniedoris/CADBench/blob/99e41a2eeb351f04611e83980f9f23cb0ca216c7/CADBenchEval/CADBench/Eval/geometry/_utils.py#L174-L205), [normalization call path](https://github.com/anniedoris/CADBench/blob/99e41a2eeb351f04611e83980f9f23cb0ca216c7/CADBenchEval/CADBench/Eval/_main.py#L93-L116).
- Paper describes voxelized IoU. Code first asks Trimesh for Boolean intersection/union volume, then falls back to 500,000 fixed-seed Monte Carlo samples and float32 +X ray parity. Thus representation, tolerance, and failure behavior differ. [iou and _sampling_iou](https://github.com/anniedoris/CADBench/blob/99e41a2eeb351f04611e83980f9f23cb0ca216c7/CADBenchEval/CADBench/Eval/geometry/_utils.py#L114-L156).
- Current perform_evaluation alpha-wraps **both** inputs before measuring, with nominal alpha_fraction=1e-3, offset_fraction=1e-4, then tries alternative keyword names and finally library defaults. It may measure a repaired outer shell rather than the original output; fallback defaults need logging for reproducibility. [alpha_wrap](https://github.com/anniedoris/CADBench/blob/99e41a2eeb351f04611e83980f9f23cb0ca216c7/CADBenchEval/CADBench/Eval/geometry/_utils.py#L12-L38), [call site](https://github.com/anniedoris/CADBench/blob/99e41a2eeb351f04611e83980f9f23cb0ca216c7/CADBenchEval/CADBench/Eval/_main.py#L93-L99).
- Token count uses Python tokenize excluding comments/layout, with regex fallback: **not provider/BPE billing tokens**. Operation count is a static AST vocabulary count including navigation, selectors, helpers and direct factories, not executed geometric operations; no loop expansion. [code_metrics.py](https://github.com/anniedoris/CADBench/blob/99e41a2eeb351f04611e83980f9f23cb0ca216c7/CADBenchEval/CADBench/Eval/code_metrics.py).

## Robustness and guarantees

DOCUMENTED: this benchmark measures plausibility/reconstruction, not exact CAD equivalence, recovered constraints, parametric intent, manufacture-readiness, or worst-case surface deviation. Paper explicitly excludes those interpretations. CD only on successes can improve when difficult examples fail; always read it alongside VSR and all-case overlap. [Paper §5, App. D](https://arxiv.org/pdf/2605.10873v2), [aggregation](https://github.com/anniedoris/CADBench/blob/99e41a2eeb351f04611e83980f9f23cb0ca216c7/CADBenchEval/CADBench/Eval/_main.py#L238-L316).

DOCUMENTED: execution helper called get_mesh_safe actually executes full Python builtins in-process; multiprocessing/timeouts are not an OS security sandbox. INFERRED: use a sandbox for untrusted model output, or wonky's restricted interpreter, never copy the name as a safety guarantee. [Execution implementation](https://github.com/anniedoris/CADBench/blob/99e41a2eeb351f04611e83980f9f23cb0ca216c7/CADBenchEval/CADBench/Eval/execution/_utils.py#L63-L84).

DOCUMENTED source defect: _sampling_iou switches to CPU when CUDA is absent, but count_ray_intersections asserts all tensors are CUDA; outer exception handler returns 0.0. Therefore, on CPU-only hardware when Trimesh Booleans fail, metric failure is silently scored as disjoint geometry. INFERRED: this is particularly relevant on Marc's Metal Mac and must be fixed or rejected before using this fallback. The parity routine uses inclusive barycentrics with no shared-edge tie-breaking, det epsilon 1e-12, t>1e-8, and area>1e-20; it is not an exact containment predicate. [Fallback](https://github.com/anniedoris/CADBench/blob/99e41a2eeb351f04611e83980f9f23cb0ca216c7/CADBenchEval/CADBench/Eval/geometry/_utils.py#L114-L142), [ray casting](https://github.com/anniedoris/CADBench/blob/99e41a2eeb351f04611e83980f9f23cb0ca216c7/CADBenchEval/CADBench/Processing/utils/iou_sampling.py#L34-L126).

## Parallelism and performance

DOCUMENTED: evaluator parallelizes independent shapes through process pools; geometry uses NumPy/Open3D float64 coordinates and CUDA float32 sampling, with int64 totals. No pure-functional kernel or certified exact arithmetic is implemented. Ray casting chunks triangles and points but is still all-pairs work. [Evaluator](https://github.com/anniedoris/CADBench/blob/99e41a2eeb351f04611e83980f9f23cb0ca216c7/CADBenchEval/CADBench/Eval/_main.py), [geometry](https://github.com/anniedoris/CADBench/blob/99e41a2eeb351f04611e83980f9f23cb0ca216c7/CADBenchEval/CADBench/Eval/geometry/_utils.py).

DOCUMENTED published timings, not locally reproduced: App. C.1.2 uses RTX PRO 6000 + Threadripper PRO 7975WX for local models. Mean per sample CADFit 453.1s (median 291.8s, max 6817.6s), CAD-Recode 2.095s, Cadrille 3.262s. API times use only 100 random single-view examples, whereas local timings use the full suite, so do not compare as equal-work kernel benchmarks. Table 2 aggregate CADFit IoU 0.859/VSR 0.981 versus CAD-Recode 0.673/0.912. [Paper Tables 2,8](https://arxiv.org/pdf/2605.10873v2).

## Known failures, limitations, war stories

- DOCUMENTED: geometry degrades with increasing face count in controlled sketch-extrude families, but relation is less monotonic with richer operation vocabularies. Repeated holes can dominate face count; add feature-class coverage, not just size bins. [Paper §4, §5 and App. C.2](https://arxiv.org/pdf/2605.10873v2).
- DOCUMENTED: CADEvolve aggregate IoU falls 0.707→0.130 on synthetic noisy meshes; CADFit falls 0.051, CAD-Recode 0.162. Specialized image models are sensitive to render layout changes. This does not prove all future specialized models are brittle. [Paper §4 and App. C.3](https://arxiv.org/pdf/2605.10873v2).
- DOCUMENTED: approximately 1M syntactically valid outputs give Spearman rho(IoU,SIoU)=0.57, rho(IoU,CD)=-0.73, rho(SIoU,CD)=-0.87. Figure 11 shows missing fine detail at high volume IoU and wrong thickness at high surface coverage. [Paper §4, App. C.4](https://arxiv.org/pdf/2605.10873v2).
- DOCUMENTED issue #1 requests STEP-only/private-code submissions and alternate languages. It is open with no comments at snapshot, not a demonstrated geometry bug. No public issue-based kernel failure corpus found; the stronger cautions above come from code inspection. [Issue #1](https://github.com/anniedoris/CADBench/issues/1).

## Relevance for wonky

INFERRED design proposal based on the metric failures and protocols above: adapt a compact **multi-axis evaluation contract**, not this native dependency stack. For each FeatureScript task log parse status, supported/unsupported feature, execution status, timeout, raw-solid validity, repaired-validity separately, physical-unit dimension errors, volume overlap, sampled surface coverage at explicit millimeter tau, mean and max/quantile distance, static source tokens, actual model billing tokens, dynamic operation count and compactness. Use separate raw-generation and fixed-budget repair-agent tracks. Store code, seed, tolerance, metric definition/version, reference geometry hash and normalization/alignment transform. [Motivation: paper §3.2/§5](https://arxiv.org/pdf/2605.10873v2), [implementation distinctions](https://github.com/anniedoris/CADBench/blob/99e41a2eeb351f04611e83980f9f23cb0ca216c7/CADBenchEval/CADBench/Eval/_main.py).

INFERRED Bend mapping: immutable point/triangle arrays, balanced per-sample map/reductions for distance sums and threshold counts; U32 suffices for these sample counts, multi-limb only for larger totals or certified predicates. Fixed-size tiled distance/parity work suits uniform GPU call trees, while kd-tree/Boolean fallback paths are irregular. Normalize coordinates for approximate F32 metrics; use F32x2 for moments/cancellation-sensitive reductions and log residuals. F32x2 is not a replacement for arbitrary exact containment or float64 exponent range. For watertight/provenance tests use wonky's own exact predicates and certified mesh, not PyMeshLab alpha wrapping or another kernel backend. Report approximate statistical metrics distinctly from certified deviation. [Source numeric assumptions](https://github.com/anniedoris/CADBench/blob/99e41a2eeb351f04611e83980f9f23cb0ca216c7/CADBenchEval/CADBench/Eval/geometry/_utils.py).

INFERRED FDM caveat: a normalized 1% score can forgive an unprintable wall or bad press-fit. Preserve a dimensioned, unaligned metric lane; pose/scale-invariant retrieval scores are useful for reconstruction but should not reward wrong units or erase placement errors. Add hole diameter, min wall, part count and interference assertions. Primary evidence is the paper's thickness counterexample, not an FDM guarantee. [Figure 11 and limitations](https://arxiv.org/pdf/2605.10873v2).

## Verdict: adapt

Adopt the diagnostic philosophy and stratified task organization; independently implement a pinned, tolerance-explicit metric contract in Bend. MIT source can be ported with notices, but paper/code disagreements, alpha wrapping and silent metric failures preclude treating the current harness as wonky's correctness oracle. No production geometry changes were made; exact reproduction of published scores remains unverified.
