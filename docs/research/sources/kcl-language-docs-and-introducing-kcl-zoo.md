## What it is

DOCUMENTED: Kinetic CAD Language is a text-first parametric language designed for human/code/GUI authoring. The May 2025 essay explicitly anticipates LLMs generating, explaining and improving KCL, motivates functional definitions instead of mutating geometry in loops, and favors higher-level patterns. A pipeline `x |> f(%) |> g(%)` desugars to nested function applications; an omitted unlabeled first argument can receive the pipeline value. INFERRED: this improves authoring, but a functional-looking language does not mean its interpreter or remote CAD engine is immutable or automatically fork-join parallel. [Essay](https://zoo.dev/research/introducing-kcl), [pipelines](https://zoo.dev/docs/kcl-lang/pipelines).

## How it works

### Constraint-first sketches

DOCUMENTED: `sketch(on=XY) { ... }` introduces lines/arcs/circles/points plus constraints. `var 40mm` is a **solver initial guess**, not a fixed design parameter and not general assignment syntax; identifiers/expressions cannot follow `var`. Define geometry seeds with literals, express design intent separately, e.g. `horizontalDistance([edge.start,edge.end]) == width`. Anchor once with coincidence to ORIGIN, then add horizontal/vertical, coincidence, equal length, tangency, symmetry and dimensions. Expose solved elements through `profile.line1`. Regions can be traced with adjacent segment pairs, `direction=CW` and `intersectionIndex` to disambiguate; do not guess an interior coordinate when a boundary reference is available. [Sketch docs](https://zoo.dev/docs/kcl-lang/sketches), [pinned source](https://github.com/KittyCAD/modeling-app/blob/d2f7712388efe52ec89594a4142f52493d8d6cf2/docs/kcl-lang/sketches.md).

DOCUMENTED implementation: `finalize_sketch_block()` gathers required constraints at highest priority and optional constraints at lower priority, normalizes initial-guess units, calls `ezpz::solve` or `solve_analysis`, rejects nonfinite values, substitutes results into geometry and records variable solutions for source rewriting. Current config is 50 iterations and convergence tolerance `1e-8`; solver values are f64. Freedom analysis tracks Fixed/Free/Conflict through solved sketch entities. This reading inspected the KCL integration, not ezpz's full optimizer internals; no Newton/SVD completeness theorem inferred. [finalize_sketch_block](https://github.com/KittyCAD/modeling-app/blob/d2f7712388efe52ec89594a4142f52493d8d6cf2/rust/kcl-lib/src/execution/exec_ast.rs#L2902-L3099), [tolerance](https://github.com/KittyCAD/modeling-app/blob/d2f7712388efe52ec89594a4142f52493d8d6cf2/rust/kcl-lib/src/std/solver.rs#L44), [freedom/substitution](https://github.com/KittyCAD/modeling-app/blob/d2f7712388efe52ec89594a4142f52493d8d6cf2/rust/kcl-lib/src/execution/sketch_solve.rs).

### Face reference versus construction plane

DOCUMENTED: `faceOf(solid,face=END)` or a tagged segment-derived face selects a face with parent-solid identity. Sketching on it and extruding extends the existing solid by default. `planeOf(solid,face=END)` gets the same geometric plane without that body-attachment behavior, so extrusion creates a separate solid; alternatively `extrude(region,method=NEW,...)` forces a new body while retaining face attachment. This distinguishes a **topological support relation** from a coincident infinite plane. `region.tags.line1` connects named source segments to generated faces. [Sketch-on-face docs](https://zoo.dev/docs/kcl-lang/sketch-on-face), [faceOf reference](https://zoo.dev/docs/kcl-std/functions/std-sketch-faceOf), [planeOf reference](https://zoo.dev/docs/kcl-std/functions/std-sketch-planeOf).

DOCUMENTED implementation: `make_face()` resolves the tagged face ID in a specified solid, errors if a required segment tag is unavailable, obtains parent sketch information, creates a front-end scene object with artifact ID and source range/node path, and stores `FaceParentSolid`, units and metadata. It errors when the solid lacks a sketch and axes are unavailable; its axis derivation carries a TODO. INFERRED: these are concrete dependency/provenance handles, not proof that tags survive arbitrary topology changes. [faces.rs](https://github.com/KittyCAD/modeling-app/blob/d2f7712388efe52ec89594a4142f52493d8d6cf2/rust/kcl-lib/src/std/faces.rs#L61-L127).

### Numeric model and version semantics

DOCUMENTED: runtime `KclValue::Number` stores `f64`, `NumericType` and source metadata. Types cover length units, angles and unitless counts; compatible call arguments auto-convert. Crucially KCL has **no area/volume/higher-dimension unit algebra**. Ascription relabels rather than converts: `2mm: in` becomes `2in`. Multiplying `10in*25.4` yields `254in`, not mm. INFERRED: wonky should retain FeatureScript's dimensional values rather than imitate this ergonomic weakness in mass/area/volume diagnostics. [numeric docs](https://zoo.dev/docs/kcl-lang/numeric), [runtime representation](https://github.com/KittyCAD/modeling-app/blob/d2f7712388efe52ec89594a4142f52493d8d6cf2/rust/kcl-lib/src/execution/kcl_value.rs#L94-L112).

DOCUMENTED: KCL 3 preview changes execution semantics as well as surface syntax: return exits immediately (2.0 recorded a result but continued execution), branch variables become local, object-before-index evaluation order, fillet/chamfer execute in order and follow tangent chains by default, sweep stops relocating the profile unless requested, obsolete `legacyMethod` is rejected, explicit angle units replace defaultAngleUnit. A project runs one language version, not mixed versions. INFERRED: pin both syntax and operation semantics to preserve CAD replay; a language upgrade can alter geometry without a parser error. [Migration](https://zoo.dev/docs/kcl-lang/migrating-to-kcl-3).

## Robustness and guarantees

DOCUMENTED limits: coplanar unions/subtractions/intersections are listed as unsupported; imported B-rep has `ImportedGeometry`, not `Solid`, and cannot be edited by solid operations; KCL 1 region tags could shuffle, fixed in 2.0. Treat these as a published capability boundary, not proof that every current engine path consistently detects and rejects every unsupported case. [Known issues](https://zoo.dev/docs/kcl-lang/known-issues).

DOCUMENTED source caveat: a nonconverged solver result produces a compilation issue but continues toward substituted geometry. Some Faer linear-algebra failures produce a diagnostic and fall back to **initial guesses**, with `converged:false`; other internal failures hard-error. INFERRED: such geometry may be useful for interactive editing, but a manufacturing/export path must refuse to treat it as satisfying constraints. Copy the explicit solver state, not successful geometry creation as a solve certificate. [solver failure branches](https://github.com/KittyCAD/modeling-app/blob/d2f7712388efe52ec89594a4142f52493d8d6cf2/rust/kcl-lib/src/execution/exec_ast.rs#L2987-L3078).

## Parallelism and performance

No reproducible kernel/solver timing benchmark in the inspected language docs or 2025 essay. Solver integration exposes a fixed 50-iteration ceiling, not measured runtime. Execution uses mutable Rust state, async remote modeling commands and f64 solver arrays; functional KCL syntax is not a direct Bend implementation. No tests or builds performed. [execution implementation](https://github.com/KittyCAD/modeling-app/blob/d2f7712388efe52ec89594a4142f52493d8d6cf2/rust/kcl-lib/src/execution/exec_ast.rs#L2902-L3099), [engine architecture](https://github.com/KittyCAD/modeling-app/blob/d2f7712388efe52ec89594a4142f52493d8d6cf2/README.md).

## Known failures, limitations, war stories

- DOCUMENTED open report [#7485](https://github.com/KittyCAD/modeling-app/issues/7485): ordinary 3D-printed tape-measure wall mount's floor/walls union returned “engine cannot handle this 3D union yet,” with full KCL repro. Historical v1.0.5 report, not independently rerun on current engine.
- DOCUMENTED open report [#12327](https://github.com/KittyCAD/modeling-app/issues/12327): impossible triangle-angle constraint combination yielded no useful error/render in v1.3.4. Contradictory constraints need actionable residual/conflict feedback, not just a blank viewport.
- DOCUMENTED design issue [#14138](https://github.com/KittyCAD/modeling-app/issues/14138): ezpz coincidence epsilon and engine region-building point deduplication epsilon disagree, so a solved triangle may become an open path in the engine. Proposal passes a physical tolerance through `SetDefaultSystemProperties` and converts it into solver units; 3D tolerance unification remains separate/unsolved in the issue. This is directly relevant to wonky's sketch→arrangement→B-rep boundary. Proposal is not a shipped guarantee.

## Relevance for wonky

INFERRED from the linked contracts: do not switch the FeatureScript frontend to KCL. Adapt the **authoring distinction between initial guesses and constraints**, tagged dependency references, parent-face-vs-plane semantics, source-linked diagnostics, immutable versioned program inputs and explicit capability matrix. Wonky's existing line/arc solver is the natural integration point: emit DOF/conflict/residual evidence and branch choice, expose supported constraints, and carry one physical tolerance policy through region construction and mesh certification. [Sketches](https://zoo.dev/docs/kcl-lang/sketches), [tolerance issue](https://github.com/KittyCAD/modeling-app/issues/14138).

INFERRED Bend fit: represent constraint arrays and metadata immutably; map residual/Jacobian row evaluation over a fixed solver system with balanced fork-join; use CPU for variable-size rank/conflict analysis, or pad/bucket GPU work with bounded iterations. F32x2 can handle many practical residual calculations but is not f64-equivalent in mantissa/exponent; normalize units/scales and propagate uncertainty. Exact U32-limb predicates should decide sketch arrangement incidences, not “residual below 1e-8 therefore coincident.” Preserve tags via wonky provenance rather than opaque engine UUIDs. No FFI embedding of Rust, ezpz or remote engine; independent port needed. [f64 model](https://github.com/KittyCAD/modeling-app/blob/d2f7712388efe52ec89594a4142f52493d8d6cf2/rust/kcl-lib/src/execution/kcl_value.rs), [solver integration](https://github.com/KittyCAD/modeling-app/blob/d2f7712388efe52ec89594a4142f52493d8d6cf2/rust/kcl-lib/src/execution/exec_ast.rs#L2902-L3099).

## Verdict: adapt

Strong language/diagnostics peer, especially constraint intent and semantic face attachment. Do not import its weak higher-dimensional units or infer robust geometry from functional syntax. Open: quantify F32x2 solver tolerance/domain, design an immutable DOF/conflict API and test cross-stage coincidence consistency. KCL 3 is preview, not a stable production reference.
