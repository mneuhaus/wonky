## 1. What changed

Production files: `src/parser.mjs`, `src/interpreter.mjs`, `src/values.mjs`,
`src/scalars.mjs`, `src/queries.mjs`, `src/library.mjs`, `src/errors.mjs`
(Regression review), `src/analytic.mjs` and `src/python.mjs` (Regression review follow-ups)
and `src/index.mjs`. New tests: `test/parser-corpus.test.mjs` (7),
`test/interpreter-corpus.test.mjs` (25) and `test/library-corpus.test.mjs`
(13). All geometry still comes from Bend.

### P1 parser (parser package)

- String tokens are never matched as keywords or symbols, so the strings
  `"function"` and `"-"` stay string literals.
- String escapes follow FsDoc tokens.html:
  - `\b \t \n \f \r \\ \" \'`;
  - `\u` with exactly four hex digits, and surrogate pairs join into one
    character.

  Other escapes fail with an explicit error.
- Try statements follow FsDoc exceptions.html:
  - `try { }` without a catch;
  - `try silent { }`;
  - `catch { }` without a binding;
  - `try silent { } catch (e) { }`.

  Try nodes carry `silent`. `name` is null when there is no binding. Every
  form catches only FeatureScript exceptions (`FeatureScriptException`, fix
  round). Capability errors, wonky's own limits and kernel audits escape
  every form.
- `for (var k, v in x)`. For nodes carry `key` (null in the one-variable
  form). `name` is always the value variable.

Across all 575 `.fs` files in `~/Workspace/cad`, 27 more files parse, none
parses differently, and none newly fails. The r10b AST is identical.

### P2 interpreter semantics (semantics package)

- **Feature parameter defaults.** The dialog is read from the precondition,
  including parameters declared inside `if` blocks. The order, weakest first
  (corrected in the Regression review, section 8):
  1. the `defineFeature` defaults map, which only fills keys the dialog
     lacks (std feature.fs: it "does NOT control the user-visible default
     value");
  2. implied defaults: `false` for a boolean, `""` for a string, the first
     member of an enum;
  3. the annotation `"Default"`;
  4. the bound-spec default for `isLength`/`isAngle`/`isInteger`/`isReal`: the
     millimeter or degree entry, else the first `[min, default, max]` entry
     (valueBounds.fs);
  5. `--param`.
- **Annotations.** Only `"Default"` is evaluated. `"Filter"`, `"UIHint"` and
  the rest stay metadata.
- **Unpicked Query parameters.** An unsupplied Query parameter becomes a
  `uiSelection` query. A feature that never resolves it builds. Resolving it
  raises an explicit capability error, also inside `try silent`, and the
  error names the fix: `--param 'x=qNothing()'` or a Part Studio input. This
  follows the triage's recommendation for Marc's open decision P2 (a).
  Onshape itself would pass the empty selection.
- **Type tags.** Maps can carry a type tag that JSON, key iteration and
  equality ignore. `color()` returns a Color and `line()` a Line. `is <Tag>`
  works for any tag. LengthBoundSpec, AngleBoundSpec, IntegerBoundSpec and
  RealBoundSpec follow std `canBeBoundSpec`.
- **Std value bounds.** `scalars.mjs` has the valueBounds.fs specs
  (`LENGTH_BOUNDS`, `ANGLE_360_BOUNDS`, `POSITIVE_COUNT_BOUNDS`, ...),
  `unitless`, `isAngle`, `isInteger`, `isReal` and `verifyBounds`. An
  out-of-range value throws `PARAMETER_OUT_OF_RANGE`, as std does. This also
  applies to `isLength`.
- **Units.** The corpus shows no unit gap. `units-source-error.fs` still fails.
- **Interpreter side of the new syntax.**
  - `for (var k, v in x)` over maps and arrays. Maps iterate by key: strings
    by Unicode code point, numbers numerically, and any other key mix is a
    capability error.
  - `catch` without a binding, and `try` without `catch`.

### P3, P4a, P7 (library package)

- **P3 pure std builtins,** each citing its std source:
  - `makeId`, `newId`;
  - `atan2`, `asin`, `acos`, `atan`;
  - `coordSystem`, `toWorld`, `fromWorld`;
  - `rotationAround`, and `mirrorAcross` as a value only (`opPattern` still
    refuses the reflection);
  - `min`, `max`, `toString`, `concatenateArrays`.

  `unitless` and `isInteger` come from `scalars.mjs` only, so each name has
  one definition.
- **P4a std queries:**
  - `qNothing`, `qIntersection`;
  - `qEverything(entityType)`, only under `qBodyType(..., BodyType.SOLID)`.
    The unfiltered forms refuse, because Onshape would include its four
    default bodies (Regression review);
  - `makeRobustQuery`, which follows the identity-keeping record. It refuses
    across a split and for a tool a Boolean consumed (Regression review);
  - `qContainsPoint` for bodies, through the Bend point-in-solid classifier.
    Inside and Boundary count as containing. Unresolved is a capability
    error. Faces, edges and sketch bodies refuse.
- **P7 N-ary `opBoolean`.** Two operands keep the old binary path. More
  operands are folded into binary Bend Booleans in source order:
  - UNION is component-aware, and the earliest tool keeps its identity.
    Tools that touch nothing stay as they were, on the binary path too (fix
    round). A pair is skipped only by bounds: its own, or those of every tool
    a merged body was built from (refix 1; the kernel test of the tool alone
    from Regression review 3 is withdrawn, [w1-casts-nary.md](w1-casts-nary.md));
  - SUBTRACTION removes every tool from every piece of every target. A call
    that removes nothing from any target refuses, as an empty INTERSECTION
    does (Regression review 3). Whether a step removed material is read from the
    kernel's face provenance, not from the volume (refix 1);
  - INTERSECTION is a left fold.

  A pair skips its kernel call only when the bounds are more than 1 µm apart.
  Record changes commit only after every step succeeded. Each step's evidence
  (`<id>/~step<k>`) and one decomposition record are appended to
  `operationEvidence`. Empty operands refuse explicitly.

### Integration (this step)

- **`src/index.mjs` loads the Bend modeling services** (the face and solid
  classifiers that `qContainsPoint` needs), with two gates:
  - not on the native backend: `WONKY_BACKEND=native` must never load the
    Bend JS target (docs/native-bridge.md 5.2);
  - only when the source names `qContainsPoint` or a frozen module manifest
    is in use.

  Without the services, `qContainsPoint` raises a capability error.

  The first integration loaded the services unconditionally. `npm test` then
  failed 7 `native-bridge-slice` tests: the native runs loaded the JS kernel.
  It also failed the lang-wk-real identity comparison, because the engine's
  `services` appeared in `identity.operation.parameters`. The gate fixed all
  8.

  Cost on the JS path, when loaded: 90 to 170 ms per process, next to 1.1 to
  1.3 s for `loadKernel()`.
- **Classifier.** `scripts/corpus/lib.mjs` has a new rule,
  `ui-selection-missing`, for the unpicked-selection error. `clusters.mjs`
  and the per-cluster scripts (`boolean-files.mjs`, `fragments.mjs`,
  `module-import-report.mjs`, the cluster subdirectories) file it under
  `fs-needs-partstudio-input`.
- **`scripts/corpus/boolean-hook-loader.mjs`** leaves the library untouched
  when production is already N-ary (`this.naryBoolean(`). The arity patch and
  the `nary` stub apply only to pre-W1 sources.
- **Library cleanup.**
  - `isLength` uses `verifyBounds`.
  - The legacy string `LENGTH_BOUNDS` is gone, so the std spec is visible
    and `LENGTH_BOUNDS is LengthBoundSpec` holds.
  - `POSITIVE_LENGTH_BOUNDS` stays as a wonky-only alias.
  - `test/language.test.mjs` accepts `PARAMETER_OUT_OF_RANGE`.
- **Id components with `/`.** std `REGEX_ID_COMPONENT` allows `/` in an Id
  component. wonky joins Id components with `/`, so it raises a capability
  error instead of a FeatureScript error.
- **Map key order** compares strings by code point (FsDoc relational.html),
  not by UTF-16 code unit.
- **Docs.** The repro READMEs have an "After W1" record.
  `fs-missing-builtin/verify-repros.mjs` states the post-W1 results. The
  `annotation-filter-and` note now describes the unpicked-query behavior.
